# WS6 part 1: recommendation logic (age policy, wired inputs, honest reasons)

Status: uncommitted working-tree change on sprint/product-hardening-2026-10. Verification: see the bottom section.

## What changed and why

1. **Age policy** (`mobile/lib/features/safety/data/age_policy.dart`, new). Age was never read. `SafetyContext` now carries `ageBand` (minor < 18, senior >= 65, unknown = adult) and `gentleSelection`. `evaluateExercise` withholds max-effort work (Powerlifting group, advanced difficulty) from minors and seniors and high-impact work (by title) from seniors, so plan, home feed and programme builder all apply it through `eligibleExercises`. The plan caps intensity (minor 0.8, senior 0.85) separately from the health screening ceiling (a healthy minor is never told they were "not cleared"). Programmes: fewer days (minor 4, senior 3), one set fewer per slot, and a mobility slot for seniors. Visible warning: `BlockReason.ageMinorAdvisory` / `ageSeniorAdvisory` in `SafetyContext.advisories` (same channel the Train tab and plan rationale already render), en+ru. Non-medical wording; no clinical thresholds.
2. **Questionnaire inputs** (`personalisation/data/recommendation_hints.dart`, new). Wired: birthYear, goals.primary/flexibility/generalFitness (mobility and conditioning share in plan, suggestions and programme spec), activityLevel / sleep / stress / basics (starting-volume cap, stated in a reason only when it really lowered the factor), level.basics (gentle selection), level.frequencyPerWeek (beginner start days), schedule.preferredWeekdays (already live in enrolment through `programmeDayOffsets`; the ratchet now uses the same composition), plus the stated session minutes now reach the planner provider. Intentionally unused, with reasons in the doc comment of that file: gender, height, weights, specificSport, currentExercises, smoking, alcohol, diet, occupation, motivation text/barriers/environments, free-text health fields, legacy bloodPressure chip, gymId, homeEquipment text.
3. **True reasons.** Suggestions: stretch/yoga/balance items get `SuggestionReason.buildsMobility`, never strength/muscle. Plan: `InjuryFilterReason` counts only exercises removed by injuries.
4. **Unscreenable injuries** (`injuryIsScreenable` in `exercise_filter.dart`): a typed injury matching none of the nine regions yields `BlockReason.unscreenableInjury` advisory ("could not tailor around this; consult a professional").
5. **Goal consistency.** Comeback / flexibility goals and "cannot do the basics" set `gentleSelection` (no max-effort / advanced items); mobility goal reserves a stretch item; cardio goals reserve a conditioning item; suggestions treat the vendor conditioning group as cardio.
6. **Session length.** `plan_builder.dart` no longer allows `budget + 5`; the plan never exceeds `targetMinutes`.
7. **bench_press equipment id** (home users without a bench): OPEN. Left for the catalogue agent's fix; no catalogue hack here.
