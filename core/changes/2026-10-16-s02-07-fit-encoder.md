# S02-07 change record: Dart FIT encoder

Date: 2026-10-16. Story: S02-07 (design 7; test id U19).

## What changed

- New `mobile/lib/features/activity/data/fit_encoder.dart`: pure `FitEncoder.encode(ActivitySession)` returning `Uint8List`, plus public `fitCrc16` (FIT SDK nibble-table CRC) so the test-only decoder can be proven against it.
- File layout: 14-byte header (protocol 2.0, profile 2132, data size, `.FIT`, header CRC) -> messages -> 2-byte CRC over header and messages. Messages in order: `file_id`, `record` (one per timeline instant), `lap`, `session`. Each message type has one fixed definition; unknown values use the base-type invalid value.
- Record timeline: the GPS offsets when a GPS stream exists, otherwise the sorted union of the other streams' offsets. Other streams attach to a record by the nearest sample within 5 s (`nearestStreamValue`). Record fields: timestamp, lat/lon (semicircles), altitude, heart rate, cadence, cumulative distance (haversine), speed, power, temperature. Heart rate is included when present locally (design 7).
- Laps: the session's laps, or one lap spanning the session when there are none. Session message: times, distance (summary or GPS-derived), sport and sub-sport (`fitSportOf`), lap count, avg/max heart rate, avg speed, ascent/descent from the summary.
- An indoor or stream-less session still encodes (no `record` messages), as design 7/DQ-3 requires FIT to work for no-GPS sessions.

## Deviations

- No `activity` message (not required for the minimal set named in the design); `event`/`event_type` fields are not written.
