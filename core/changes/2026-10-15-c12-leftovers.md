Follow-up to C12 (5d2c356). Plan: C12, SD-6, SD-11, SD-15, D-60, D-63; design sections 6.3, 7.6.

## What changed
- `functions/src/release_guard.ts`: new optional `ReleaseGuardDeps.env`; new `bodyScanBucketCanary` evidence key; new flag-gated check `checkBodyScanBucket`. It runs only when `BODY_SCAN_BUCKET` is configured (process env first, then `functions/.env.<project>`, same name validity rule as `body_scan/flags.ts`); with no bucket no check is added, so the existing 10-check shape is unchanged. With a bucket it requires: bucket describes OK, public access prevention enforced, uniform access on, no `allUsers`/`allAuthenticatedUsers` binding, `fn-bodyscan` and `fn-account-delete` hold `roles/storage.objectAdmin`, and `core/state/g4_release_evidence.json` records `bodyScanBucketCanary.status = "closed"`. gcloud errors are UNAVAILABLE, everything else FAILED (existing style).
- `functions/scripts/run_release_guard.mjs`: passes `env: process.env` (one line; needed so the gate sees the real env).
- `runbooks/body_scan_bucket.md` (repo-root `runbooks/`, where C02 created it): added `secretAccessor` on `ai-gateway-kill-switch` for `fn-bodyscan`, purge identity note, canary evidence recording step, guard behaviour, an explicit verify-before-deploying-`storage.rules` procedure, the SD-15 go-live blockers list, rollback renumbered to section 7.
