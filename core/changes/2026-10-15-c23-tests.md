# C23 tests: food diary state and UI

## What changed
Functional Dart tests under `mobile/test/features/food_diary/`, one file per commit. Per-file results are appended below as each file lands.

## Why
Coverage map rows FOOD-24, FOOD-25, FOOD-20 (chips), A11Y-06, I18N-01 for the C23 diary state and UI.

## Files and results
- `state/food_api_test.dart`: error slug mapping (feature-disabled is the calm not-available state, closed failure set, no free text kept), response parsers, `AnalysedItem` refs, `FakeFoodApi`. 33 passed. `CallableFoodApi` itself (the HttpsCallable wiring) is NOT_RUN: `HttpsCallable` cannot be faked without a mocking package.
- `food_diary_fixtures.dart`: shared entry builders (helper, not a test).
- `state/diary_providers_test.dart`: visibility per verdict (referProfessional, needsAnswer, needsProfile, unknown fail closed), day entries, day targets/totals against the plan, write actions (deletion fence, validation, degraded entry, offline, 500-food cap), entry ids. 34 passed. Observation: `dayKeyOf` needs `initializeDateFormatting('en')` (done at app start); the test initialises it.
- `state/food_search_controller_test.dart`: 3-char minimum, explicit submit only, 600 ms debounce at the 599/600 boundary, replaced pending submit, last-results cache (case/padding, failure not cached), notAvailable/error/rate-limited phases, stale response ignored, dispose. 26 passed.
- `widgets/check_these_chips_test.dart`: text state label plus icon, semantics label "title, state" as button, RU state words, 48 dp, one announcement (and none when all resolved), focus to next unresolved chip or heading after resolve. 13 passed. `food_diary_harness.dart` is the shared widget harness (helper).

## Verification
Each file was run alone with `flutter test <file> --no-pub`. The complete set is re-run after the last file.
