### RU plural / decimal rule (D-84, Y-F10)

1. ICU plurals are used only for values that are always whole numbers. ICU Russian
   puts every fraction in `other`, so a decimal can never be inflected correctly.
2. Every new RU plural defines `one`, `few`, `many` and `other`. Existing older
   entries that omit `many` (for example `machineCardSeenTimes`) are not touched.
3. Values that can be decimal (body-fat points such as 24.1, kilograms per week
   such as 0.4, weeks such as 29.9) never sit inside a plural: they are formatted
   with `NumberFormat` for the active locale and followed by a non-inflecting
   abbreviation ("кг", "п. п.", "нед.").
4. Each field decided:

| Key | Placeholder | Decision |
|---|---|---|
| `bodyCheckInLast` | days | int (whole days since the last check-in) |
| `bodyScanChecksCount`, `foodCheckCount` | count | int (number of items) |
| `bodyScanHistoryCount` | count | int (number of scans) |
| `bodyScanRetentionDays` | days | int (choice list) |
| `bodyScanStrengthCount` | count | int (sessions) |
| `bodyScanWeightBodyStale` | days | int |
| `nutritionReviewBasis` | points | int (number of weigh-ins, not body-fat points) |
| `nutritionStepsValue` | steps | int |
| `onbNutritionPaceMessage` | weeks | int (caller passes a whole number of weeks); `kg` is a pre-formatted String placeholder followed by the abbreviation "кг" |
| `scanManualTimerStarted` | seconds | int (3/5/10) |

No plural key has a decimal placeholder (checked by type).

orangeAccent 3.72, white70 4.45, redAccent 2.20 (all below 4.5 for text); over mid grey

## 4. Medical-safe wording pass

Scanned all 605 new EN and RU strings for diagnosis words and "should/must/need to"
directives about health. Changed:

* `onbNutritionPaceBelowRange` EN/RU: "below the healthy range" -> "below the range this plan supports" (no health claim). Test `step_nutrition_test.dart` expectation updated.
* `onbNutritionPaceUnderweight` EN/RU: "Keeping your weight steady is the safe choice" / "Безопаснее удерживать вес" -> "The plan keeps your weight steady instead." / "План удерживает вес на одном уровне." (no safety advice, no weight-class word in the RU/EN reply).
* `bodyScanCloudBody` EN/RU: now states that photo details such as location and camera data are removed before upload (matches `public/privacy.html`, which already says metadata is removed, and the EXIF fix in `25546977`).

Reviewed and kept: `bodyScanProvisionalBannerBody` ("Treat it as a rough guide" is about the estimate, not health), `nutritionSourcesLimitNotMedical` and `foodDiaryHiddenBody` (point to a professional, no diagnosis), the "need more weigh-ins" strings (data requirements, not health directives). No string names a disease, disorder or condition. `public/privacy.html` already states that the face is blurred and "the picture's metadata is removed" before any photo leaves the phone; no wording change was needed there.
