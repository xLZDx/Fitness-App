# C19 plan UI tests

What: functional Dart tests for the C19 nutrition plan UI under
`mobile/test/features/nutrition_plan/`, one file per commit, sharing the C18
harness (`plan_state_fixtures.dart`, `plan_state_harness.dart`) and a small
host helper `plan_widget_host.dart`.

Why: coverage map rows PLAN-17, PLAN-18, PLAN-25, PLAN-28, SAFE-16, A11Y-05,
A11Y-10 and the a11y F6 slider contract.

## Files

- `kcal_range_slider_test.dart` (T84): pure `moveKcalThumb` (step 10, bounds,
  min gap 100, max gap 400, limit codes) and the widget (per-thumb semantics
  with spoken value and unit, increase/decrease actions, bound and gap
  announcements, steppers equal thumbs, drag beyond the ends, EN and RU).
  Product fix: `kcal_range_slider.dart` now persists the LAST drag value on
  drag end. Before, `onChangeEnd(widget.range)` could persist the pre-drag
  range when the last move and the release landed in one frame (the test
  failed with 2000-2200 instead of 1850-2200).

Verification: see the per-file results in the final report; single-file runs
only.

- `macro_ranges_card_test.dart` (7 passed): macro ranges as g ranges from the plan, protein aim, steps goal steppers +/-500, 48 dp targets, EN and RU incl. RU plural forms. Product fix: nutritionStepsValue and nutritionReviewBasis used the ICU '#' shorthand which Flutter gen-l10n renders literally ('# steps'); both ARBs now use the named placeholder.

- `ownership_selector_test.dart` (7 passed): radio rows with title and explanation, exactly the current value selected, tap reports the new ownership, current/disabled report nothing, header semantics, EN and RU.

- `auto_adjust_toggles_test.dart` (6 passed): toggles follow stored values, change only their own flag, Manual shows both off and disabled, per-ownership hint, EN and RU.

- `professional_notice_test.dart` (6 passed): notice has title and body only, no digits in EN/RU, states no reason, no action buttons, header semantics, RU text.

- `review_card_test.dart` (20 passed): why-card (date, decision per kind and ownership, ordered reasons, basis plural, trend), undo only for coached applied changes inside the window (expiry boundary, undone, other week, no record, no change, no handler), accept only for a current shared proposal, EN and RU plurals.

- `nutrition_entry_card_test.dart` (9 passed): range shown only for eligible with plan, no digit for referProfessional/under 18 even with stored plan, set-up for needsAnswer/needsProfile/no plan, tap opens /nutrition, semantics button, EN and RU.

- `nutrition_plan_page_test.dart` (25 passed): verdict gating (referProfessional notice only and digit-free even with a stored plan, needsAnswer/needsProfile link to /nutrition/profile), full eligible render, no ETA, first-review hint, weight line, links, planSurfaceShown once, create plan inside bounds, data-notice gate before create/edit/ownership/pause (declined = no write), slider/steps/ownership/auto toggle persisted via actions, coached->shared flip, offline message, pause toggle, EN and RU.

- `weight_log_page_test.dart` (20 passed): parseLoggedWeight limits (30..300, comma, garbage), empty state and 'first review after about 3 weigh-ins over 2 weeks' intro, newest-first list with source, add (typed, comma, bounds, invalid keeps sheet, cancel, signed out), data-notice gate before add and delete (declined = no write, acknowledged releases once), edit replaces without duplicating, delete confirm/cancel, RU.

- `plan_sources_page_test.dart` (6 passed): sections, named formulas and licences (Mifflin-St Jeor, USDA CC0, Open Food Facts ODbL), estimates and not-medical limits, header semantics, 200% text scale EN/RU without overflow, RU.

- `plan_explainer_page_test.dart` (6 passed): weekly rules, the three ownership modes, safety limits, cooldown wording, no date/result promises, 200% text scale EN/RU, RU.

- `nutrition_routes_test.dart` (5 passed): real router: no redirect for a finished user on any /nutrition* path, route table registers each path, sources/explainer/profile paths resolve to their pages (plan and weight pages are covered by registration plus their own page tests).
