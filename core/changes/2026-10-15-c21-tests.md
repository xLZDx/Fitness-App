# Change record: C21 generic foods tests

## What changed
- `mobile/test/features/food_diary/data/generic_foods_test.dart` (new, 68 tests): parses the REAL assets
  `generic_foods_v1.json` and `generic_foods_ru.json` via `dart:io`; row count (2,590 / 321), id format and
  uniqueness, per-100 g sanity (non-negative, kcal <= 900, Atwater 4/4/9 band with documented exemptions),
  tag integrity (meat/fish/pork/alcohol/vegan consistency), RU name fallback, restrictive tag parse, malformed
  input containment, token search ranking (exact 3 > prefix 2 > substring 1, ties, limit, e/yo), synonyms.
- Product defects found by those tests and fixed minimally (asset and builder kept in sync):
  - `Eggplant, raw` and `Eggplant, pickled` were tagged with the egg allergen because the builder regex
    `\begg|eggs\b` matched "eggplant". Builder now uses `\beggs?\b`; the two asset rows carry `allergens: []`.
  - `Beverages, Malt liquor beverage` was not tagged `alcohol`. Builder `ALCOHOL_WORDS` gains `liquor`; the row
    now has `alcohol: true`.
  - Asset edits were byte-level on the one-line JSON; the file still parses (2,590 rows).

- `mobile/test/features/food_diary/data/food_suggestions_test.dart` (new, 77 tests): `fitsFilter` (allergen
  certain/uncertain, all 14 allergens, vegan/vegetarian/pescatarian/gluten-free/dairy-free/halal/kosher, pork and
  alcohol tags, shellfish kosher-only, combinations, `excludedFoods` EN/RU/synonym/prefix/short-token rules) and
  `suggestFoods` (focus choice and ties, 30%/50% thresholds, ranking ties, kcal < 20, excluded categories, max 2 per
  category, cap 5, limit, determinism) on synthetic rows and on the real table.
- Product defect fixed in `mobile/lib/features/food_diary/data/food_suggestions.dart`: halal and kosher only
  hid rows with `animalProduct == null`; the documented contract hides ALL uncertain rows. Both cases now test
  `t.isUncertain` (restrictive side; only a handful of real rows change outcome).

## Why
Coverage map: restrictive diet/allergen tagging must be provable on the real table, not only on fixtures.

## Observations, not changed
- `Bacon, meatless` and `Bacon bits, meatless` keep `pork: true` (restrictive for halal/kosher; they are also
  `animalProduct: null`, so they are hidden from suggestions anyway).
- Many imitation/dressing rows carry both `milk` and `eggs` allergens by design (uncertain composition).
