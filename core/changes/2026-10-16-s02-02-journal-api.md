# S02-02 change record: journal repository API, tombstone, sync state, wipe and sign-out hooks

Date: 2026-10-16. Story: S02-02 "Local journal" (design 3.4, 3.5, 10; test ids I01, I06, I09, I10, I18, I21-I25, I45).

## What changed

- New `mobile/lib/features/activity/repository/activity_journal.dart`: the `ActivityJournal` interface (start, put, read, list, listTombstones, delete, updateSyncState, markSynced, assessSignOut, wipe, close), the `ActivitySignOutHooks` interface (export offer and wipe confirmation, implemented by the UI and export stories) and `ActivityWipeCoordinator` (empty journal signs out without a prompt; non-empty offers export and wipes only after confirmation; account deletion and auth failure at launch wipe without a prompt).
- New `file_activity_journal.dart`: `FileActivityJournal`. In-process mutex for every operation; monotonic `seq` counter that continues past the highest sequence seen at recovery; ids restricted to `[A-Za-z0-9_-]{1,64}`; an identical re-put is a no-op; a put after a tombstone is refused (delete wins); a newer-schema record is never rewritten; `delete` writes a tombstone generation without streams, laps or provenance; `markSynced` takes an `expectedGeneration` so an edit made during upload is not marked synced; the future completes (and `onAcknowledged` fires) only after the COMMIT rename, and failures of `CURRENT`, the index or the old-generation delete after the commit never fail the mutation; a pre-commit failure surfaces `JournalStorageFullException` or `JournalIoException` carrying the pending session; `read` re-verifies the record against COMMIT, decrypts streams, and on key loss or undecryptable streams persists `streamLost` in a new generation (no exception, no wipe, no download); old generations are deleted only after a verified `read`; a second live instance on the same directory is refused; `wipe` deletes the three directories and the key.

## Why

Design 10 acknowledgement rule, single writer, full-disk handling, monotonic counters and design 3.5 sign-out and key-loss behaviour.

## Affected contracts and paths

`mobile/lib/features/activity/repository/`. Deviations: `list()` returns entries without streams for scale (use `read` for streams); a transient secure-storage read failure marks the entry unavailable in memory only (it is not persisted as `streamLost`, to avoid losing a recoverable stream); GPX/FIT export and the sign-out UI are interfaces only.
