# S02-06b change record: orphan reconciler

Date: 2026-10-16. Story: S02-06b (design 5.2, 6, 6.3; test ids F27, F28, F72).

## What changed

- New `functions/src/activity_streams/reconcile.ts`, scheduled `reconcileActivityStreams` (every 5 minutes), three independent passes (a failure of one never stops the others):
  1. Pending: collection group `activity_streams` where `pendingSince <= now - 1 h` (a never-stored `pending` row and a `stored` row with `pendingUploadId`). If the promoted object's SHA-256 equals `intendedStoredSha256` the row is repaired through the existing `selectPromotedObject` (its transaction re-checks fence, Auth, tombstone, summary, consent and the current uploadId); any refusal, mismatch, missing or unparseable object deletes the upload's own objects and clears the marker via `clearPendingUpload`.
  2. Stored rows (cursor walk over `state == stored` ordered by `expiresAt`, the purge index): a row without summary is removed with its objects; a row whose object is missing becomes `deleted` with `lastErrorCode = object_missing`; healthy rows are not written.
  3. Objects under `streams/` and `quarantine/` (cursor walk): an object older than the upload TTL (10 min) that no row references (no row, not the row's `objectPath`, not the current pending upload) is deleted; unrecognised names are counted and left alone.
  - Cursors live in the new server-only document `activity_reconcile_state/main` (default-deny rules, Admin SDK only).
  - One structured log entry per run with counts and ages (pending age, quarantine age, orphans, missing objects); no uid, id or path.
- `commit_stream.ts`: `currentUploadId` and `expectedHashOf` exported (no behaviour change).
- `bucket.ts`: `StreamListingBucket`, `ListedStreamFile`, `activityStreamListingBucket()` (a bucket that can list a prefix).
- `firestore.indexes.json`: single-field collection-group override on `activity_streams.pendingSince`.
- `functions/src/index.ts`: export.

## Notes

- Pending rows are examined only after the 1 h bound, so a consent-withdrawn pending row is aborted at that bound, not at withdrawal time (commit and upload already refuse immediately).
- `activity_reconcile_state` needs a `data_lifecycle_policy.json` row in S02-08 (server-only, no client access).
