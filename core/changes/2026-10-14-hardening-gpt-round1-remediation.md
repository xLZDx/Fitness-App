# Change record: remediation of the final-gate review (round 1) on f0e00ae

## What changed
- MAJOR-01, difficulty ceiling: `safetyContextForTrainingContext` now copies `maxDifficulty`, so a beginner or never-trained user keeps the "nothing above your level" ceiling in every training context (plan, programme builders; home suggestions already filtered by tier). Two other rebuilt contexts (add-to-programme gate in `programme_providers.dart`, `_resolveExercise` in `equipment_providers.dart`) now also carry `ageBand` and `gentleSelection`; equipment and `maxDifficulty` stay out on purpose (explicit choice, not a recommendation).
- MAJOR-02, scan persistence: `_save()` in `scan_capture_screen.dart` is bound to the uid that started it. The uid and repositories are captured before the first await; the live uid is re-checked before each photo, after each write, before the sidecar and after it. New `accountBeingDeletedUidProvider` (set by the deletion flow right after the server confirms, before the wipe) closes the window in which the wipe runs while auth still shows the same uid. On abort the partial writes are removed through the original account's repositories only, the screen state is cleared and the screen pops silently. `PhotoStore.remove` no longer recreates the folder or an index when none exists.
- MAJOR-03, durable deletion cleanup (`functions/src/index.ts`): `deleteAccount` writes an intent record `accountDeletionRetries/{uid}` (pending, attempts 0, createdAt, nextAttemptAt +15 min, expireAt +30 days, bare error code only) BEFORE deleting the Auth user and aborts before the Auth deletion if that write fails. A clean final sweep deletes the record (`finalCleanup: "complete"`); a failed one keeps it (`"scheduled"`). The scheduled `reconcileAccountDeletions` (every 15 min, no user auth) claims a due record (attempts + 1, backoff 15 min doubling to 6 h) before sweeping, deletes it on success, skips and deletes records of users that still exist in Auth, terminates at 12 attempts (`failed_terminal`, ERROR `account_deletion_reconcile_exhausted`), has a 240 s per-run deadline and logs ERROR `account_deletion_reconcile_run_failed` when the due query fails. One shared `sweepAccountData`. Rules deny all client access; composite index and TTL field override added; the collection is classified EXEMPT in the lifecycle policy and documented in the data inventory (md and csv). Alert definitions (source-controlled, not deployed by this repo) cover the new events; creating the live policy and attaching a channel remains the operator step.
- MAJOR-04, coach recorder: the recording keeps the starting uid, is discarded on any auth identity change and is saved only under that uid.
- Decision A, birth-year precision: `PersonalInfo.lowestAgeAt` and `ageBandForPersonal`; the minor band applies while the calendar-year difference is 18 or less, the senior band from 65, the body scan uses the lowest possible age. Consumers (safety context, programme days, suggestion builder, scan access) use them. Plan R2-1, R2-4, R2-8 updated.
- Decision B, Android backup: `FlutterSharedPreferences.xml`, `FlutterSecureStorage.xml` and `FlutterSecureKeyStorage.xml` are excluded from backup (API 30 and below) and from cloud backup and device transfer (API 31 and above). Inventory updated.

## Why
The final GPT-PM gate on f0e00ae returned REJECT with four MAJOR findings and two blocking decisions. A read-only reliability review of the first remediation found two more valid defects in the reconciler design (record written only after a caught failure; a crashed run never counted as an attempt), and a Flutter review found the wipe-before-sign-out window, stale screen state after abort and two further stripped safety contexts. All were fixed in this commit.
