# S02-06b change record: activity object sweep in sweepAccountData

Date: 2026-10-16. Story: S02-06b (design 6, 6.1; test ids F24, F25, F26, F57, F78).

## What changed

- New `functions/src/activity_streams/sweep.ts`:
  - `sweepActivityStreamObjects(uid, deps?)`: deletes `streams/<uid>/` and `quarantine/<uid>/` of the private activity bucket. Bucket unset is a logged no-op (`activity_stream_storage_sweep_skipped_unconfigured`); an all-404 outcome is success; both prefixes are ALWAYS attempted, then ONE bare error (`code` only, no message) is thrown for any other failure. Needs no Firestore row or settings document. A uid the path builders refuse is a no-op (nothing could have been stored).
  - `runIndependentCleanups(steps)`: runs every cleanup in order, never skipping one because an earlier one failed. One failure is rethrown unchanged (existing Body Scan behaviour is preserved); several failures become ONE error with the first failure's code.
- `functions/src/index.ts`: `sweepAccountData` now runs `sweepBodyScanObjects` and `sweepActivityStreamObjects` through `runIndependentCleanups` after the Firestore deletes. Both existing `sweepAccountData` calls in `deleteAccount` (Step 2, Step 4) and the `reconcileAccountDeletions` retry therefore sweep both buckets, independently.
- `functions/src/activity_streams/bucket.ts`: `StreamBucket.deleteFiles` options gain an optional `force` (type only; same SDK option `sweepBodyScanObjects` uses).

## Why

Design 6.1 positive cleanup invariant: independent attempts, one aggregated bare code, retry completes. Body Scan failing must not skip the activity sweep and vice versa.

## Contracts and paths affected

`sweepAccountData` behaviour (index.ts); trailing `/` on the prefixes keeps uid `abc` apart from `abcd`.

No tests, builds or checks were run (operator rule v4); test agents write and run F24-F26, F57, F78.
