# Late sweep: resumable listing cursor (GPT-PM MAJOR-02B.3)

- What: the late sweep persists its listing position on the `late_sweep_<hash>` record, so a user with 10 000 or more live objects ahead of a late orphan is no longer starved by the 20 x 500 page cap.
- Why: `sweepUserPrefix` returned "not finished" at the page cap but its position was local, so every 5-minute run restarted at page one and never reached an orphan sorting after the live objects.
- Design: `sweepUserPrefix` returns `{done, cursor}`; `cursor` is the last object NAME handled (names do not expire, unlike page tokens). The next run lists with `startOffset = cursor` (inclusive, so that one object is simply seen again; progress is guaranteed). The cursor is written back with a compare-and-set transaction (`tx.update` only if `rev` and `dueAtMs` still equal what the run read); if a newer `completeFence` rewrote the record, the cursor is dropped and the newer record is untouched. `completeFence` already writes the record with a whole-document `set`, which removes any `cursor`, so a new operation always starts from the beginning (comment added). A stored cursor outside the user's `users/{uid}/scans/` prefix is ignored. The record is still deleted by compare-and-delete only after the listing reaches the end; rev/dueAtMs semantics, page cap, budget and schedule are unchanged.
- Fake: `fakes.ts` `getFiles` now honours `startOffset` (inclusive, like GCS).
- Tests (purge.test.ts): 3 500 live pending scans (10 500 objects, untouched) followed by a late orphan: run 1 keeps the record and stores a cursor, run 2 deletes the orphan and the record, all live objects remain; a cursor from an older rev is not applied when a newer record replaced it; a foreign-prefix cursor is ignored.
- MINOR: `core/DATA_INVENTORY_2026-08-11.csv` (body_scan_purge_state row) now matches the markdown inventory and runbook: about 17 minutes under normal operation, retried every 5 minutes until deleted, no hard bound.
- Not verified: real GCS `startOffset` behaviour and real Firestore transactions (fake only).
