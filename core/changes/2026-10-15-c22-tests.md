## Defect found (not fixed here)
`FoodItem.toJson` emits `sourceId: "llm_estimate"` for `FoodSource.llmEstimate`, but design section 5.6 (`core/plans/BODY_SCAN_NUTRITION_TECH_DESIGN_2026-10-15.md` line 285) lists the item `sourceId` allowlist as `"usda_fdc"|"open_food_facts"|"user"|"label_ocr"`. Design s17.3 (line 682) and FOOD-09 require items to carry `llm_estimate`, so the s5.6 line is stale. `firestore.rules` `foodItemAt` does not check `sourceId` at all, so nothing is rejected at write time. `food_source_test.dart` pins the emitted set minus the s5.6 allowlist to exactly `{llm_estimate}`; reconcile the design line (preferred) or the layer deliberately.

## Test defect fixed while writing
`label_scale_test.dart` first used `math.pow(2, 1000)` (an int that wraps to 0 on the VM) as a huge serving; replaced with `1e300`.
