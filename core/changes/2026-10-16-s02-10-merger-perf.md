# S02-10 change record: merger performance restructuring

Date: 2026-10-16. Story: S02-10 (design 10; test ids U21, U22, U23, U36).

## What changed

- `mobile/lib/features/activity/data/activity_merger.dart`:
  - `merge(candidates, policy, {onPairCompared})`: new optional named parameter, a `void Function()?` invoked once per pairwise comparison (one echo-lookup step or one cluster-head comparison). With null the behaviour and the result are identical (design 10 seam).
  - Echo detection was O(sessions^2); it now builds an index by source id / app package and scans a holder list only until the first holder that is not the session itself.
  - Clustering was O(sessions x clusters); heads are now kept in a time-bucket index (`_HeadWindow`). Two sessions can only be the same workout when their starts differ by at most `W = max(maxStartDiff, (1 - minIou) / minIou * longest session) + 1 s`; a query reads three buckets of width W and tests the candidates in cluster-creation order, so the chosen cluster is the same as with a full scan. A policy with `minIou <= 0` has no bound and falls back to one bucket.
  - Ranks are computed once per session (identity map) instead of on every sort comparison.
  - Rule 0 (same id collapses to the first session in sorted order) and a deterministic same-id tie-break (newer import, then serialised content) so order independence holds for replayed records. This is the merger half of the native-id rule; the id helper follows in the next commit.

## Why

Design 10: the only gate is an operation count (300 candidates at most 100 000 pairwise comparisons, 2 000 sessions without streams at most 4 000 000). The naive echo detection alone cost n^2 = 90 000 at n = 300.

## Affected contracts

- `merge` result is unchanged for inputs without duplicate ids. Inputs with a repeated `id` now yield one session (first in the sort order); previously they were clustered by time.
- S02-01 fields (`explicitValues`, `summaryOverrides`, `extras`, edit history) are still carried from the primary member unchanged (`_mergeCluster` and `_join` untouched).
- No other code in `lib` calls `merge`; `test/features/activity/data/activity_merger_test.dart` calls it positionally and keeps compiling.
