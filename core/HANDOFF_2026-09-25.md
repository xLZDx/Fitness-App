## T3: what was actually built (Rosetta plan `fitness_app-2026-09-18T18-43-41-930Z-9cb0ae`,
GPT-PM APPROVE, 0 BLOCKER/0 MAJOR, hash `9fdd07c3...`)

New `mobile/lib/features/form_check/data/pose_scoring_gate.dart`:
- `scoredJointsOf(target)` — target's joints minus `unscoredJoints`.
- `chooseScoringSide(frame, scoredSet)` — compares mean likelihood of the scored LEFT joints vs
  their RIGHT counterparts; maps right→left slots only when right is strictly better; a missing
  counterpart leaves the slot empty (never silently reuses the hidden left joint); a bilateral
  scored set is never remapped.
- `reliabilityVerdict(scoringFrame, scoredSet, config)` — reuses `gatePose` over exactly the scored
  set, returns the full `PoseGateVerdict` (not a bool).
- `combineGateVerdicts(classifierVerdict, scoringVerdict)` — classifier verdict wins if not ok,
  else the scoring verdict.

`RepSessionController._onFrame` (`form_check_providers.dart`) now computes, on ONE frame, both the
classifier verdict and the scoring verdict, and publishes ONE new provider,
`poseEffectiveGateVerdictProvider`, before any early return (including the pause path and the
unscorable-frame path). `poseMatchScore` runs only when the scoring verdict is `ok`; otherwise the
frame still reaches the rep counter (counting unaffected) but produces no score, so an all-unreliable
rep is unjudged (not falsely missed). The OLD `poseGateVerdictProvider` is untouched — still the raw
classifier gate, single writer `FormFeedbackController`.

Readers switched from the raw to the effective provider: `coachSessionProvider`
(`coach_phase_providers.dart`), `CoachReadinessBand` (`widgets/coach_readiness_band.dart`), the
`[rep]` debug log line. `avatarVerdictSeverity` gained a `currentFrameReliable` parameter — applied
ONLY to the silhouette-match fallback branch, never to a classifier rule that `canFault` (fixed
after flutter-reviewer's MINOR finding: a real fault from a canFault rule must keep its colour
regardless of target-scoring reliability). A completed rep's own record
(`lastRepMissedTarget`/`lastRepVerdict`) is NOT modified by an unreliable current frame — only the
live overlay goes neutral.

`[rep]` debug log now also prints the chosen scoring side, withheld-frame counts per verdict
reason, and per-joint likelihood/x,y of the scored (side-mapped) frame — see
`_debugScoredJoints`/`_peakSideThisRep`/`_unreliableVerdictsThisRep` in
`form_check_providers.dart`.
