# Возобновление серии O — состояние на 2026-08-12

Оператор дал автономный GO на диапазон: **O3-O10, P3, P4-lite · compileSdk 35→36 · разметка
upperBack · разделение applicationId debug/release**. Этот файл — точка входа для следующей сессии.

   будет сделать отдельное меню/контрол по подключению к разным девайсам, и т.д. — но это потом
   отдельным гейтом»*. O2 уже убрал шаг из потока. Строить его обратно — против прямого указания.
   Шов `HealthService` не тронут: убран ШАГ, не интерфейс.
2. **P3 не отдельный гейт.** `PLAN_R11_DECISIONS_2026-08-12.md:253` — O8 его поглощает (колесо года
   рождения живёт на экране «О себе»). Делать отдельно значит делать дважды.
3. **Нумерация «N/9» в плане устарела.** После решений оператора поток короче; счётчик выводится из
   `kOnboardingOrder.length`, а не пишется числом.

## Осталось, по порядку

### O5 — «График» (НОВЫЙ экран, новых данных больше всего)

Схема из `O0_ONBOARDING_SCHEMA_2026-08-12.md` §5:

```dart
class TrainingSchedule {
  final int? daysPerWeek;            // 2..6
  final int? sessionMinutes;         // 30/45/60/75/90
  final List<int> preferredWeekdays; // DateTime.monday..sunday
}
// UserProfile получает поле schedule
```

**НЕ переиспользовать `FitnessLevel.frequencyPerWeek`** — там записано, сколько человек тренируется
СЕЙЧАС; слить с «сколько планирую» значит уничтожить единственную базовую точку, от которой
генератор плана может считать нагрузку. `MotivationPrefs.preferredDuration` остаётся вычисляемым из
`sessionMinutes`.

Нужно: новый `OnboardingStep.schedule` в `kOnboardingOrder` (после `equipment`), экран, ветка в
`isOnboardingStepAnswered`, `_titleFor`, `_widgetFor`, l10n, чтение/запись Firestore, тесты.

### O6 — «Тело» (самый большой)

Вкладки «Ограничения» ↔ «Приоритеты», диаграмма тела с зонами, две сетки чипов, и раскрывающийся
блок «Дополнительные сведения» с нынешним содержимым шага «Здоровье» БЕЗ изменений (указание
оператора: экран здоровья «очень удобный», его не трогать — он и не трогается, только переезжает
под шторку; свободный ввод сохраняется).

`FocusZone {chest, back, shoulders, arms, core, glutes, legs, fullBody}` — намеренно НЕ
переиспользует `InjuryRegion`: одно отвечает «что тренировать», другое «что обходить», списки не
совпадают.

### O8 — «О себе» + P3

`PersonalInfo.birthYear`; `age` становится вычисляемым (`текущий год − birthYear`). Миграция в
единственной точке чтения (`firestore_profile_repository.dart`): `birthYear ??= текущий год − age`.
**Точность ±1 год — месяц рождения никогда не спрашивался; это подписывается в интерфейсе, а не
замалчивается.** Плюс колесо года по §9.1 `BodyMetricPicker`, рост, вес, целевой вес, пол, уровень
активности.

### O10 — генерация, превью плана, аккаунт

**Упирается не в вёрстку.** Спека запрещает фальшивый прогресс и фальшивый прогноз (`:382-383`) и
требует, чтобы превью использовало НАСТОЯЩИЙ генератор, а не фикстуру (`:388`). Прежде чем рисовать
экран — проверить, существует ли генератор плана. Если нет, это не гейт вёрстки, и оператору надо
сказать об этом прямо, а не рисовать заглушку, которую спека запрещает.

### P4-lite — молчаливая потеря травм

`step_health.dart:72` — `.where((s) => s.contains(':'))` отбрасывает всё, что не подошло под формат
«часть тела: тип». Человек пишет «колено болит», поле выглядит заполненным, в профиль не уходит
ничего. Правка: неразобранная запись сохраняется как травма с пустым типом.

**Честно о пользе:** на сегодняшнюю безопасность НЕ влияет — `exercise_filter.dart` фильтрует 0 из
1 887 упражнений, потому что тегов противопоказаний в каталоге нет. Правка делает данные пригодными
к моменту, когда теги появятся. Продавать как «теперь безопаснее» нельзя.

### compileSdk 35→36

`flutter_secure_storage` и `flutter_tts` требуют 36; проект компилируется против 35. Предупреждение
на каждой сборке, со временем блокер выкладки в Play. На S23 с Android 16 перестаёт быть
теоретическим. Проверить, что SDK 36 установлен локально (`D:\android-sdk`), прежде чем менять.

### Разметка upperBack

Девятая зона добавлена в O1 и ЖИВЁТ БЕЗ ЕДИНОГО размеченного упражнения. Это безопасно только
потому, что `coversAllOf` (`safety_coverage_providers.dart:58-61`) отказывается заявлять скрининг
для зоны с нулевым покрытием. Разметка — отдельный проход по каталогу; ратчеты покрытия закреплены
в ЧЕТЫРЁХ местах (Dart enum, JSON-проекция, Dart-тест, Python-тест).

### applicationId debug/release

Сейчас общий: `com.fitnessapp.fitness_app.sptr` для обеих сборок. Последствия наблюдались вживую
