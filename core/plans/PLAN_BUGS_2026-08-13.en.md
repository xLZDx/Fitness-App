## Device loop — a crucial source correction

Original emulator: Android 14 x86_64 at **320 × 640 / 160 dpi**.

Two application IDs were present: release `com.fitnessapp.fitness_app.sptr` (`mobile/android/app/build.gradle:105`), plus obsolete `com.fitnessapp.fitness_app` from a prior build. The first screenshots inadvertently captured the **older package**, yielding false conclusions about new UI. **Verify an APK's package/version using `aapt2 dump badging` on the actual build**, rather than trusting `dumpsys` for a similarly named installed package.

The same split-per-ABI build could show **arm64 versionCode 2367** and **x86_64 4367**. Those differed because of ABI offset, **not** because they were different source revisions.

Anonymous entry and onboarding worked in the emulator, enabling a meaningful install → open → onboarding → screenshot test loop. That began to close an earlier "no R11/O screen run on device" verification gap, but it was still only the described checkpoint's emulator evidence.

## Block B — defects from screenshots

### B7 — Voice and AI commentary would not stop — DONE August 13, `09ef865`

**Code-level defect:** `setVoiceEnabledProvider` was read once in `start()` (`set_timer_providers.dart:140`), with no path calling a voice-coach `stop()` when the user switched speech off. By contrast, Form Coach already called `coach.stop()` after mute (`form_check_providers.dart:573`). `_play()` (`:177-185`) suppressed only **new** sounds, leaving an existing utterance audible.

The pre-existing test **"voice off means nothing is said"** (`set_timer_controller_test.dart:182-192`) disabled voice **before** start, missing the actual after-start toggle bug.

Fix: Subscribe to relevant voice/sound providers and halt playback **immediately** when disabled. Required test: start with voice on, turn it off **while speaking**, assert `stop()` was called.

### B1 — Body silhouette missing from Priorities tab — DONE August 13, `09ef865`; emulator checked at `e4366b5`

Limitations showed an anatomical figure, but Priorities showed only chips (`step_body.dart:120-137`). `BodyZoneMap` hardcoded `InjuryRegion` (`body_zone_map.dart:21,54,147`).

Proposed/implemented mapping generalized the widget to `Map<T, List<Rect>>` with a map for `FocusZone`. `fullBody` is **not one anatomical region**, so it correctly remains a chip-only option.

### B6 — Video speed controls layout — CODE DONE August 13, `09ef865`; **NOT yet device verified**

`exercise_reference.dart:561-580` positioned horizontal speed `ChoiceChip` controls at `right:8, bottom:8` across the video. Change to compact vertical controls on the **left**.

Do not convert "code done" into a claim of real-device visual acceptance.

### B8 — Weight prompt appeared too broadly — DONE August 13, `09ef865`; emulator checked at `e4366b5`

Old flow showed `SetCaptureSheet.show` unconditionally (`workout_player_page.dart:263`), immediately followed by another `DifficultyRatingSheet.show` (`:359`).

Operator decision: ask for weight **at exercise start** and **only for exercises where external weight makes sense**; do not ask for yoga, unweighted squats, push-ups or crunches.

Use `ExerciseItem` fields `equipmentId`, `equipmentLabel`, `isStretch` (`equipment_models.dart:52,58,72`), not a fabricated one-size-fits-all weight question.

### B2a+B2b — English-language fallback mismatch — DONE August 13, `eb66c7e`

- **B2a:** Six program title templates had hardcoded Russian literals (`programme_templates.dart:54,62,71,79,88,95`), unconnected to localization. This caused screenshots mixing English "Train" with a Russian program title.
- **B2b:** Exercise names were saved as localized string snapshots (`programme_schedule.dart:78` and `workout_player_page.dart:466`), causing mixed-language Recent Activity after language changes. Display should resolve by `exerciseId` against the current locale and retain saved title as a **fallback**.

The core exercise catalogue itself was not the primary cause: English records formed the base, `.ru.json` the overlay, and `_loadOverlay` returned no overlay for `en` (`asset_equipment_repository.dart:77`).

### B4 — Human-shaped Form Coach silhouette — CODE DONE August 13, `dd644d1` / `e1714e1`; **awaiting owner visual approval**

`_SilhouettePainter` (`form_check_page.dart:1391-1413`) had drawn thick independent lines and a head circle, not a body outline. The proposed corrective abstraction was `buildSilhouette` in `pose_silhouette.dart` to produce a continuous contour with appropriate varying width.

This was a **third attempt**. The source explicitly refused closure until the operator inspected the actual image; passing tests was not enough.

### B3 — Missing exercise-technique text — DONE August 13–14, but with new gaps

Measured **403 of 1,887** exercise records (about **21%**) missing steps in both `exercises_vendor.json` and `.ru.json`. It was a **data** gap, not only a widget gap.

After owner GO to author text, the source verified all **403** had clips and the **same two text fields** were absent. The existing invariant said `summary` must copy the first step, so a distinct `purpose` field was added for "why do this".

Merge tool: `tools/catalog/merge_exercise_text.py`; input batches `tools/catalog/batches/`; missing-id manifest `core/plans/B3_EXERCISES_WITHOUT_STEPS_2026-08-13.csv`.

**403/403** missing records received purpose and five technique steps in **both languages**. Historical content batches: forearms/powerlifting 10, biceps/triceps 26, chest 19, back 28, shoulders 46, legs 70, abs 33, stretching 41, yoga 42, calisthenics/functional 88. The original recorded a BLOCKER where Russian source text failed to reach the UI, captured in `core/DECISION_LOG.md` at **01:52** and **03:10**.

**Remaining:** **1,484 of 1,887** records with preexisting steps still lacked the newly created `purpose` field; 403 text records were authored by AI assistance without certified trainer review; purpose appeared only in Exercise detail, not program/player cards.

### B5 — Personalized programs: initially NOT AUTHORIZED, then subdivided and worked

The original detected >2-hour / 15+ file scope and split B5.

Pre-remediation defects:

- `buildProgrammeSchedule` read only `programme` and `catalogue` (`programme_schedule.dart:39-42`), **no questionnaire data** (equipment, location, goal, level, focus, schedule).
- The catalogue passed was `safeCatalogProvider`, only injury-filtered.
- **One exercise per day** (`:71-82`).
- Six fixed templates, no actual generator adapting to questionnaire answers.
- Program cards without exercise images.

**B5a — DONE August 13.** Restrict candidate catalogue by location/equipment before generation (`availableWith`); use `FocusZone` to populate fuller plans; cap days by user-requested schedule. The report intentionally **did not filter by difficulty**, because all 1,887 entries carried `beginner` and the filter would be meaningless. Personalizing methodology beyond template choice based solely on the goal was deferred to B5d, not invented. Agent-found BLOCKER documented in `DECISION_LOG.md` at **21:58**.

**B5b — DONE August 13 except full player route.** Split into four sub-gates due to **24 source + 20 test** readers of `ScheduledSession`, with explicit `GO B5b-1..4`. Added backwards-compatible day data, schedule filled to selected duration, injury screening and offline preloading across the day, +N day counters and real exercise counts in daily digest. **Initially unbuilt:** tapping the day still opened only the first exercise.

**B5b player — DONE August 14.** `/workout/:id` read `?day=`, passed `dayId` and keyed one session per planned **day**, not per entry exercise. Exercises merged by `exerciseId` (`upsertExerciseById`), avoiding position collision. The player showed **Exercise 2 of 4** with completed entries and navigation, per owner decision to avoid a new screen. Stable `daySessionId` avoided duplicate sessions after `autoDispose`/route replacement. Also fixed an overflowing Add exercise CTA at **400px**.

**B5c — DONE August 14.** Current-program card showed the upcoming day as responsive exercise thumbnails (`_ProgrammeDayThumbs`), with count for hidden items; restricted exercises retained their placeholder slot but no misleading image. The **template** card still lacked exercise imagery because `ProgrammeTemplate` contained no actual exercise list (`programme_templates.dart:33-53`); inventing contents before generation was prohibited. `DECISION_LOG` entry **09:57**.

**B5d — Program creation from questionnaire, templates retained as recommendations. Three sub-gates:**

1. **B5d-1 DONE August 14:** Schedule on actual preferred weekdays, not ignored `preferredWeekdays`. When preferred dates and days/week conflict, explicitly chosen weekdays prevail and `Programme.daysPerWeek` reflects the actual number. Fixed a DST issue: `add(Duration(days:))` could shift calendar weekdays. Logged 10:10.
2. **B5d-2 DONE August 14:** Programs tab added a **"Build from my answers"** card using actual goal, level, days and regions. Enrol through the **same** authoritative `enroll` pipeline as templates. Hide the card when onboarding answers are missing: "from your answers" without answers would be false. Program duration remained explicit constant `kProfileProgrammeWeeks = 8` (two templates used eight weeks; existing range was 4–10); a claim such as 12 weeks for gain vs four for return would invent training methodology. Logged 10:24.
3. **B5d-3 DONE August 14:** Rank six templates by actual questionnaire match, show one **"Best fit"** label and grounded explanations of goal, level, schedule and zones. Score was **four independent booleans**, not a made-up "87% match". Unanswered dimensions are not matches; don't rank an empty questionnaire or invent a unique winner in a tie. Logged 10:46.

**Measured remaining B5d limitation:** After B5d-2, `goals.primary` and `level.tier` reached `Programme.goal/level` on profile-generated plans, but downstream behavior still mostly used labels and a goal filter. No generator used those fields to truly alter exercise prescription. For templates they stayed copied from the template.
