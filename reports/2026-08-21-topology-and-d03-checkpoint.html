1 · Local worktree topology

Four local checkouts of this repository (Fitness_App, _wt-formcoach, _wt-gates-efgh, _wt-master-sync) shared one .git, and this session had been operating out of _wt-gates-efgh all along while the directory actually named after the project sat on an orphaned marketing branch. Inspected every worktree before touching anything, preserved all untracked/unique content found (9 marketing report files plus one formcoach report, byte-copied to scratch before any state changed; one path-colliding file renamed aside rather than deleted), then freed the master ref from _wt-master-sync (a branch detach, not a reset — its dirty working tree was not touched) and fast-forwarded Fitness_App onto it.

Root cause of why reports kept misidentifying the project as _wt-gates-efgh: report_conform.py read the project name from git rev-parse --show-toplevel, which is each worktree's own path. Fixed to derive it from the shared origin remote instead, with a regression test covering the exact multi-worktree case.

Two items left in a documented, intentionally-unforced state: the empty _wt-gates-efgh directory (OS still holds a handle on it) and _wt-master-sync's removal (needs git worktree remove --force, which would discard dirty content without separate authorization). Both are one manual command away once cleared.

2 · M7 — localized copy that bypassed the ARB pipeline

Two files (contribute_video_page.dart, equipment_report_sheet.dart) threw plain Dart errors or set plain-string success messages for validation/sign-in failures, then displayed them through a variable rather than a literal Text(...) argument — the one blind spot this project's own no_untranslated_strings_test.dart already documents it cannot see. A Russian-locale user would still have read English. Replaced with AppLocalizations lookups (six new ARB keys, both languages); flutter analyze clean, l10n suite 9/9, existing widget suite 4/4.

Worth stating plainly: the first commit attempt for this fix landed a commit whose message described the code change but whose diff contained only the DECISION_LOG entry — a mechanical gate had denied an earlier compound git add && git commit call in full, silently leaving the four real files unstaged. Caught immediately from git status and git show --stat, fixed with a second commit (not an amend, since the first was already pushed) carrying the actual diff.

3 · D-03 — the finding that forced this checkpoint

Earlier this pass, D-03 (the anonymous "Continue" button not always leaving the login screen) was recorded as FIXED (device-verified, 7/7), with extending to the full 20-trial bar flagged as follow-up. Did that follow-up on the same physical device and the same installed build (confirmed no auth/onboarding commit landed in between).

A methodology defect, caught before it could distort the result

The first extension attempt screenshotted 2.5s after the tap — too short. Most frames caught the sign-in spinner still in flight; a couple showed the button already idle with no way to tell whether that meant "hasn't started" or "already reverted." Discarded all 13 as inconclusive, except one (trial 11) that was watched live for four more seconds: the spinner cleared, the app was back on the plain login screen — a genuine first-tap failure — and a second tap on the same screen worked immediately. That is the exact D-05B/D-03 symptom already on record: first tap silently drops, identical second tap works.

Redid the remaining 12 trials with an 8-second settle window, long enough to cover the full cycle trial 11 showed takes about 6.5s. Confirmed a PNG-size split (~669KB onboarding vs. ~149KB login) tracks the visual result exactly on four spot-checks, then used it to classify the rest.
