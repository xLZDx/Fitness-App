03OBS‑1 — Observability as a priority gate

Why this is its own gate, not a line item

Every serious defect in this project's history was caught by a one-off manual audit — weeks or months later, never by a monitoring system: Auth disabled in production for weeks; Stripe API version drifted from its webhooks (would have reset every subscriber to free); the Functions Jest suite never actually ran; App Check enforcement status is still unknown; the Play API 36 deadline was found manually 15 days before it hit.

After review the gate grew from 7 to 13 items, split by blast radius:

[CI] · merge-blocking, cheap rollback
  • Verify functions/ tests actually ran
  • RU/EN semantic-drift check (structural parity already exists)
  • Dart/Flutter dependency (SCA) scanning (backend already has it)
  • Invariant: no path without SafetyContext (untagged-row policy stays out of scope — that's a D1/H3 decision, not engineering)
  • kCanonicalMachines ↔ equipment.json parity
  • Secret scanning — extended to git history
  • Composed-screen golden tests (extends the existing CI harness)
[RUNTIME] · production monitor, needs an alert owner
  • Auth + Firestore write/read canary
  • App Check / Firestore rules / Identity Toolkit enforcement dashboard
  • Billing integrity monitor (Stripe)
  • Client-direct Gemini call monitoring (no rate limit today)
  • Data deletion/export sweep-coverage check
  • Camera/ML/frame-timing telemetry

Priority: High, parallel to the clinical-authority path (D1/H3) — but NOT above the hard Play API 36 deadline (5 days out at document date). Prerequisites gating the RUNTIME half: who owns alerts, the canary's attestation model, the RU/EN baseline.

05Independent three-agent review

Round 1 was independent — no agent saw another's findings. All findings adjudicated and applied; full record in §11 of the source file.

Architect

Verdict: changes required

targetSdk deadline ranked below OBS‑1 — fixed. OBS‑1 didn't actually protect the safety paths it claimed to prioritize — added an invariant guard. Zero client telemetry for a camera+ML product. CI gates and runtime monitors bundled under one GO — split by blast radius. GlassCard count understated by ~3.5x.

Security-reviewer

Verdict: 2 of 3 safety claims stale

Pregnancy path and the B5d bypass are both already fixed (F014/F015) with regression tests — the first draft wrongly listed them open. The injury filter is confirmed still open, 360 is exact. Found a real open gap: client-direct Gemini calls with no rate limit, missing from OBS‑1's first draft.

Flutter-reviewer

Verdict: no blockers, one factual correction

Crashlytics is already wired — "no monitoring exists" was inaccurate. RU/EN parity is already partly automated and CI-enforced — the OBS‑1 item was rescoped to semantic drift. HUD golden tests exist but explicitly exclude composed screens — added as its own item.

06External review — GPT‑PM (2 rounds)

Round 1: 4 MAJOR + 2 MINOR on a cold read — all independently verified against the real repo (git ls-files, grep against CURRENT_STATE.md) and applied. Headline: OBS‑1's untagged-row-exclusion item pre-empted a still-open external clinical-authority decision (D1/H3 in CURRENT_STATE.md) — rescoped to an engineering-only invariant; §9 renamed to a non-exhaustive list with an explicit D1/H3 row added; P0's status corrected (G1–G6 closed, G0 blocked externally).

Round 2: confirmed round 1 landed correctly, then found 3 more MAJOR + 2 MINOR. Headline: the targetSdk deadline was overstated as non-negotiable — independently verified via web search against Google Play's own help page that an extension to 2026-11-01 is available via Play Console (availability for this specific account unchecked); wording corrected.

Rounds 3–4: round 3 (scoped via a note excluding unrelated files) found 1 MINOR, fixed a stale wording slip in DECISION_LOG.md. Round 4 (scoped to the exact commit, cb713e7) found 2 MAJOR that turned out to be non-defects on inspection (committing before consensus is by design; the HTML reports are excluded from GPT-PM's review scope by the tool's own REVIEW_EXCLUDE design, not an oversight) plus 2 real MINOR (a finding-count arithmetic slip, a missing forward-reference) — both fixed. --final not yet obtained; push was never requested.
