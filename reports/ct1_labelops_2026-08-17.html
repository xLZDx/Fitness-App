What was built

Nine executable components, 184 tests, in scripts/ct1/.

The design constraint everything else follows from: a reviewer who can see which rule fired is not producing a label, they are producing an agreement rate — and an agreement rate trained on looks exactly like a human label while being a slightly noisier copy of the rule that generated it. That is the feedback loop the label contract already refuses at the training step, and handing reviewers the machine's output would be refusing it in the one place it cannot happen.

The gate review

Four independent reviewers, round 1 with no shared output. Every MAJOR reproduced before it was accepted.

Major An adjudicator's name next to a value they contradicted

adjudicate() validated a ruling whose key had one reviewer, or two who agreed, then never read it — the branch order reaches SINGLE and AGREE before it consults a ruling.

ruling: value=False by qa.carol result: state=SINGLE value=True adjudicator='qa.carol'

Both states are USABLE, so a documented human correction would have been dropped into an immutable dataset while the record named the person who made it. Now refused: an adjudication of something nobody disputed is not an adjudication.

Major The baseline flagged duplicates by position in the file

Found by a test written for this review, asserting that selection is a function of the row id. duplicate_title, duplicate_summary and duplicate_steps_block reported the second and later occurrence in input order, so which member of a duplicate group got flagged was a fact about the catalogue's layout.

same content, rows shuffled → symmetric difference: 1 row flagged holdout population: 56 → 55 after the fix

A vendor re-export in a different order would have silently changed which rows reviewers were sent — the same instability the hash-based sampling exists to avoid, reached by another route. Fixed to the lowest id in the group; queue size unchanged.

Major The manifest described the contract and no consumer read it

Questions, verdicts, reason codes and schema version were written into every manifest while the page generator, importer and evaluator all read the code constants. Documentation that cannot be wrong is documentation nobody checks. Concretely: bump the constants, regenerate pages from a committed batch — the documented command — and reviewers answer v3 questions over a v2 batch with nothing erroring anywhere. check_contract() now refuses field by field.

Major SCHEMA_VERSION had not moved although the manifest shape had

Both 001 and 002 said schema_version: 1 while 002 had gained five fields, so a consumer dispatching on it could not tell them apart. Now 2.

Major CI compared what a reviewer opens, not what the metrics come from

sealed_baseline_labels.json is the ground truth behind every precision figure and the manifest carries the stratum populations the estimator weights by. Drift in either leaves items.json identical and the numbers wrong. All four artefacts are compared now, the manifest minus source_commit, with the path derived from BATCH_ID.

Minor Eight smaller findings, all confirmed and fixed

Six guards had no test at all. A non-dict review entry raised AttributeError from the middle of the loop instead of being refused with a sentence. A stratum with one reviewed row contributed full weight to the estimate and nothing to the standard error, silently — it says so now. import_reviews had an assignments=None default that disabled the unplanned-reviewer check for any caller that forgot it; a convenience default that turns off a check is a check with an off switch.

Two tests that could not have failed

The determinism test claimed to rule out a seeded shuffle. It did not — random.Random(seed).sample satisfies both of its assertions, measured. Its replacement asserts order-independence, which a seeded shuffle cannot satisfy, and it failed against the real code immediately, producing the baseline finding above. Separately, the double-review test asserted "fewer than half"; a mutation raising the share to 50% still passed because the hash landed just under the line.

Earlier in the session a mutation of the estimator survived: the shared fixture duplicated every second row, making both strata exactly 44 rows, which made a population-weighted estimate numerically identical to an unweighted mean. That is the third time in this programme a fixture has guaranteed its own outcome.

Why the batch is 003

The baseline fix moved two rows, so the reviewer assignments changed. Rebuilding 002 in place was tempting — it was committed the same afternoon, never pushed, and nothing had been returned against it.

That argument rests on nobody has a copy, and this checkout is shared: the 002 reviewer pages sat on disk where anyone could have opened one. A claim I cannot check is not allowed to be what a rule hangs on, and a new directory costs nothing and needs no such claim. 001 and 002 are both kept, 002 carrying a SUPERSEDED.md; a test rebuilds against 002/items.json and asserts the move was the small explained one rather than a reshuffle.

Deleting the superseded directories is an operator call. The shell policy hook blocks recursive deletes, and the response to a guard is to work with it rather than around it.
