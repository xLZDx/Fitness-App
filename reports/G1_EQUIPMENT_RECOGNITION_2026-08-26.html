03Round 1 — what GPT‑PM's review found

Every finding checked independently before accepting: re-reading the actual source, re-deriving the math, or reproducing the exact test fixture named.

Major · fixed

Client and server owned the same 20-second deadline

The mobile client's timeout and the server's model-call budget were both exactly 20s — but the server's clock starts only after auth, validation, and a Firestore quota transaction have already run. A legitimate ~18s answer plus that overhead could exceed the client's budget, silently discarding a paid, quota-charged answer for a weaker on-device fallback.

Fixed: client default raised 20s → 30s, with a comment cross-referencing the server's own 20s (left as-is, already tuned against measured latency).

Major · fixed

The claimed image validation did not validate an image

Server-side input checking accepted any non-empty base64 string under a length cap, labelled with one of three allowed MIME strings — never decoding or sniffing the bytes. The test suite's own “valid” fixture was literally the base64 for the plain text hello, and it passed straight through, labelled image/jpeg.

Fixed: strict base64 decode (rejects malformed/non-canonical encoding), a decoded-byte size cap, real JPEG/PNG/WebP file-signature sniffing, and a mismatch check between the declared and the actual MIME type. 4 new tests, including the exact hello case.

Minor · fixed

“No prompt-injection surface” overclaimed

True for caller-controlled text (there is none), not true in general — multimodal models can be steered by text rendered inside an image, a real if lower-severity residual risk.

Fixed: wording narrowed to “no caller-controlled TEXT field,” with an honest paragraph recording the multimodal risk as tracked, not solved.

Minor · fixed

Production wiring never exercised by mobile tests

Every mobile test injected the network call directly, bypassing the real httpsCallable wiring — a typo in the function name or a JSON key would compile and ship unnoticed.

Fixed: verified FirebaseFunctions/HttpsCallable have private constructors in the installed SDK (a direct fake is genuinely not possible without heavier test scaffolding this project doesn't have), then extracted the request-building and response-extraction into two pure, independently-tested functions plus a named constant. 4 new tests pin the exact contract.

Minor · fixed

The registry-parity test's normalisation was a simplified approximation

The new TS tripwire used a bare lowercase-and-trim, not the real Dart algorithm (also folds ë→е and collapses punctuation) — harmless against the current list, but a weaker guarantee than claimed.

Fixed: replaced with an exact port of the real algorithm.

04Round 2 — a defect in the fix itself

Sending the round-1 fixes back for verification surfaced a real problem in one of them.

Major · fixed

The new size check ran after the expensive part

The image-validation fix decoded the full base64 string before checking its length — so an oversized payload paid the decode/allocation cost, unmetered and before quota was even touched, en route to being refused.

Fixed: a cheap string-length guard added before decoding, sized to the exact ceiling for the decoded-byte cap. The post-decode check is now provably unreachable given the pre-check, but kept as defense in depth.

Two further MINORs — the decision log describing the round-1 (not round-2) state, and a leftover comment contradicting the fix it sat beside — were also found and fixed the same round.

A process note, not a code finding: a cross-session git collision

While updating an unrelated PM Bridge config file (routing this project to a fresh ChatGPT conversation after the previous thread hit its length limit), a plain git commit in the pm-bridge repository swept in four files another concurrent session had already staged there — a “Rosetta R0” feature, unrelated to Fitness_App. Nothing was lost or overwritten; the content is intact inside the resulting commit. But the commit message doesn't describe most of what it contains, and that session's own staged state was consumed by someone else's commit.

No further git surgery was attempted there: the other session was visibly still writing to the same file when this was noticed, and reset/rewrite against a live concurrent edit would have been the riskier move. Flagged transparently to the operator instead of quietly worked around.
