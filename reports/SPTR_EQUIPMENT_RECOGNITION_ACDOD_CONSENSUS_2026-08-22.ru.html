Итог одной строкой: документ с полным AC/DoD для всех 34 гейтов v4.4 (структура Jira: Epic = фаза, Story = гейт, Task = deliverable) прошёл три раунда состязательного ревью GPT-PM и получил финальный вердикт CONSENSUS — APPROVE FOR IMPLEMENTATION, 0 открытых BLOCKER/MAJOR/MINOR.

По пути было два поворота: сначала я реализовала облегчённую двухуровневую схему (полный AC/DoD только для ближайшей фазы, «скелеты» для остального) — вы это прямо отменили и потребовали полный AC/DoD везде и сразу, в иерархии Epic/Story/Task. Затем, уже на готовом документе, ревью GPT-PM нашло реальные, конкретные дефекты — не стилистику, а вещи вроде циклической зависимости между гейтами и отката уже закрытого design-инварианта. Всё исправлено и подтверждено.

Черновик 1

Двухуровневая схема (по рекомендации GPT-PM)

Полный AC/DoD только для P0 и P1.G1, для остальных 27 гейтов — лёгкие «Gate Contracts» (purpose, зависимости, ревьюеры). Вы отменили это решение: «твой воркфлоу должен включать AC/DoD для всего документа и гейтов/подгейтов как в жире — эпик, стори, таск, и для всего есть AC/DoD».

Черновик 2

Полный AC/DoD для всех 34 гейтов, Epic → Story → Task

Каждая фаза получила Epic-уровневый AC/DoD, каждый гейт — полный Purpose/Inputs/Deliverables/Verification/Required review/Exit/Rollback в формате Story, каждый deliverable — отдельная Task-строка со своим AC и DoD. Собрано из verbatim-текста v4.1 + поправок v4.2/v4.3/v4.4, без фабрикации.

Разбор: как выглядела настоящая находка

AC-B03 — «мы не строили P4» ≠ «visual-путь недоступен»

Самый поучительный момент всего цикла. Когда P2.G5 легитимно выбирает DEFER_VISUAL, фаза P4 (визуальный поиск) вообще не строится. Мой первый фикс сказал: раз P4 не существует — тест на «визуальное заражение» текстового пути автоматически проходит. GPT-PM указал: отсутствие нового кода не доказывает отсутствие ЛЮБОГО визуального пути — в приложении уже есть отдельная фича VisualMatch, про которую я не подумала.

Раунд 2 — отклонено

«Под DEFER_VISUAL тест существует, но его сценарий заражения тривиально проходит — сборка P4.G2 не нужна».

Раунд 3 — принято

CI-доказательство: ни один визуальный retriever/verifier/фича (включая VisualMatch) не достижимы из production text-lane; при появлении нового визуального компонента без повторного прогона этого гейта — путь автоматически уходит в NOT_SUPPORTED, никогда не EXACT_MODEL.

Что происходило с инструментом ревью попутно

Раунды 1–3 шли через pm-bridge — мост Claude↔ChatGPT с полной автоматизацией браузера. По вашему прямому указанию (после случая с «залипшей» проверкой автоматизации, которая на деле оказалась вашим же параллельным набором текста в том же окне ChatGPT) стандартный формат ответов GPT-PM изменён: теперь только простой Markdown в самом чате, без HTML/canvas-артефактов — файл сохраняю я сама. Дважды проверка «сообщение отправлено» ложно срабатывала как ошибка при реально успешной отправке — каждый раз проверялось напрямую по содержимому страницы перед повторной попыткой, чтобы не задублировать сообщения.
