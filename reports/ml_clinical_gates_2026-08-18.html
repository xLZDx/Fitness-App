Four Refusals

Four gates were built this session and every one of them is mostly a refusal: a model that may not be promoted, a clinician's judgement that may not be simulated, a pipeline that may not train, and a measurement that may not be quoted while it covers half the surface. This is the report on what was built, what was found wrong, and what is still open.

Gate 1 · commit a18e0daThe model lifecycle, and a registry generated rather than typed

core/ml/MODEL_REGISTRY.json already declared nine lifecycle states, and a Dart test checked that every model's state was one of the nine. That is membership, not legality — it cannot tell TRAINED from CHAMPION, and it would accept a model that moved between them in a single edit.

The two implications denied

TRAINED does not imply CHALLENGER. Being built is not evidence of being better.

CHALLENGER does not imply CHAMPION. Being better is not authority to ship. PROMOTION_REVIEW is the only door, and it is a human decision.

assert_no_train_deploy_coupling refuses a pre-champion model reporting a live deployment_status. CT ≠ CD: a continuous-training cycle may end at REJECTED, and that is a successful cycle, so nothing on the training side carries authority to ship.

The dataset registry is derived, never hand-maintained

Every field is read from a real artefact and CI re-derives the file, so drift is a failure rather than a discovery — a registry somebody maintains by hand is wrong the first time a dataset is rebuilt, and the failure is silent because the registry is the thing you would check.

training_run.py is a validator and not a framework — the two consumers a framework would need do not exist. Its CLI prints NO REAL CT-1 CHALLENGER TRAINED, which is the true state, rather than an empty table that reads like a clean history.

Gate 2 · commits a18e0da, 12b1909The clinical handoff said the opposite of what the app does

MAJOR · documentation defect · FACT

Section 4.1 of the clinical validation handoff said an untagged exercise is withheld. exercise_filter.dart:38 returns false when contraindications is empty, so the row is kept and shown — including to a user with a declared injury, and without telling them it could not be screened.

A clinician answering Q3 would have been answering about a product that does not exist. Corrected in place with an explicit correction block rather than a silent edit.

The same section mis-stated finding F013 as contested and not upheld. The audit records say the behaviour is REPRODUCED_VERIFIED and the blocker upheld; only the severity is contested 1–1. Behaviour, severity and the instruction not to act are now three separate claims.

Not fixed, deliberately

exercise_filter.dart:38 was not flipped to fail-closed. The audit's own instruction: do not flip it before D1 answers. Flipping it would remove hundreds of exercises from every injured user's library on this repository's guess about which ones are unsafe — which is the guess it has no authority to make.

The pin was bound to a branch, which moves

Section 8 previously named the branch formcoach/gates-a-c. It advanced three commits while the document sat unchanged, so a review “against the branch” could not be tied to anything. It is now pinned to the catalogue digest and byte count. A follow-up commit fixed a second-order defect: the recorded commit still named the revision at which section 4.1 was wrong.

Gate 3 · commits a18e0da, 77060d6A worklist a clinician can actually start on Monday

An independent review asked whether a real clinician could begin from the handoff alone. They could not, and five of the six blockers needed no clinical judgement whatsoever — a moving branch pin, no row-level worklist, no fillable format, no field anywhere for a reviewer's credentials or authority, and a rule vocabulary readable only as Python. All five were engineering. All five are closed.

Each row states, in its own cell, what the app does with it today: the corrected F013 claim on the row rather than in a section a reader may never reach.

Four things the validator will not do

It has no opinion about which tag belongs on which exercise, and a test fails if a heuristic mapping content to a tag ever appears in the module. A blank row is NOT REVIEWED, never accepted by default. UNKNOWN is a first-class answer — forcing a disposition on a row nobody can decide manufactures exactly the clinical judgement this repository must not manufacture. And a validated submission closes nothing: validate() returns closes: [] and says so.

It is deliberately not a flag on the CT-1 content importer. That module refuses to ask whether an exercise is safe, in its own docstring, and the refusal is load-bearing: a content reviewer must never be able to produce a clinical claim, and one file with a boolean between the two authorities would end that. A test asserts the two paths do not import each other.

Nine findings from gate review, all fixed

Two read-only specialists reviewed the committed gate. Neither found a way for a bad submission to be accepted; every finding was malformed input crashing with a traceback instead of this module's own refusal, or a test that guarded less than its name claimed.

  • A tags list holding an unhashable element raised TypeError out of the set-membership test.
  • A submission.json parsing to anything but an object raised AttributeError before a single field check ran — the ordinary shape of a truncated email attachment.
  • A sheet re-saved by Excel's plain CSV (Comma delimited) option is written in the local codepage with no BOM, and the catalogue's titles are not ASCII. The refusal now names the cause, says use CSV UTF-8, and says nothing is lost.
  • rows_csv could name an absolute path anywhere on disk, while the neighbouring refusal already promised beside.
  • A half-present worklist crashed CI on a raw FileNotFoundError.
  • handoff_commit was checked for presence and not content, so a hand-rebuilt header with a blank commit validated.
The test that guarded a blocklist

test_the_worklist_proposes_no_answer — described in its own docstring as the single most important property — listed the field names a proposal might use. A one-word rename defeated it. It is now an allowlist over the exact row and payload key sets, so any new field fails until somebody adds it deliberately.

Gate 4 · commit 77060d6Seven pipeline stages, and the eighth that does not exist

IMPORT → VALIDATE → ADJUDICATE → BUILD_EVAL → BASELINE_EVALUATE → ERROR_ANALYSIS → CHALLENGER_DECISION. The first five already existed; the last two, a single reproducible entry point, and any way to exercise the chain before a human label comes back did not.

GO does not start anything

GO means a person may now start a training run, not a training run started. A pipeline that trains on its own GO produces a model nobody chose. The test asserts this against the module's parsed import graph — a substring search cannot tell an import from the decision text that legitimately names the training-run validator, and the first version of that test failed on its own subject's prose.

MAJOR · two decision gates were dead · FACT

challenger_decision read dataset["agreement"] and dataset["adjudication"]. The builder produced neither — inter-rater agreement was never recorded in the evaluation dataset at all, and the adjudication key is adjudication_counts. Both gates passed on every possible input, including one where the reviewers agreed on nothing.

Found by writing a test that constructs the state each gate should trip. Not reachable by mutation testing, which breaks existing logic and cannot reach a branch that never executes.

Fixed at the root rather than in the caller: the evaluation dataset now records pairwise agreement over every question two reviewers both answered, pooled over compared answers rather than averaged over pairs. A null agreement means no two reviewers saw the same row, not they disagreed completely — a gate conflating those would refuse every single-review batch for a reason that never happened.

Error analysis separates three things a single number would merge

  • A miss is content a reviewer called defective and no rule fired on: a gap a challenger could close.
  • A false alarm is a rule too broad, where narrowing the rule is cheaper than training anything.
  • A silent question is one no rule maps to at all. The baseline cannot be wrong where it does not speak, and reporting that as 0.0 precision would send somebody to tune a rule that does not exist.

The fixture run was refused, and the refusal was kept

Running the chain on generated data hit reviewer_kind must be the literal 'HUMAN'. Stamping fixtures HUMAN would have made every fixture file a lie — the exact thing the field exists to prevent. So SYNTHETIC became a first-class kind and an import accepts exactly one per run; accepting both is refused, because a dataset holding one reviewed answer and one generated one could never be separated again. Three further guards keep them apart, including one in the dataset writer, because the other CLI never passes through the pipeline's.

Gate 5 · commit f153ff9The measurement that covered half the surface

MAJOR · FACT

Enabling App Check enforcement has three stated preconditions, and the second is the console has to show attestation actually succeeding. That number came from a log field emitted by 6 of 13 callables. deleteAccount, bookCoachSession and five others emitted nothing, so the observed attested share described half the surface while reading as though it described all of it — and the missing half included the two functions the code itself singles out as the ones you would not gate blindly.

All seven are now instrumented, and a test asserts over the source that every exported callable has a matching log call. The failure that guards against is a new callable shipping unmeasured, which no behavioural test of the existing ones can see.

Enforcement was not enabled, and N-05 is not closed

The three preconditions remain outside this repository. But the deeper reason is that App Check is the wrong control for N-05: it attests the app, not the account. Somebody creating a hundred accounts from a genuine, unmodified build passes attestation a hundred times. Turning the flag on would close a different hole and let N-05 look closed.
