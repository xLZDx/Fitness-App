Step 4 — four AI callables, App Check from the first revision

aiCoachAdvice, aiEquipmentRecognition, aiMachineDescription, aiExerciseGeneration shipped under their own least-privilege identity, fn-ai-runtime, with App Check enforced. Along the way, two side-effect regressions from closing Step 3 were found and fixed — not hypothetical, they genuinely broke the first deploy and the first test.

Regression A — the build failed before the first deploy Found at deploy time

Removing roles/editor from the default Compute SA (Step 3's closure) also removed roles/cloudbuild.builds.builder, the role gen2 function builds actually run under — the build failed for all four at once. Confirmed against Google's own documentation, fixed with one narrow role, nothing broader restored.

GPT-PM round 1 — 2 MAJOR, 2 MINOR MAJOR · 2

Both MAJORs held up under direct verification:

  • My own "403 with no token" test proved nothing: the new functions lacked the public roles/run.invoker every other callable already has — the request was blocked at Cloud Run IAM, before App Check ever ran. Fixed; after the grant, a genuine Firebase-shaped 401 UNAUTHENTICATED.
  • APP_CHECK_ENFORCED_AI only existed as mutable Cloud Run state — a clean redeploy with no manual follow-up would silently ship the AI callables unenforced again. Added envFlagFailClosed: enforced on any value except the literal string "false", with regression tests.
GPT-PM round 2 — the 401 didn't distinguish App Check from the handler's own Auth guard MAJOR · 1

A sharp point: the handlers themselves throw unauthenticated whenever request.auth is missing — the same 401 would appear even with App Check off. Required proof: a real Auth token with no App Check token. Delivered: the structured verification log showed app: MISSING, auth: VALID on all four — App Check itself is genuinely rejecting, not the handler's own Auth guard.

GPT-PM round 3 APPROVE

The full evidence chain accepted: identity → public ingress → fail-closed config → App Check genuinely rejects a request that lacks it. PUSH: AUTHORIZED — pushed as 3c163a9.

Step 5 — a real end-to-end path to Vertex, no mocking

GPT-PM correctly pointed out that Step 4's proof stopped at input validation — that doesn't exercise the AI chain itself. Step 5 closed exactly that gap, on a real Android device (the S8) via the App Check debug provider.

GPT-PM round 1 — the proof never reached Vertex MAJOR · 1

"App Check works, but quota/permissions/model could be broken — Step 5 would close without ever exercising the real path." Explicitly authorized as bounded: four small calls, no load testing needed.

A synthetic JPEG first passed our own magic-byte check but was rejected by Gemini's own decoder — proof by itself that the request genuinely got there; a real photo from data/gym_photos_2026-07-30/ resolved it.
