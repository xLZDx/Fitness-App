3. A real bug in build_release.ps1

Fixed, found incidentally

The release build silently failed three times this window (exit code 0, no APK produced) across different files. Root cause: this environment runs Windows PowerShell 5.1, where a native command's stderr line becomes a terminating error under $ErrorActionPreference = 'Stop' independent of 2>$null (which hides the displayed text, not the underlying error record). git diff --quiet HEAD exists purely for its exit code (1 = dirty tree, normal control flow) — but git occasionally also writes an unrelated autocrlf advisory to stderr for whichever file it last touched, which was enough to abort the whole script before $LASTEXITCODE was ever read.

A first fix attempt ($PSNativeCommandUseErrorActionPreference = $false) was wrong — that variable is PowerShell 7.3+ only and a no-op on 5.1; caught by re-testing (failed identically), reverted. Correct fix: locally scope $ErrorActionPreference = 'Continue' around just the one git diff --quiet call, saving and restoring the prior value — the script's global 'Stop' is untouched for everything else. Verified across 2 subsequent clean builds, including versionCode 2874 printing the dirty-tree warning correctly instead of dying silently.
