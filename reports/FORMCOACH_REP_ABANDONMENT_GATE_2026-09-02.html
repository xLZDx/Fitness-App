The defect, on the device

End of a real set, S23, 2026-09-02. The thirteenth "repetition" ran to 980 observed frames — roughly 33 seconds — against a set whose tempo readout averaged 1.9s. It completed. It was scored against a target it had never been anywhere near (peak match 0.072), the set summary gained a repetition nobody performed, and the lifter — who had stopped half a minute earlier — was told they had not reached the shape.

Recorded in reports/device-check-2026-09-02/logcat_reps.txt, line 13 of the extracted reps_all.txt.

The counter had a floor — a lap under 600ms is a landmark glitch, not a body — and no ceiling at all. Nothing stopped an open repetition from sitting indefinitely once the lifter walked away or the detector lost them.

The pause fix, in its final form

The camera keeps delivering frames through a pause by design — a paused set is not a dead camera. So gating the ceiling check on "counting is live" (round 1) stops it from firing mid-pause, but the frame clock underneath keeps moving. The first live frame after resume can carry a timestamp tens of seconds later, and comparing it straight against the moment the rep opened would abandon it the instant the set resumes.

Two narrower fixes were tried and both failed their own regression test before the third landed:

  • v1 — mark the pause boundary from the first frame seen while already paused. Fails when the paused frame arrives long after the pause actually started: the measured gap only covers part of the real pause.
  • v2 — mark it from the last frame seen while still live instead. Correct when at least one frame arrives during the pause, but sets nothing at all when zero frames do — exactly what a genuinely stalled camera looks like.
  • v3, shipped — mark the boundary from the coach-phase transition itself, via a ref.listen on the phase provider. Correct with any number of frames during the pause, including zero, because it no longer depends on a frame arriving to notice anything happened.

Every version was proven wrong or right the same way: rep_expiry_pause_test.dart run against the real code, then mutation-checked by reverting the fix and confirming the test fails.

The golden flake

The visual-regression suite picks a random backdrop photo per test, seeded for determinism. The seed fix (round 1) made WHICH photo a test picks independent of the other tests in the file — but Image.asset resolves through a real asset-bundle read that the first golden to touch a file pays for and every later one gets free. The same seeded pick still rendered as a photograph inside the full file and as the plain scrim underneath it when the same test ran alone: a 95.64% pixel diff, caught by running each golden individually with --plain-name.

Fixed with precacheImage, forced onto each container's own clock before capture. Verified stable as a full file (×3), each golden alone, and two-of-three partial combinations — all identical to the recorded reference.
