Three mistakes of mine

GPT-PM caught the first two, the operator caught the third. All three were verified against the actual source and are recorded in the decision log alongside the successes — a log that only records wins stops being evidence.

BLOCKER

A secret's value went into a plan-closure payload

Closing AUTH-DIAG-1, I pasted the App Check debug token's actual value into the evidence text. The token was already sitting in the repository in plaintext, but I added one more leak channel — the review exchange itself. At the time I did not know whether it was still valid; it is now known that it is not. That is not a defence: “a secret's value is never printed anywhere” cannot be conditional on the secret being live, because nobody checks that before publishing.

Fixed: the value was removed and the re-submitted closure carried none. No token is printed into the log, the reports or any GPT-PM message from here on — verified after every write.

MAJOR

I called signing in “reversible”. It is not

To close R2 autonomously I proposed signing into Google on the S8, arguing it could be undone with the app's own Sign out. GPT-PM rejected it; I checked the source and it is right: linkWithCredential permanently attaches the Google identity to the same UID (mobile/lib/features/auth/data/firebase_auth_repository.dart:155-165), and on credential-already-in-use the guest data is left unreachable (same file, :193-199).

The option was dropped and stayed dropped until the operator authorised it in their own words; only then was the sign-in performed — and it behaved exactly as GPT-PM predicted.

MAJOR

I described a machine without opening the source photograph

The decision log received a sentence calling the failing frame “a leg-press / hack-squat style machine”. The operator rejected it on sight — “no, what is on screen is not a hack machine, look properly” — and was right. I had described the machine from a 422×278 crop of a photograph of a monitor, while the source image sat on this same machine and took one command to open.

It is in fact a plate-loaded LAT PULLDOWN — an upper-body back machine. The features the identification rests on are visible in both frames: a footplate at floor level, a horizontal thigh restraint pad above it, a saddle seat, a tall inclined torso pad, two long arms arching overhead into converging handles, and plate horns low on both sides. The footplate carries a moulded STAR TRAC logo, which makes Star Trac's plate-loaded line the obvious make — but that is read off branding in the photograph rather than checked against a model catalogue, so it is recorded as the likely make, not a verified model.

The frame is D:\Downloads\Photos-1-001\20260810_131311.jpg, identified by the ceiling luminaire, the exit sign and the machine itself; the same machine from another angle is D:\Downloads\Photos-1-001\20260730_135543.jpg. Open defect: recognition accuracy

Formally outside SCAN-G1 — core/SCAN_G1_SCOPE.md puts the recognition pipeline out of the gate under the standing rule “recorded, not fixed”. But the product's promise is to name the machine in front of the user, and on this frame it does not.

lat pulldown

A plate-loaded lat pulldown: footplate, thigh restraint pad, saddle seat, two arms arching overhead into converging handles. Upper body, back. The make (STAR TRAC) is read off the logo moulded into the footplate.

What the app answered

55

“Glute kickback”, outcome confident — the MATCH header and the “Open exercises” CTA. One run earlier: 45 / 35 / 15 — all three lower-body too.

The right answer was available

in the catalogue

lat pulldown is in CANONICAL_MACHINES (functions/src/ai_equipment_recognition.ts:76). The model was not forced into a wrong label by a missing class — the class was there and was not chosen in either recorded run.

MAJOR

Confidence is decided on the top-two margin alone — there is no absolute floor

ScanResult.fromMatches (mobile/lib/features/visual_equipment/data/scan_outcome.dart:128-160) separates confident from alternatives on the top1–top2 margin alone (confidentMargin = 0.15) and returns confident unconditionally when there is a single candidate.

So 0.55 with nothing close behind enters the same confident state as the correct 0.85 — the same header, the same CTA, and the same persistence eligibility via isWorthRemembering — while displaying a lower number. The score is shown; the state it produces is not differentiated by it at all. The same file already refuses to let the on-device path look settled “however sure the model sounds”; there is no symmetric protection against looking settled while being unsure on the cloud path.

This is app code, not model behaviour: checkable, and fixable without retraining. It goes to a separate measured gate together with the operator's 52-photograph corpus.

The transport was clean throughout: seven consecutive successful calls between 09:22:03 and 09:27:57 UTC, each auth VALID / app VALID / attested true / outcome success, 1291–2595 ms. Nothing failed — the pipeline delivered a confident wrong answer.
