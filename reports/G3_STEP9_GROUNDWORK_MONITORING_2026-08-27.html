01 What was built

All four items are definitions only. No live GCP resource (metric, alert, notification channel) was created at any point in this work.

Stripe: duplicate-subscription reconciliation failure

Done

A LogMatch policy for the Stripe webhook handler: matches exactly the two reconciliation failure log lines, not the two neighboring success/warning logs from the same code path. Scoped to the stripewebhook Cloud Run service (not a function name — see below).

Account deletion and export: operational failures

Done

A mandatory failure-path audit ran before declaring this done: the subscription-document read in deleteAccount happens BEFORE its first try block — none of the three named error logs would fire if it threw. Found and verified a real platform backstop: firebase-functions' own onCall wrapper catches any unhandled exception and logs "Unhandled error" — but only when it is NOT an HttpsError, i.e. only for genuinely unexpected failures. Both filters include this backstop.

App Check: attested-call ratio

Done · metric not created

The visibility itself was already built earlier (discovered by scouting, not reinvented). This part added a real log-based-metric definition (not just a filter) with bounded cardinality: 17 known call sites x 2 attested values. The 17-entry list is now mechanically cross-checked against the actual source inventory by a separate test — a future 18th call site not added to the list fails that test instead of silently slipping through.

AI Gateway: four metrics and seven queries

Done

A call counter (operation x outcome), a latency distribution (bucket boundaries centered on the code's own real timeouts — 20/25/45 seconds), a token-usage distribution (deliberately includes failed calls too — tokens can be spent before a response turns out empty), and a quota-exhaustion counter (a separate event — the gateway itself never sees a quota refusal, since the quota check runs earlier). Plus seven named queries for manual Log Explorer investigation.

02 Six rounds, four real findings

Every finding was substantive: the code genuinely would not have worked as intended had it shipped in its original form.

Round 1 · wrong Cloud Logging resource model
Filters used resource.labels.function_name — the Gen1 Cloud Functions shape. The whole project runs on v2 (Cloud Run): real log entries carry resource.type="cloud_run_revision" and resource.labels.service_name. With the original filter, a monitor would match exactly zero real log entries — green during an actual failure.
Round 1 · not a real alert policy
Definitions only produced a filter string, not a full AlertPolicy JSON (needs combiner, conditionMatchedLog, a rate-limited alertStrategy, a channel list).
Fixed · round 1
Added a function deriving the real Cloud Run service name from the TypeScript export name. Added a full AlertPolicy renderer with an empty channel list — both shapes checked against Google's own REST reference before writing the code, not guessed.
Round 2 · not actually exhaustive drift protection
The AI Gateway's 4-operation list was only checked with satisfies — which proves every array element is valid but NOT that every type member is present. Add a 5th operation and the code still compiles, silently excluding the new one from every metric.
Fixed · round 2
Single source of truth: the operations array now lives in ai_gateway.ts, with the type derived FROM the array instead of declared separately. The monitoring module imports the exact same array — the duplicate that could have drifted no longer exists structurally.
Round 3 · same problem, for App Check
App Check's 17-known-callable list is a plain string set, not a TypeScript type, so the same structural fix didn't apply — the list needed manual upkeep with no mechanical guard at all.
Fixed · final approval
An existing test in scaling.test.ts, which scans the real source files for every callable, was extracted into a reusable helper. A new test compares the 17-entry list against that real inventory in both directions: a missing callable fails the test, a stale entry fails the test.
