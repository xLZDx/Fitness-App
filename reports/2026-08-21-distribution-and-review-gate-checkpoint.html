2 · A new commit/push gate, installed live, satisfied honestly

The operator installed a new machine-wide review mechanism (pm-bridge + gpt_review_gate.py) mid-session, in a concurrent session, replacing the previously suspended Codex gate. It fired against this repo's next commit with no prior warning in this session's own context. Read the tool's source before running it rather than treating it as a black box: it sends a diff to a GPT web session via an automated browser, and is explicitly designed to fail open — a failed attempt still writes a receipt and satisfies the gate, only a call that was never attempted blocks it.

Ran it for real. The first call failed on a real, expected condition — the shared browser profile was in use by another concurrent session at that moment, since this tool is shared machine-wide infrastructure, not per-project. That failed attempt's receipt still satisfied the gate. No hook was edited, no receipt was fabricated, no kill switch was set inline. Recorded as a reference memory so a future session has context instead of guessing at this on first contact.
