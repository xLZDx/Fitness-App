Пустой Home после блокировки PAR-Q — причина найдена, исправление проверено на устройстве

Кнопка «Проверить мои ответы о здоровье» на экране блокировки уводила на пустой Home вместо анкеты. Причина — редирект в GoRouter, а не зависание движка.

Коротко

Оператор записал видео: на вкладке «Библиотека», при незаполненной анкете здоровья (PAR-Q), нажатие на упражнение показывает экран блокировки «Это упражнение придержано». Нажатие на его единственную кнопку — «Проверить мои ответы о здоровье» — вместо анкеты оставляло пустой Home: только фоновое фото, без контента и часто без нижней навигации. Эффект не самовосстанавливался и повторялся на любой вкладке.

Причина — не зависание Flutter-движка, а роутер: push('/onboarding') для уже онбордженного пользователя молча подменяется редиректом на /home, а именно в этом состоянии (онбординг пройден, PAR-Q — нет) и находится каждый, кто видит этот экран. Исправление: та же кнопка теперь ведёт на /onboarding/edit — путь, специально созданный, чтобы пережить этот редирект. Проверено вживую на S8: анкета открывается, возврат назад работает корректно.

Как искали причину

  1. Видео от оператора: Тренировки → Библиотека → блокировка PAR-Q → Back → Home пуст; тот же пустой экран остаётся при переключении на «Прогресс».
  2. Проверка debug-трейсов: оператор указал: «если дебаг это не ловит — значит он сломан». Подтверждено кодом: kDebugMode-трейсы вырезаются из релизной сборки компилятором Dart полностью — их отсутствие ничего не доказывает. Баг воспроизведён отдельно на debug-сборке из текущего HEAD, чтобы убедиться, что условие бага не специфично для релиза.
  3. Живой logcat на S23 (релиз 1.0.0 / 2656): оператор переподключил устройство и воспроизвёл баг вживую («все как на видео»). ~48 минут захвата, процесс приложения жив и на переднем плане всё время — и ни одной строки от самого приложения: ни исключения, ни ANR in com.fitnessapp..., ни предупреждений Choreographer/Davey. Это исключило пойманное исключение, системный ANR и обычный джиттер кадров как причину.
  4. Оператор описал повтор словами: «банер появляется, я соглашаюсь, и всё пропадает, только обои остаются» — один тап на кнопку экрана блокировки, без Back.
  5. Разбор кадров видео (2 fps): кадр 16–17 — экран блокировки с единственной кнопкой «Проверить мои ответы о здоровье»; кадр 18 (0.5 c спустя) — уже пустой Home. Это указало на конкретный onPressed, а не на «Back» как триггер.

Причина FACT — прямое чтение кода

Кнопка вызывает:

onReviewProfile: () => GoRouter.of(context).push('/onboarding'),

А в роутере есть защита от возврата уже онбордженного пользователя в мастер онбординга по старой ссылке/кнопке «назад»:

// app_router.dart:108-110
if (isSignedIn && isOnboarded && location == '/onboarding') {
  return '/home';
}

isOnboarded — это грубый флаг «мастер онбординга пройден один раз», независимый от того, заполнен ли конкретно шаг PAR-Q внутри него. Аккаунт вполне может быть isOnboarded == true и при этом иметь полностью пустую анкету здоровья — именно это и показывает экран блокировки. То есть кнопка, которая существует специально для случая «анкета не заполнена», почти всегда стартует из состояния, где этот редирект активен, и её нажатие молча превращается в переход на /home.

/home — дочерний роут внутри единственного ShellRoute приложения (общая оболочка с нижней навигацией), а сам экран блокировки открыт как отдельная страница на корневом навигаторе, вне этой оболочки. HYPOTHESIS — не доказано трейсом, но согласуется со всеми уликами: push в состояние, вложенное в ShellRoute, из точки вне её, при уже смонтированном экземпляре оболочки ниже в стеке — вероятный механизм именно «пустого контента без единой ошибки в логах», а не полноценного зависания потока.

Где ещё воспроизводится «пустой контент, без фона/навигации»

После разблокировки телефона оператором был пойман второй скриншот того же семейства симптомов: вкладка «Тренировка → Программы» с видимым контентом, но полностью чёрным фоном (без обычного HUD-фото), без нижней навигации и с неактивными на вид кнопками «Начать программу» — визуально согласуется с жалобой оператора «нельзя запустить ни одного упражнения».

Исправление

Шесть мест, где кнопка «Проверить мои ответы о здоровье» вызывала push('/onboarding'), заменены на push('/onboarding/edit') — путь, уже существующий и явно построенный «как вход, переживающий редирект» для уже онбордженного пользователя (тот же приём уже используется в Профиле, для правки ответов).

Открытые вопросы

1. S23 с релизной сборкой

Фикс подтверждён только на debug-сборке на S8. На S23 всё ещё стоит релиз 1.0.0 (2656) с багом — для полной проверки нужна новая сборка и переустановка там же.

2. Механизм «пустого контента» — не до конца доказан

HYPOTHESIS: разрыв состояния оболочки (ShellRoute/ GlobalKey) при push поверх уже смонтированной оболочки. Фикс убирает сам триггер (редирект больше не подменяет цель), поэтому механизм больше не воспроизводим для прямой проверки трейсом — оставлено как непроверенная гипотеза, а не факт.

3. Просьба оператора: ограничить это сообщение только онбордингом

«...текст на банере не читается и почему он там вообще появляется я не понимаю — это должно быть только частью онбординга, и потом нигде не должно быть упоминаний... это часть [онбординга]»

Не выполнено в рамках этого фикса. Непрочитанный текст на скриншоте, скорее всего, был симптомом именно этого бага (чёрный фон вместо HUD-фото — см. раздел выше), а не отдельная проблема контраста самого баннера. Но сама просьба — показывать это сообщение только при онбординге — шире, чем навигационный баг: код (eligibility_notice.dart, комментарии F017/N01 в workouts_page.dart) явно и осознанно делает этот блок сквозным — он обязан появляться на любом экране, где человеку могут выдать упражнение (Тренировки, запись на программу, AI-план, диплинк), а не только при онбординге, чтобы поймать человека, который оставил PAR-Q незаполненной и позже. Это самостоятельное продуктовое решение с уже записанным обоснованием в коде — требует отдельного явного решения оператора, не сделано молча вместе с этим фиксом.
