Вопрос масштаба — до кода

Референс vs реальный экран: несоответствие масштаба

Референсный экран Session — минимальный: кольцо, список подходов done/current/pending, одна кнопка с динамической подписью. Реальный workout_player_page.dart — ~970 строк: видео, карта мышц, шаги техники, карточка Form Coach, чип рекомендуемого веса, таймер подхода (уже на HudRing), инструменты (блины/разминка), таймер отдыха, и четыре последовательных кнопки действий (Завершить / Добавить упражнение / Запланировать / В программу). У референса нет аналога ни для видео, ни для карты мышц, ни для инструментов, ни для расписания.

Решение GPT-PM (записано как governance-правило для этого экрана): «Референс Session авторитетен для визуального языка и presentation-состояния таймера там, где есть прямое семантическое соответствие. Он не авторитетен для удаления продуктовой функциональности или изобретения более узкой архитектуры плеера там, где соответствия нет».

Что сделано — в рамках этого решения

Два пункта, оба явно одобрены GPT-PM

  • RestTimer → HudRing

    56px-индикатор отдыха теперь рисуется через тот же HudRing, что и таймер подхода (уже был на нём с прошлого раунда), а не через штатный CircularProgressIndicator. То же состояние, те же коллбэки, тот же pause/skip/reset, те же ключи виджетов.

  • Цвета таймеров → семантические токены

    SetTimerCard и RestTimer: пять фаз подхода теперь красятся через AppSemanticColors вместо буквальных AppPalette.aurora*. danger сознательно не используется — ни одна из фаз не несёт смысла ошибки.

Явно вне рамок этого гейта: четыре кнопки действий страницы остаются раздельными и без изменений; новый список статусов подходов (done/current/pending) не создаётся — GPT-PM: такой список требует state-модели, которой пока нет как чистой read-only проекции существующего состояния.

Ревью GPT-PM — 3 раунда

От MINOR к спору о версии Flutter — к APPROVE

  1. 1
    Коммит 15e51a6 MINOR
    Замена кольца незаметно потеряла semantics-роль прогресса, которую штатный CircularProgressIndicator давал бесплатно — HudRing оборачивает в Semantics только при semanticsLabel, а этот путь исключает из дерева semantics дочерний текст с обратным отсчётом. Остальное (геометрия кольца, общий accentPrimary у idle/work, неиспользование danger) подтверждено чистым.
  2. 2
    Коммит 63c51f5 MINOR — исправлено частично
    Обратный отсчёт снова озвучивается, но GPT-PM указал на SemanticsRole.progressBar + minValue/maxValue как обязательное исправление. Эти API отсутствуют в закреплённой версии проекта — Flutter 3.27.1 (проверено: grep -rl SemanticsRole по исходникам SDK — ноль совпадений; добавлено во Flutter позже). Прочитан реальный ProgressIndicator._buildSemanticsWrapper этой версии — старый виджет всегда отдавал только процент, без роли и границ.
  3. 3
    Коммит ceef1de VERDICT: APPROVE
    Восстановлен именно процент (не несуществующий API), рядом с обратным отсчётом — "1:30, 0%". GPT-PM независимо перепроверил тегированный исходник 3.27.1 и подтвердил: собственная цитата раунда 2 была для более новой версии Flutter и не подходит этому репозиторию. PUSH: AUTHORIZED.
