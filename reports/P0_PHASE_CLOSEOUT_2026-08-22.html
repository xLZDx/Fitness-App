03The two outcome decisions

Two gates didn’t just pass or fail — they reached a specific, evidence-backed decision worth stating plainly.

P0.G5 · cloud feasibility

Outcome: OCR_TEXT_ONLY_DEFER_VISUAL. No safe non-production Firebase/GCP project exists to probe a Vertex AI / vector-search path — the only available project is the one stripeWebhook runs in. Rather than test against production or guess, every probe is honestly recorded NOT_ATTEMPTED and no provider SDK was installed. Visual equipment recognition stays deferred until a safe staging environment exists.

Strategy: SEPARATE_FIREBASE_CODEBASE. The new equipment-identity ML work gets its own Firebase Functions codebase, package, and CI job — proven, not asserted: a deliberately-broken identity module was shown to fail its build while the real Stripe-carrying codebase kept building clean at the same time, via real npm/tsc subprocess runs.

05The one real defect: a stale evidence hash

Found by the final adversarial review round, independently reproduced before being trusted, then fixed within the same pass.

Major · fixed

P0.G1’s baseline recorded a hash from before P0.G4’s own line-ending fix

recognition_baseline_v1.json, committed first in the phase, recorded the equipment catalog’s CRLF-based SHA-256. Roughly four hours later, P0.G4 fixed exactly this class of drift for its own snapshot artifact by pinning line endings — but nothing regenerated P0.G1’s baseline afterward, so it silently kept the stale hash.

Why nothing caught it: every existing test compared a freshly-built payload to a freshly-computed hash of the current file — a tautology that stays green even when the real committed file on disk is stale, because it never loads and checks what’s actually committed. CI never ran the generator’s own --check mode against the real file either.

Fixed: regenerated the artifact for real — the diff is exactly the affected hash and source-commit fields; the type count didn’t change, confirming the catalog’s actual content never did either, only the byte representation the hash was computed over. Two new tests now check the real committed files instead of a fresh temp copy, closing the gap for good.

06Final adversarial review

Three independent, cold-read agents against the whole nine-commit P0 diff — not just the last gate’s changes — hunting specifically for invented provenance, rights fail-open paths, false cloud-feasibility claims, accidental dual deploys, hidden production mutation, and stale evidence.

No issue on all four areas: no hidden production mutation, no path to an accidental dual deploy, no secret or PII disclosure in this public repo, and no way to construct a rights-registry entry that bypasses the review requirement.

Provenance authenticity

No issue on all four areas, verified against the real orchestration code the baseline doc describes — not just the doc’s own claims about itself. One minor doc-checklist fix applied.

Evidence integrity

Found the stale-hash MAJOR above. Cloud-feasibility claims checked clean. Two areas left honestly unfinished by the agent rather than guessed at; partially closed by direct follow-up (see below).
