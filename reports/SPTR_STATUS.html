02 D-03: the real root cause, found and fixed

The previous version of this page recorded D-03 as an App-Check race hypothesis. That hypothesis did not hold up against the code: firebase_auth_repository.dart already guarantees currentUser is assigned before the authStateChanges() stream event fires (verified against the Firebase SDK source). The real cause turned out to be deterministic, not probabilistic.

A router-redirect exemption for anonymous sign-in from /login

app_router.dart's resolveRedirect() carries a guest-upgrade exemption: if (isSignedIn && !isAnonymous && location == '/login') return isOnboarded ? '/home' : '/onboarding'; — the condition requires !isAnonymous. Right after an anonymous sign-in the user is exactly anonymous, so this branch never fires, and /login is in _publicPaths, so the redirect never touches it either way. The UI stayed on /login not because of a race, but because no redirect branch treated "just signed in anonymously" as a reason to leave /login.

Fix: the "Continue" (anonymous) button in login_page.dart now calls context.go('/home') explicitly after a successful signInAnonymously(), instead of relying on GoRouter to re-evaluate the redirect on its own.

Proof, not just code review: a new widget test using a controllable fake repository (_ControllableAuthRepository) that splits the currentUser assignment and the authStateChanges() stream event into two independently-triggerable steps — the fix is verified regardless of whether the stream fires in time. The test's first version wrongly assumed the race hypothesis; rewritten after its first run got stuck even with the stream firing correctly — that is what actually surfaced the real cause.

Not done this pass: real-device verification (20 trials on S8, the program's own FIXED_VERIFIED bar) — this session has no adb/Android SDK access. Status is FIXED, not FIXED_VERIFIED.

    • 04 Closing the governance blocker: gym-webhook-disclosure

    Codex review of the Gate F port (the next commit in the queue, "gym identity") raised a BLOCKER: Gate F is the first client code that ever supplies a real gymId on an equipment report, which makes an already-existing but previously unreachable server-side dispatcher (functions/src/index.ts's reportEquipment → a webhook at gyms/{gymId}.maintenanceWebhookUrl) reachable — while the published privacy policy still stated flatly that "Two processors are involved, and no others."

    Operator decision: DISCLOSE, not REMOVE

    A gym that has registered a maintenance channel is now documented as a conditional third recipient of a report's contents — not a "processor" in the GDPR Art. 28 sense: a gym fixes its own equipment for its own purpose, not on the app's instructions, which is itself the correct recipient-vs-processor test (Art. 4(8)), not merely the absence of a signed agreement. The dispatch code is unchanged.

    Four rounds of Codex review on this closure, every finding fixed: round 1 — the decision record's draft wording overclaimed the legal status ("processor"); round 2 — the ledger invariant only checked one surface/direction; round 3 — the check was a whole-file substring search instead of reading the actual policy value (a decoy in an unrelated key could pass unnoticed), plus Terms of Service had drifted from Privacy on the report's stated purpose ("to correct the catalogue" vs. "forwarded to the gym"), plus the invariant never checked that the dispatch itself still existed; round 4 — the policy's "short version" bullets still promised unconditionally that "everything is stored in the EU" and "everything can be deleted," even though a forwarded report already leaves the app's systems, plus the decision record justified "recipient" status by the absence of an agreement instead of the actual purposes-and-means test.

    The resulting invariant, gym_webhook_disclosure_stays_honest(), checks six texts (the canonical source plus both .arb files plus public/privacy.html, both languages — each via a direct import/JSON parse of the specific value, not a whole-file search), the dispatch itself in functions/src/index.ts, and the decision-record file's presence — and reopens if any of that stops being true. Full suite: 137 (was 135, +2 new tests for the decoy and dispatch-removal cases).
