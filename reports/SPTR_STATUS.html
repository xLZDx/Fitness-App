02 D-03: the real root cause

The candidate fix from the prior session (Material + Semantics(button: true)) closes a real, separate accessibility defect, but is not D-03's cause. 20 clean trials on S8 (canonical bab46c6) on a rebuilt binary with the correct App Check debug token.

The tap is delivered. signInAnonymously() genuinely succeeds. The UI does not leave /login.

Method: polled for screen readiness via uiautomator dump instead of a fixed sleep — the first attempt on a fixed sleep gave a false result, since the screen didn't exist yet at tap time. Tap coordinate taken from a screenshot, not from the accessibility node's bounds: the D-03 fix's merge semantics combine the title, subtitle, and the button itself into one node whose centroid lands on the subtitle text — a separate, newly found accessibility defect.

Result: 5/10 success, 5/10 never leave /login within 25s. Strictly bimodal, not a ~50% flake. Successful trials reach /login in ~3.6–3.7s and navigate on ~4.4s later. Failing trials reach a visually identical /login in ~15.5–15.7s — and then stay stuck.

W LocalRequestInterceptor: App attestation failed (403)
W LocalRequestInterceptor: Too many attempts
D FirebaseAuth: Notifying auth state listeners about user ( Q6lcurNjxGcvB9FMlgsGw7ck0ln1 )

The five successful trials carry zero App-Check-related log lines. The five stuck trials all show this exact error pair before the (still successful) sign-in — 5/5 correlated, not sampled. Working hypothesis (not confirmed against source): app_router.dart's redirect reads authRepo.currentUser synchronously and only re-runs on notifyListeners() from profileListenable — on this timing, either the notification never arrives or currentUser hasn't caught up yet. Same defect class MVP-1/MVP-3 closed on the marketing/site-prototype-2026-08-19 branch (see §4) — but a different call site neither fix covers.

Next step (not done this pass): reproduce under a controlled widget test (the same pattern MVP-3 used — racing a controlled StreamController) before touching app_router.dart — test-first, not a guessed fix.
