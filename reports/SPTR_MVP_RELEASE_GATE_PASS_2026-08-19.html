01The one check this pass exists for

A real cold start, not a mocked stream.

MVP-3 (closed earlier this session) makes the splash screen wait for authUserProvider's real first emission before ever navigating past /splash, closing a race where the router could bounce a real signed-in user to /login during Firebase's session restore. The unit tests for that fix use a manually-controlled stream to model the restore window — correct, but still a simulation. This pass did the thing itself: signed in, force-stopped the app (a true process kill, not backgrounding), cleared logcat, and relaunched.

Logcat for the relaunch had no MVP-3: line (the failure/timeout log this session's fix added) and no FATAL/AndroidRuntime crash — the real stream emission won the race against the 5-second safety timeout, the exact fast-path behaviour the fix was written for, confirmed on genuine Android auth-stack timing rather than a scripted one.

04A near-miss, checked before trusting it

The Profile page's "health questionnaire" tile bounced straight back to Home twice in a row when tapped — briefly looked like a fresh navigation regression from this session's router-adjacent work. Checked before assuming so: it isn't. injuries_page.dart's own doc comment documents this exact dead end as pre-existing — that tile routes to /onboarding, and the router's redirect bounces anyone already onboarded straight back home, which is the stated reason a separate /injuries screen exists at all. Tapped the correct tile instead; it works, as shown above.

05What's still open, and why it stopped here

Scan recognition round-trip. This AVD has no camera passthrough (the preview renders black) and no gym-equipment photo was available through the photo-picker to substitute for one. Needs a real device, or a seeded test image on the emulator.

Account-switch isolation. Not exercised — needs a second real account on the same device, not just a second anonymous session.

EN locale, confirmed live. adb shell cmd locale set-app-locales reported the per-app locale as applied (en-US), but the app kept rendering Russian after a force-stop + relaunch — read as a locale-propagation timing quirk between Android's per-app-language mechanism and this app's deviceLocalesProvider (which reads platform locales once at provider-container creation), not chased further given the cost of root-causing an AVD quirk versus its value here. The automated suite's default test locale is English and passed 2508/2508 including every test touched this session — offered as indirect evidence, not a substitute for a live check.

Each remaining item needs tooling this pass didn't have — a camera-capable real device, a second account, or a way to reliably force English on this specific emulator image — rather than more ad hoc adb probing on the same setup. Per the MVP closure plan's execution order, the release gate stays open and the final dream-team review waits on it.
