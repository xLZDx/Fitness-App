02What changed

Before this gate, targetSdk was inherited from the Flutter default (already 35, not lower). Android enforces edge-to-edge by default from API 35; API 36 removes the app's last opt-out — and with it, the automatic system-bar padding that had been masking missing SafeArea widgets.

04Live testing found two regressions — the second caused by the first fix

Plan v2 required a mandatory rebuild-and-re-smoke after any fix for exactly this reason. It worked: self re-verification (not GPT‑PM) caught a regression introduced by the very first fix.

Found by live testing · fixed

The scanner's low-light banner slid under the status bar

On a real API 36 device, the status-bar inset for this Positioned banner was no longer applied automatically (unlike the neighboring ScanTopBar, which already had a SafeArea).

Fixed: banner wrapped in SafeArea(bottom:false).

Self-inflicted regression · fixed

The first fix itself caused the banner to overlap ScanTopBar

After the first fix, both elements independently positioned themselves from the same safe-area edge — exactly the anti-pattern already documented in CoachTopStrip's own comment: two independently-Positioned Stack children collide the moment either one's height changes.

Fixed: both elements merged into one Column under a shared SafeArea instead of independent positioning.

Found by fix-the-class search · fixed

CoachTopStrip in Form Coach — same defect class

Per "fix the class, not the instance" (CLAUDE.md §17), the codebase was grepped for the same pattern before treating the scanner bug as isolated. A second real instance was found.

Fixed: wrapped in SafeArea(bottom:false). A third similar-looking candidate (exercise_reference.dart) was checked and found already correct.

05What GPT‑PM's review found — round 1

Every finding was independently verified before acting on it, including live on-device testing where a code read alone was not enough.

Major · fixed

The final smoke matrix was incomplete/stale

Intermediate evidence did not cover the full final candidate.

Fixed: a complete re-run of all 11 items against the exact final candidate (section 06).

Major · fixed

The AAB was unverified and possibly "dirty"

A clean rebuild without the -dirty stamp and an independent signature check were required.

Fixed: clean rebuild (GIT_SHA=d8525cd, no -dirty), verified via jarsigner -verify -certs (apksigner doesn't support .aab) — same real signing identity as the APKs.

Major · verified live, not confirmed as a regression

Predictive back gesture risk on API 36

The app already had documented history with exactly this bug class (main_shell.dart, PopScope/_AnnounceShellCanPop, entry dated 2026-08-13) — so this finding was verified with a live device test rather than a code read alone.

Verified and not confirmed: 3 scenarios on S23 (sub-flow pop, non-Home tab → Home, Home → exit) — all passed correctly on build 736.

Minor · fixed

The stated root cause was overstated

A code comment claimed the defect was "masked below targetSdk 35" — inaccurate, since the app's targetSdk was already 35 before this gate, not lower.

Fixed: wording narrowed to "a latent defect surfaced during this gate's verification, not necessarily created by the 35→36 move itself."

Minor · fixed

No regression test guarded the geometry itself

Nothing protected against this exact class of overlap recurring in the future.

Fixed: a new test using FakeViewPadding, checking the banner never sits above the inset and never overlaps ScanTopBar.

08What's still open — stated plainly, not hidden

  • Google Play publication was not performed and is not claimed — this gate closes only the targetSdk 36 requirement and Android 16 compatibility, verified on real hardware. Play Console acceptance/publication is a separate, unstarted task.
  • One data-safety incident, disclosed plainly: three consecutive back-presses during live testing accidentally exited to the operator's real personal home screen (showing personal photos). The app was immediately relaunched, no personal content was further viewed, no data was modified.
  • The operator's real personal data (a shoulder injury under Profile → Injuries) was used only to verify keyboard/IME behavior — the field was opened but not edited; unchanged state was confirmed via a second uiautomator dump.
  • S8 cannot verify Android 16 — confirmed live (adb shell getprop): a hardware ceiling of Android 9/SDK 28. All API 36 verification was performed on S23.
