Why so little

Tokens already match the reference — there's nothing left to reconcile

The danger color t.danger = 0xFFFF5A5A is already byte-identical to the reference's error color; the glass panel and chip recipes are the same ones already confirmed byte-matched in earlier gates. SafetyRefusalCard/EligibilityNotice already draw from these tokens. The only element with no token analogue and no data risk is the heading — so that's the one change that shipped.

EligibilityNotice is used in 8 places app-wide (confirmed via grep) — 5 screens outside onboarding plus its own "urgent" chest-pain logic. Touching it inside an onboarding gate would be an app-wide functional risk, not a single-screen visual one — so it's explicitly excluded, along with SafetyRefusalCard, BodyZoneMap, every chip widget, and the embedded step_health.dart.
