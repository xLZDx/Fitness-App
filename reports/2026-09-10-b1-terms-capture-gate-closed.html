What was found and fixed during the gate

This gate’s own tests found genuine defects on their first run, not on review. Recorded here rather than smoothed over.

  • Step 8 — a timestamp grammar that wasn’t one. Python’s strptime accepts a single-digit day and matches literal T/Z case-insensitively, so "2026091T142233Z" and "20260910t142233z" both parsed as valid despite being malformed. Fixed by requiring the canonical re-rendering to match the input string exactly.
  • Steps 12–13 — three exception classes mistaken for one hierarchy. AuthorityError, CaptureError and CandidateManifestError are unrelated classes from three different modules. Three tests wrote pytest.raises(CaptureError) where the real code path raises AuthorityError — they caught nothing and would have passed silently on a broken guard. Fixed by importing the real classes and correcting the three tests.
  • Step 14 — an overlapping guard that masked its own mutant. The original orphan-file test used a filename that also failed a separate name-parse check, so disabling the is_dir() guard specifically changed nothing observable — the mutant survived, correctly, and that survival is recorded rather than erased. Fixed by adding a fixture (a file whose name genuinely parses as a valid capture identity) that isolates the one guard the first fixture couldn’t.

Guards recorded as unproven, not silently claimed

Three guards across this gate cannot currently be distinguished from their own absence by any fixture — not because they are dead code, but because an earlier check in the same function already guarantees the condition they test. Each is documented in-source rather than deleted or claimed as mutation-proven.

register_from_file (step 11) — M10

Assigning resolve_source_id(...)’s return value rather than reusing the input is defence in depth: the function compares byte-for-byte, so on every path that doesn’t raise, its return value is provably identical to the input. No fixture can currently make the two diverge.

terms_verify.py (step 14) — two guards

The capture_id_matches_timestamp re-check is implied by two earlier checks in the same function (the sidecar’s own internal consistency check, then the cross-bound directory check) — both already run first. The duplicate-identity check in verify_all is unreachable for the current three mutually-prefix-free B1 target sources, kept for a future target set that isn’t.
