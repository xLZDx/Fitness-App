Gate G3 is closed. The rights contract in scripts/equipment_identity/rights.py gained three things it did not have: evidence bound to specific bytes, a subject the permission question is about, and one identifier grammar that all three layers understand identically.

No source was promoted. All 17 remain UNREVIEWED. This gate makes a legal decision expressible, auditable and hard to fake — it does not make one, and no mechanism here could.

What was wrong

The decision was not bound to what it rested on

rights.py validated only the shape of termsSnapshotSha256, and only when the field happened to be present. There was no snapshot file, no path to one, and nothing ever opened anything. So termsCaptured: true with any 64-hex string and no file anywhere passed — and REVIEWED then unlocked every privileged use.

The schema already claimed otherwise in one place ("required in practice by rights.py") while hedging the opposite way in another ("ideally with termsSnapshotSha256"). The documentation was not merely ahead of the code; its two halves contradicted each other.

A grant had no population and no subject

Permissions were granted per sourceId, wholesale. The five eligibility functions took only the source record, so there was no object identity anywhere in the API. "Reviewed for this part of the catalogue" was not an expressible statement, and a review covering part of a source was recorded as a grant over all of it. core/equipment_identity/p1/wger_staging/wger_license_raw.json is exactly that case: individual wger records carry no resolved reference into wger's own licence list.

The bypass was the dispatch table, not the function names

ELIGIBILITY_BY_USE was a module-level dict whose values were those same five callables. Making them private would have left ELIGIBILITY_BY_USE["DISPLAY"](record) working exactly as before, with no subject at all.

The first remedy I proposed for it — a grep for public helper names — would have reported success while the hole stayed open. I had read lines 280–330 and stopped one line short of the table.

Two rules: a capture is bound to real bytes in every state, and a scope belongs to exactly one state. Enforced identically in rights.py, in the JSON Schema (draft-07 if/then) and in the .strict() Zod mirror. The mirror was kept strict: relaxing .strict() would have silenced the mismatch rather than fixing it.

Capture-before-review is preserved deliberately

An intermediate draft of this amendment forbade a snapshot on an UNREVIEWED source, fusing capture and legal review into one atomic act. That is a regression of an approved semantic: P0_G3_RIGHTS_GOVERNANCE.md states outright that termsCaptured is factual metadata, independent of whether anyone has read it. Recorded separately because the reasoning that produced it — "let's tidy the matrix into three rows instead of four" — looks like simplification.

Decisions that were not mine

BLOCKED is bound to bytes too, over my stated objection that requiring evidence for bad news makes bad news the costlier thing to report. GPT-PM's position: BLOCKED is a human legal conclusion, not an absence, and a source whose terms could not be reached at all is UNREVIEWED — already fail-closed, and already the honest word for "nobody could look". Recorded as the reviewer's call over the implementer's, not as agreement.

BLOCKED forbids a scope, because a scope there could only mean a partial block, which this contract cannot express. Named as a limitation rather than left to be inferred from behaviour.

WHOLE_SOURCE trusts upstream provenance, and now says so. The registry has no population oracle: it cannot know that a given key does not belong to a source. An earlier draft claimed an unknown key would be denied; nothing could have implemented that, so the claim was deleted rather than left as decoration. The namespace, unlike the key, is knowable — the source declares it — which is why namespace matching is enforced for both scope kinds and key matching only under SUBSET.

One grammar, three engines

I wrote in the plan that a byte-identical ^\S(?:.*\S)?$ across Python, JSON Schema and Zod gives "one rule rather than three approximations of one". That is false, and here is the measurement taken before replanning:

InputPython reNode RegExp
U+0085rejectsaccepts
U+FEFFacceptsrejects
"abc\n"acceptsrejects

The first two rows are GPT-PM's counterexamples, confirmed. The third is mine and it is broader: Python's $ matches before a trailing newline, so every shared $-anchored pattern diverges there — including the ASCII grammar I reached for immediately after dropping \S. And since the jsonschema package compiles pattern with Python's own re, two layers would have agreed with each other while the third silently disagreed.

^[A-Za-z0-9](?:[A-Za-z0-9._:-]*[A-Za-z0-9])?(?![\s\S])

An enumerated ASCII alphabet instead of \S, so no engine's opinion about what counts as whitespace participates in the decision at all. (?![\s\S]) instead of $, because [\s\S] is a set unioned with its own complement — "any character" in both engines whatever either calls whitespace. The grammar is deliberately narrower than Unicode: a source whose keys are inexpressible in it gets no scope, which is a refusal you can see rather than a silent transliteration into something that no longer identifies anything.

The evidence

224 Python tests · 313 jest tests across 17 suites · 10 of 10 mutations proven

The whole pre-existing suite stayed green, and no expected result in it was changed.

The load-bearing part is not the assertions but the mutations. A test that a hash must match passes just as well against a validator that never opens the file; a scope test passes against a parameter nothing reads. So each of the ten mutations had to turn its own test red, and each revert had to turn it green again.

A red test is not enough to score a kill, and this harness proved that on itself. Mutation (i) removed the inner review-state guard, pytest went red, and the harness reported KILLED — while the mutated code was in fact raising KeyError, because the fixture was invalid in a second dimension. Nothing had been demonstrated about the guard. Every mutation now declares its observable and both of its values in advance: a separate probe prints one token for one behaviour, the baseline token is verified on unmutated source, and the mutant must print the declared token. Any other token — including an exception raised elsewhere — is not a kill, however red the suite goes. A pre-flight separately rejects a pair of expectations that happen to be equal, since such a check could never fail. Mutation (i)'s answer now moves False → True.

Three mutations carried a control that had to STAY green — which is the answer to the finding that got the previous plan refused:

  • Dropping the lexical .. ban kills its test while resolved containment's test holds — and vice versa. The fixtures are chosen so that sub/../terms.txt resolves inside the root (only the lexical guard refuses it) and an in-root junction to a file outside contains no .. at all (only containment refuses it). Before this, both fixtures were caught by both guards, so deleting one was masked by the other: the mutant survived having proven nothing.
  • Dropping the namespace comparison kills the same-key/different-namespace test while the different-key test holds. That is what makes the namespace separately load-bearing rather than incidentally covered by the key comparison.

The harness pre-flights every anchor (exactly one occurrence) and every node-id (pytest exit code 5 is not a pass). It earned its keep immediately: it caught a stale indentation in one anchor that would otherwise have applied no mutation and reported a survivor.

The containment guard's escape fixture was created with a directory junction (mklink /J): os.symlink fails on this machine with WinError 1314, privilege not held. The junction is what made that guard provable locally rather than deferred to a Linux container. Where neither mechanism exists the test SKIPs — and that skip is explicitly not evidence.

The closure review found four defects

Run against the finished gate rather than the plan. None was a style note; three of the four were places where a check described more than it did.

1. A path could name bytes that are in no checkout

terms.txt:legal-review is innocent by every rule the validator had: not absolute, no drive, no .., inside the declared directory, resolving to a regular file. On NTFS it addresses a separate alternate data stream. Git stores no such stream and .gitattributes -text cannot preserve one, so a legal decision could be bound to a digest of bytes existing on exactly one machine.

The escape was confirmed by measurement, not by argument: the stream was written and validation accepted it, before any fix. The remedy is a portable-path grammar shared by all three layers, refusing the colon on every platform — including those with no such concept, because a path meaning one file on Linux and a hidden stream on Windows is not the portable reference this field claims to be, and a rule that changes by platform is not a contract. It is ordered after the absolute-path and .. checks deliberately: each of the three keeps a fixture only it rejects, so none masks another's mutant.

2. A mutant died of the wrong exception, and the harness called it a kill

Covered above, under the evidence. GPT-PM's required change, verbatim: "Have the mutation harness assert that semantic flip explicitly, so an unrelated exception cannot count as a kill" — "Baseline must return False; after mutation (i), the predicate must return True, not merely make pytest non-zero".

One expectation is deliberately not an acceptance, and is worth stating plainly rather than dressing up: mutation (b) weakens has_path and has_hash to or, and no fixture then gets accepted, because the next lines read both fields unconditionally. Its declared flip is RightsValidationError → KeyError — the guard's real job being to turn half the evidence into a stated refusal before the code walks into the missing half. Declaring that exact token is what keeps it a proof: an unrelated exception still fails it.

3. Parity covered one field out of three

The three-engine claim was earned for the scope identifier and quietly extended in prose to the two fields carrying the actual legal evidence. Measured: Python rejected a whitespace-only termsSnapshotPath that the JSON Schema and Zod both accepted, and all three still spelled the sha256 rule with $, which Python matches before a trailing newline and JavaScript does not.

The shared case file gained snapshot_path_valid/invalid (5 + 21) and sha256_valid/invalid (3 + 8), and all four sections now run through Python's re, the Draft-07 schema and Zod. sub/../terms.txt stays deliberately legal to all three grammars: a schema cannot resolve a path, so claiming containment there would be a promise this layer has no way to keep, and rights.py's separate guard stays independently provable.

4. The structural check did not walk functions

It enumerated module-level assignments, so a new public def eligible_for_export(record) — a permission route reachable by name, in no container at all — would have left it green. It now walks function definitions and applies one rule with no allowlist: any module-level function reading a name in PERMISSION_FIELDS must require a subject. The absence of a list is the point; "these helpers are exempt" is exactly the bookkeeping that goes stale, so _commercially_allowed takes and demands a subject it never reads rather than being written down somewhere as a special case.

The verification round found two more — both in the remediation itself

Neither was a regression in the approved work. Both were places where the remediation's own evidence claimed more than it demonstrated. One was settled by measurement, because reading did not settle it.

5. The new grammar swallowed the absolute-path guard, and the source went on certifying it as independently provable

_resolve_terms_snapshot refused absolute, drive and UNC paths in a dedicated check, then applied the grammar, with a comment stating each ordered check kept a fixture only IT rejected. That comment was false the moment the grammar landed: everything that makes a path absolute — a leading /, a :, a \ — is outside the grammar's alphabet.

Measured rather than argued. An exhaustive search over 11,110 strings built from the grammar's own alphabet plus :, \, / and space, up to length four, found no string the grammar accepts and the absolute check would reject. The guard was unkillable by construction: deleting it left every test green — precisely the masked-guard defect the earlier remediation claimed to have eliminated.

The guard is removed, not kept as defence in depth. A check indistinguishable from its own absence is not depth; it is a claim, and this contract has now been bitten three times by a check that described more than it did. The class is still refused — by the grammar, with /etc/passwd, C:/Windows/win.ini, C:\Windows\win.ini, UNC syntax and /a in the shared invalid-case list proving it in all three engines, and with mutation (j) proving the grammar itself is load-bearing. The three original tests still pass, unchanged in what they assert. The subsumption is now itself a test that re-runs that exhaustive search: if a distinguishing string ever appears, the guard becomes provable, and the failing test is the instruction to bring it back.

Two lexical checks remain, and each keeps a fixture only it rejects: the grammar (mutation j) and the .. ban (mutation c, sub/../terms.txt — well-shaped, resolves inside the root).

6. The AST check found permission readers, not permission routes

It flagged a module-level function containing a string literal from PERMISSION_FIELDS. The bypass it was written to catch contains no such literal:

def eligible_for_export(record):
    return eligible_for(record, "DISPLAY", SubjectRef("test", "item1"))

That wrapper hands out a permission while its own caller names no object, and the check never looked at it — while the remediation cited this exact signature as the class it caught.

The rule now computes reachability to a fixed point over a graph of module-level names. The first attempt built that graph from calls and proved the point again by missing the real front door: eligible_for dispatches through _ELIGIBILITY_BY_USE[use](record, subject), a call on a Subscript, so it had no edge to any sink and a wrapper around it stayed invisible for a second, unrelated reason. The graph is therefore built from name references, with module-level assignments as relay nodes — which also re-covers by construction the older rule that no public container may publish a permission callable.

Demonstrated on the real module, not inferred from a fixture passing. The wrapper is appended to rights.py's actual source and the rule is asked about that, in all three forms the review named: through the public eligible_for, through a private _eligible_for_* predicate, and through the dispatch table directly. Each is flagged; the same wrapper with a subject parameter is not; a wrapper around the wrapper is flagged transitively; and a function touching neither a permission field nor a permission route is not, so the rule is not simply "every function".

The next round found the same bug in a third form

7. An assignment is a permission route too, and the rule excluded assignments by construction

The reference graph made module-level assignments relay nodes — and then said in as many words that they are never offenders themselves. So this stayed invisible:

eligible_for_export = lambda record: eligible_for(record, "DISPLAY", SubjectRef("test", "item1"))

The assignment references eligible_for, enters the reachable set, and is then dropped from the offender set for not being a FunctionDef. The neighbouring public-container check does not catch it either: that one inspects dict/list/tuple/set values, and this is a callable directly. Reproduced against the implemented helper before fixing: the name was not even in the reachable set, and offenders was empty.

Three rounds, three forms of one mistake — literal, then call edge, then node kind — and each time the check was right about the form in front of it and wrong about the class. The rule now judges a reaching assignment on what it exposes rather than on the syntax that produced it: any lambda in the value (including one buried in a container) must take a subject; a bare alias inherits the aliased function's parameters; a pure container with no lambda relays only, which is what keeps _ELIGIBILITY_BY_USE non-offending; and anything else reaching a sink counts as an offender, because an expression whose signature cannot be read cannot be shown to demand a subject. Conservative deliberately: a false offender costs one argument in a review, a false clean is a permission handed out about nothing.

Regressions, all against the real rights.py source: the lambda form is flagged; the same lambda taking subject is not; a lambda buried in a container is flagged; public_eligible_for = eligible_for is not flagged, because the alias inherits a signature that already demands a subject, and a rule flagging it would be "no aliases" rather than "no subjectless routes"; and _ELIGIBILITY_BY_USE is asserted to stay reachable-but-clean, so the rule cannot drift into "no containers". A functools.partial with the subject pre-bound covers the unknown-expression branch.

Three more — and that is where patching forms stopped

A fourth round on the same check. All three confirmed against the real source before being accepted.

  • 8. A parameter named subject is not a subject requirement. The check read the name and never the signature, so lambda record, subject=SubjectRef("test", "item1"): ... was clean while eligible_for_export(record) still handed out a permission. Same for a def with a default, and for a keyword-only parameter with one.
  • 9. Exempting every lambda-free container recreated the original bypass. EXPORTS = {"DISPLAY": functools.partial(eligible_for, subject=SubjectRef(...))} references eligible_for, so it reaches the sink — and was declared clean for being a dict with no lambda in it. That is materially _ELIGIBILITY_BY_USE's own class of route, with partial in place of a predicate.
  • 10. A class was not a node in the graph at all. class EligibleExport: def __call__(self, record): return eligible_for(...) plus eligible_for_export = EligibleExport() created no edge, never entered the reachable set, and left nothing for the conservative unknown-expression branch to judge.

Four rounds, one mistake, now named as one thing. Literal → call edge → node kind → signature/container/class. Each version was right about the form in front of it and wrong about the class, and each fix was written in terms of syntax. So the rule is not written that way any more: it asks one question of every reachable module-level name — what callable does this expose, and can that callable be invoked without a mandatory subject? A lambda is judged on its own args; an alias inherits the aliased function's; a container is judged recursively on what it holds; a class on its methods that touch a permission; an instantiation on that class's __call__; and anything whose signature cannot be read is an offender, because "cannot be shown to demand a subject" and "does not demand one" have to be treated alike here.

Nine regressions were added, all appended to rights.py's real source, each with the control that differs only in making the subject mandatory — plus EXPORTS = {"DISPLAY": eligible_for} and public_eligible_for = eligible_for as the cases that must STAY clean, or the rule would have become "no containers, no aliases".

And the claim is now bounded rather than growing. The helper states what a static read of one module's text cannot see: dynamic access via getattr, a route built at runtime or by a signature-rewriting decorator, and anything outside this module. The honest claim is narrow — no permission route is reachable by name from this module's own source without a mandatory subject — which is what every bypass found across four rounds actually was, and is not the same as "no bypass exists". Writing that boundary down is what stops this from becoming round eleven.

Three more — the rule enumerated syntax in three places at once

  • 11. The fail-closed fallback failed open. The helper's own text said an unreadable callable surface must count as an offender; the code's last line returned False. So export = partial(eligible_for, subject=...) if FLAG else eligible_for walked straight through it, and export(record) handed out a permission.
  • 12. Sinks were seeded from defs only. A route that reads a permission without calling anything never entered the graph: export = lambda record: record["rights"]["displayAllowed"], and the same as a class __call__. The previous class regression only covered a class that calls eligible_for, which is why it did not expose this.
  • 13. The binding collector knew four statement types. (export := lambda record: ...) binds a module global; for export in [...] binds one; with ... as export binds one. None was collected — while the claim said "reachable by name from this module's own source".

The fix in all three places is the same fix: stop enumerating syntax. Bindings are now found by locating module-scope stores rather than by listing statement types — which is why a walrus, a for target, a with ... as, and a name bound inside if TYPE_CHECKING: or a try/except pair are covered by one change instead of five cases, and an unidentifiable binding value is an offender rather than a silent pass. Sinks are seeded from any node kind that intrinsically reads a permission — a function, a class method, a lambda, an instance of such a class — but deliberately not from a bare tuple of those strings, or PERMISSION_FIELDS itself would be a sink. And the classifier's fallback now fails closed for real: an expression it does not model is an offender whenever it can pull a permission in at all, with IfExp, BoolOp and Starred given real branch analysis so the rule is not simply "any expression I have not seen".

Regressions were again appended to the real source, each with a control differing only in the one thing that should matter: the conditional with a pre-bound partial (and eligible_for if FLAG else eligible_for staying clean); the direct-literal lambda and the direct-literal callable class (and both with a mandatory subject); the walrus; the for binding; and a with ... as whose value cannot be identified. That last fixture also caught an over-flag in the first attempt — _ = eligible_for inside the with body was treated as an unknown binding rather than the alias it is — which is why binding discovery now walks nested statements and not only the top-level one.

A sixth round — and the conclusion that a static lint was the wrong sole instrument

  • 14. One binding remembered per name. setdefault kept the first, so export = eligible_for followed by export = lambda record: eligible_for(...) read clean while Python keeps the second. Bindings are now a list per name, and the effective set is everything at or after the last unconditional binding: an unconditional rebind really does overwrite what came before (so the reverse order stays clean, and has a control saying so), while a conditional rebind after it might still be live and is judged.
  • 15. The scope walker dropped nested definitions. if ENABLE_EXPORT: def eligible_for_export(...) binds a module global, and the walker refused to enqueue any child FunctionDef at all. Also missed: a walrus in a function default or a comprehension, both of which execute in the enclosing scope, and match captures, which live on pattern nodes rather than on Name. Binding discovery is now an explicit descent over module-scope statements carrying a conditional flag: a nested def/class is registered without descending into its body, and the expressions around it — decorators, defaults, bases — are visited because they run in the enclosing scope.
  • 16. Sink seeding still enumerated callable shapes, so operator.itemgetter("displayAllowed") and a class-level export = lambda record: record["rights"]["displayAllowed"] never entered the graph and never reached the fail-closed judging stage. Seeding is now inverted: a value containing a permission literal seeds unless it is provably passive data — a constant, or a container/frozenset(...) of constants. That single exception exists for one shape, PERMISSION_FIELDS, and has its own control.

The conclusion, which is the part worth keeping. Six rounds, sixteen findings, every one a real form the static check could not see. The reason is structural: a hand-written AST walk has to model Python's binding and scope semantics, and getting that exactly right is not something a test helper achieves. So the lint is no longer the only instrument.

test_no_live_callable_answers_a_permission_without_a_subject models nothing. It reads vars(rights) — Python's own answer about what the module bound — and asks every callable the same question twice, about two records differing only in their permission booleans. A callable whose boolean answer changes has read a permission and answered from a record alone, with no subject. That criterion needs no scope rules, so a conditional def, a walrus, a match capture, a class attribute and an itemgetter are all equally visible to it. _reviewed and _not_discovery_only return the same value for both records, because they report review state and priority rather than a permission — and a control asserts exactly that, so the criterion is not "any bool-returning callable". Its teeth are proven rather than assumed: the test binds the original bypass onto the module, confirms it is caught, and removes it in a finally.

The static lint stays as defence in depth over the source, with its limits written into its own docstring; the actual guarantee is the runtime one — _require_subject, called by eligible_for and separately by every per-use predicate.

A seventh round corrected a claim — and that matters more than the two code fixes

17. _require_subject does not guarantee the CALLER supplied a subject

The closure argument written one round earlier — "the runtime enforcement is the actual guarantee, the lint is defence in depth over it" — is wrong, and the review proved it with the very bypass these rounds exist for:

def eligible_for_export(record):
    return eligible_for(record, "DISPLAY", SubjectRef("test", "item1"))

That wrapper constructs a perfectly valid SubjectRef internally. eligible_for and every private predicate pass _require_subject happily, while the external caller named no object at all. So _require_subject guarantees the predicates receive a valid SubjectRef; it cannot establish who supplied it. "The caller must name the object" is a separate, public-surface invariant, carried by the structural and runtime instruments — so a miss in either is a real miss, and invoking the runtime guard to excuse one was exactly the claim-wider-than-the-check this gate keeps finding.

18. Two extreme records cannot detect permission dependence

The probe compared all-permissions-true against all-permissions-false, and two points cannot characterise a boolean function of six inputs:

eligible_for_export = lambda record: (
    record["rights"]["displayAllowed"] != record["rights"]["trainingAllowed"]
)

answers False on both and True on any mixed record. The probe now enumerates the whole space — six fields, 64 records, everything else held permissive and equal — and flags a callable whose successful boolean answer varies across it. The XOR case is a regression, so the two-point version cannot return unnoticed.

19. Neither instrument saw a class attribute bound under class-body control flow

class EligibleExport:
    if ENABLE_EXPORT:
        export = lambda record: record["rights"]["displayAllowed"]

The static side read only cls.body, saw the If, and stopped, so the class never seeded. The runtime side iterated vars(rights) and probed the class object, which constructs it rather than calling .export. Both were fixed: class_members now descends through class-body control flow without entering nested def/class bodies, and the runtime walk descends one level into classes the module defines itself. The runtime half is proven independently — the test binds such a class onto the live module and requires the offender list to be exactly ["EligibleExport.export"].

An eighth round: the correction accepted, two more found — both in the runtime instrument

The _require_subject correction, the XOR fix and the class-body if case were all accepted. Two remained.

20. A grant can be a boolean or an exception, and the probe threw the exceptions away

def eligible_for_export(record):
    if record["rights"]["displayAllowed"]:
        return True
    raise RightsValidationError("not allowed")

The caller learns the permission either way — True is the grant, the exception is the denial. But the probe collected only successful boolean answers, so its set was {True} across all 64 records and it reported clean. It now records an outcome per record — a boolean value, a non-boolean value's type, or the exception class — and flags a callable when a boolean appears at all and the outcome varies. A callable that never produces a boolean (wrong arity, say) is still not a route. Three controls keep that from becoming "anything that ever raises": a constant value, an always-raising callable, and one reading legalReviewState rather than a permission.

21. A match in a class body and a classmethod descriptor defeated the two halves separately

class EligibleExport:
    match 1:
        case 1:
            @classmethod
            def export(cls, record):
                return record["rights"]["displayAllowed"]

Statically, the class-body descent walked body/orelse/finalbody/handlers, and a match keeps its branches under cases — so the method was never reached. At runtime, vars(cls)["export"] is a classmethod descriptor, which is not itself callable, while EligibleExport.export is: reading the raw stored value skipped exactly the descriptor forms. Fixed on both sides, and generically rather than by extending two lists: the static descent follows every child that is a statement or has a body, and the runtime walk reads getattr(cls, name) instead of the raw vars entry. The premise is asserted in the test itself — callable(vars(C)["export"]) is False while callable(C.export) is True — so the fix cannot be mistaken for decoration.
