Gate 1 · commit 792def6The one action that avoided data loss was the one the router blocked

This was found while working N-05 and is not an N-05 control. It is a data-loss defect that the abuse review happened to walk into.

FirebaseAuthRepository.signInWithGoogle calls linkWithCredential on a guest, which keeps the same uid and therefore every document under users/{uid} — profile, injuries, workout history, schedule. That was written deliberately and it works. Nothing could reach it.

Three facts, measured

signInWithGoogle has exactly one production call site, and it is on /login. resolveRedirect bounced every signed-in user off /login, and isSignedIn is user != null — true for a guest. The profile screen offered Settings and Sign out, and Sign out fires with no confirmation.

So a guest's only self-service exit from an anonymous session was Sign out, which mints a fresh uid next time. The repository already states the consequence in its own words: the old account is “not lost so much as unreachable forever, because an anonymous account has no credential to sign back into.”

Both halves shipped, because either alone is nothing — an open door nobody walks through, or a tile that redirects away on tap. resolveRedirect now takes isAnonymous, and the profile screen has a guest-only tile that pushes /login.

The derivation is now testable, and that mattered

resolveRedirect can be perfectly correct about guests while the router never tells it who the guest is, and a pure test of the decision cannot see that. The first attempt at covering it mounted the real router, which meant building /home — the whole app shell — inside a unit test, and it hung. The redirect closure became redirectFor(…) instead: one seam, five cases, no widget tree.

The promise was corrected before it shipped

The new tile's subtitle first read “Everything you have logged stays where it is.” That is conditionally false. On credential-already-in-use the code falls back to signInWithCredential and, at its own comment, “this device's guest data stays orphaned but intact” — the reinstall and second-device case, which is common. Since this tile is about to be the remedy offered to a user who has just been refused something, telling them their data is safe in exactly the case where it is not would be worse than not offering it. The string now names the exception, and a test asserts it.

Gate 2 · commit a467ff2A deliberate refusal was rendering as a broken link

The backend already writes a sentence for a reader: “You have reached today's limit for this action. It resets tomorrow.” Here is where it died.

StepWhat happened to the refusal
1enforceDailyQuota throws resource-exhausted with its message
2ClipUrlResolver.fetch caught everything alike, counted it, returned {}
3resolve mapped the empty map to null
4the player stored the unresolved sentinel
5the classifier called that linkUnavailable
6the screen said “The clip link is unavailable”, detail line suppressed

There is no second channel: firestore.rules closes users/{uid}/usage/{day} outright, with a comment explaining that no client reads it. The callable's error was the only signal the app had, and it was being discarded.

Why this is live, not hypothetical

ANONYMOUS_QUOTA_DIVISOR = 8 ships today, so guests are already refused at 50 clip links a day — and every one of those refusals was indistinguishable on the phone from a signing outage, a missing object, or a missing IAM grant the backend names as a real failure mode.

This repository has paid for the same class of mistake once already: a 2026-08-08 device report where the player blamed the network on a 1 Gb connection, “actively misleading — it sent the reader to look at their router while the real fault was somewhere else entirely.” The rule written that day was name only what is known.

ClipQuotaExhausted is a domain type, so the classifier stays free of Firebase and testable with no plugins registered. asQuotaRefusal matches the gRPC status code, never message text. swallowOrThrow is the whole single-clip failure policy, extracted because the catch it came from is reachable only through a real backend call — a mutation inside it would have survived unnoticed.

Left open on purpose

The offline prefetch still swallows. It chunks at sixty and accumulates across chunks, so throwing out of one chunk would discard what earlier chunks already signed and turn a partial prefetch into a total failure. Telling that user properly needs a result type that can say “38 of 84, limit reached”, which the method cannot express. Recorded rather than half-fixed.

Gate 3 · commit 15034adA tripwire that had never been fired

The team-feed guard was written earlier and never run. It runs now. It does not test Teams; it tests one conditional: wired to a real repository ⇒ firestore.rules must authorise it.

That conditional is vacuous in this repository, because nothing is wired — and a guard that is vacuous against real inputs is the exact defect this programme keeps hitting. So it is a pure function exercised against three trees: the real one, a synthetic wired tree with no rule (must fail), and a synthetic wired tree with a rule (must pass). Two controls sit beside it: the provider still defaults to the mock, and the rules file still matches no team collection.

The mutation. A line naming teamFeedRepositoryProvider.overrideWithValue was appended to lib/main.dart. The tripwire fired with its full refusal message and the dormancy control failed alongside it. Restored byte-for-byte. N07 = KEEP: not wired, not deleted, now guarded.

Gate 4 · commit 8c89d88The corpus recorded as unrecoverable was sitting on disk

The dataset registry said the scanner's training corpus “cannot be addressed, hashed or rebuilt from here.” The first half of that note — the pipeline is not a git repository — is true and is now independently verified. The second half was wrong.

Measured 2026-08-18

1,741 files in dataset/, manifest 411189bc…, untouched since v1 was built. Six artefacts hashed, including a complete self-contained trainer with its hyperparameters and seed as literals. And the shipped equipment_v1.tflite is byte-identical to the pipeline's own build output.

UNRESOLVED means unversioned, not missing — and the distinction decides what the work is. A reader of the old note plans a re-crawl. The truth is that git init plus a recorded hash closes v1.

A pin plus a probe, not a directory read: a registry field computed from a path on one machine would differ everywhere else, and CI would fail on a difference that means nothing. On a machine without the directory the probe reports NOT_PRESENT_ON_THIS_MACHINE and says explicitly that absence of the directory is not evidence the pipeline is gone.

Two of the six recovery items are the interesting ones. The only v2 run log on disk describes a 29-class run while the registered v2 artefact carries 37 labels — recorded as MISSING_AND_CONTRADICTED rather than missing, deliberately, because “missing” invites somebody to supply the log they have. And v2's label set was generated from a third, unversioned copy of this project at an unrecorded revision.

Of the 19 tests, three need the real bytes and skip with a stated reason where the pipeline is absent. A skip that names why is evidence; a test quietly asserting True is not.

Gate 5 · commit 38fdd7cA test that guarded a contract the document had stopped having

Two suite failures, both introduced by this programme's own rewrite of the clinical handoff, and both already committed. Found by running the full Flutter suite rather than the touched files.

The shape of the mistake

The test asserted nine hand-typed field names from the pre-worklist result format. Section 7 replaced that format with a spreadsheet, and the test went on passing for three commits afterwards — guarding a contract the document no longer had. It only failed once the rewrite removed the last of the old names.

The test was inspected first, and it was the stale half. The field list is now read from the submission file that is actually issued and from the constants the validator actually enforces. A hand-copied list cannot notice divergence; a derived one fails on it. The second failure was simpler: section 8 is now a block meant to be copied into a submission, so it writes 1887, not 1,887. Forcing a thousands separator into a machine-readable block to satisfy a test is the wrong direction, so the comparison strips separators — what must not drift is the number, not its spelling.

Two mutations killed. A third — un-backticking AMEND in the dispositions table — survived correctly, because the document names that value elsewhere and the guarded property was still true. Recorded, because a survivor that is not a defect is worth distinguishing from one that is.

Gate 7 · commit efbcac7N-05: the framing was the thing that was wrong

Two review rounds, run independently and then adversarially, converged: per-account uniqueness is not the binding constraint. The full disposition, with a file:line on every claim, is at core/review/N05_DISPOSITION.md.

The two facts that decide it

The signed URL is a caller-agnostic bearer token. The signature covers bucket, object, expiry and signing identity — “Nothing about the caller enters it.” One mint serves unlimited redemptions for twenty minutes, so the quota meters mints, not bytes, and no per-account control touches redemption at all.

There is no lifetime cap. The counter is keyed on the date, so it resets every UTC midnight forever. One verified account on the undivided quota sweeps the 2,539-object library in three days, quietly, rotating nothing. Requiring a real identity makes the per-identity attack slower — and makes it look fixed.

All three proposed controls broke, and the reasons are not aesthetic

ControlVerdictWhy
P1 — cumulative distinct ceiling rejected Irreconcilable with charge-before-sign plus refund. Add at charge time and a stale catalogue path becomes a permanent lifetime debit for a clip never received; add after signing and the atomicity the transaction exists to provide is gone. Firestore cannot condition on post-arrayUnion cardinality, so there is no third placement. Separately: against a harvester, a distinct set and a plain counter are numerically identical — it buys fairness to re-watchers, not security.
P2 — identity above a threshold half-cleared Was blocked on client work; that block is cleared by Gate 1. What remains is that its promise is conditionally false on credential-already-in-use, so complying with the refusal can cost the user their history.
P3 — project-wide ceiling rejected A Sybil-powered denial of service on paying customers: the attacker's cost to trip a shared ceiling equals their cost to harvest, so seventeen free accounts can turn every subscriber's video off until midnight at a time they choose. True even if sized correctly — and it cannot be sized, because the only telemetry that ships is Crashlytics and the real population is “5–10 testnet users”. The salvageable half is the alarm, not the brake.

The exposure is not the money. Full-library extraction costs SPTR $0.077–$0.31. The two real exposures are the licence condition — which caps no volume, only permanence — and amplification, which none of P1/P2/P3 addresses.

Device fingerprinting and every variant stay refused, on three independent grounds: unavailable in the installed SDK, contradicted by published policy because every such control must survive account deletion to work, and already refused on this repository's own record for better reasons than effectiveness.

Gate 8 · commit 1d1cc37The shared MLOps primitive is a check, not a schema

The brief asked for a shared evaluation-report primitive if it has at least two real consumers. It does — and the thing worth sharing turned out not to be the format.

One consumer's report is generated JSON. The other's is prose, and I checked before writing it off: a held-out 15% stratified split, n=261, a per-class table, and a post-mortem of a train/val overlap the pipeline caught — the first run reported 0.774 and was wrong. Those numbers came from a pipeline that is not in this repository, so nothing here can re-emit them in any format. A schema every producer emits would have had exactly one producer.

What both consumers actually share

The model registry states measured numbers inline and names the report they came from, and nothing checked the two agree. A registry that quotes a figure its own cited source does not contain is worse than one that quotes nothing, because the citation is what makes it look verified.

Current state: 20 quoted metrics, 0 drifted, 13 matched, 7 not locatable — each of the seven named. NOT_LOCATABLE is a distinct verdict from MATCHES on purpose, and a test asserts the matched count, because “no drift” over zero readable claims is true and worthless. The locator maps spellings, never meanings: top_1 and top-1 are the same measurement, top_1 and accuracy are not.

One citation was wrong and is now right: the scanner's real-world numbers come from a separate measurement document, not the model README, so an evaluation may name its own source. No number moved.

A mutation survived, and the test was at fault

Widening the proximity window from 120 characters to 100,000 left the whole suite green, because the proximity case built its gap as WINDOW * 3 — a fixture that scales with the thing under test and therefore passes for every value of it. Same defect class this programme has hit before: a fixture that guarantees its own outcome. The gap is now a literal and a second case bounds the constant; both fail under the mutation.

PROMOTION_REVIEW_RECORD was not built. It has zero real consumers: no model has ever been promoted, v1 is champion by default rather than by evaluation, and v2 is deliberately not a challenger. A record type for an event that has never occurred would be a schema written from imagination.

What a person still has to decide

Nothing in this repository can make an anonymous uid cost something. Three levers exist and all three are outside it.

DecisionStateWhat it turns on
App Check enforcement measurable, unmeasured Every callable now reports attestation, so the production attested share can be measured — it has not been. Enforcing before measuring locks out every unattested real install. A deployment decision.
Anonymous sign-in policy product Whether a guest keeps unrestricted video at all. Anonymous sign-in is a first-class login button here, and the repository has called this the operator's since the divisor was introduced.
Platform cost controls unknown Whether a GCP budget alert exists is not knowable from this repository. Whether a global brake is ever acceptable is answered above: not at any number.
Anonymous callers can buy open Checkout accepts anonymous callers for real money including lifetime, while the free trial rejects them. Quota never reads tier, so that subscriber runs at 1/8 — and since the prefetch is premium-gated, the anonymous batch ceiling exists only for anonymous users who have paid. Three costed options are written out; none was chosen here, because each is the kind of decision this repository has already assigned to the operator.
