Confirmed and fixed

R-01 — the fence absorbed the next member's doc comment
Severity
MAJOR
Basis
FACT — demonstrated, not argued
Claim
health_flags_field_coverage_test.dart slices each member from its own anchor to the next anchor, so every slice swallows the doc comment belonging to the following member. A field named once in that comment satisfied contains.
Evidence
A field added to every member except operator ==, with its name appearing once in the doc comment that follows operator ==, left the entire fence green. Re-running that attack against the fix turns operator == red.
Failure
Exactly N-01: a field present everywhere but in equality, which is what made HealthFlags(reported) == HealthFlags.empty true and discarded the user's health block on the next read.
Impact
The guard built to end that bug class would not have reported its return.
Fix
Comments stripped from each slice; matching on a word boundary rather than a substring — surgery was otherwise satisfied by a mention of surgeryDate.

Sixth instance of this class in this programme, and the first one I wrote myself — in the file whose own doc comment describes the class. A matcher that reads prose is evidence about prose, including when the prose is about matchers.
