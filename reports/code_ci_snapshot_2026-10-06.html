04 Dependency security — functions/

npm audit against the Cloud Functions package, re-run today. The dedicated CI "dependency audit" job fails on exactly this — npm audit's own exit code is non-zero whenever vulnerabilities exist, by design, so that job going red is working as intended, not a false alarm.

1 critical finding traces to transitive deps of @google-cloud/storage (vulnerable retry-request / teeny-request versions). Not yet triaged for actual exploitability in this codebase's usage pattern — that triage is the next concrete step, not a re-statement of npm audit's own severity label.
Scope note. 18 is the CI job's own number, and it is deliberately scoped to --omit=dev --package-lock-only — documented in functions.yml as an explicit choice (a vulnerability in jest never reaches a user; one in stripe or firebase-admin does). Running a plain, unscoped npm audit today (devDependencies included) returns 54 (14 moderate, 39 high, same 1 critical) — the extra 36 are tooling-only advisories the project's own policy treats as out of CI-gating scope, not a hidden production risk.
Mobile side unverified today. The equivalent Dart/Flutter OSV scan job is broken at the CI-config level (wrong working directory), so there is currently no live dependency-vulnerability signal for the Flutter side at all — this is itself a gap worth closing, separate from any vulnerability it might find.
