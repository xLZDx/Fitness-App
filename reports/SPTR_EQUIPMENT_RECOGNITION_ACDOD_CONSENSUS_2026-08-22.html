One line: the full AC/DoD document for all 34 v4.4 gates (Jira-style hierarchy: Epic = phase, Story = gate, Task = deliverable) went through three rounds of adversarial review with GPT-PM and reached a final verdict of CONSENSUS — APPROVE FOR IMPLEMENTATION, zero open BLOCKER/MAJOR/MINOR findings.

Two turning points along the way. First, I had built a lighter two-tier scheme (full AC/DoD only for the nearest phase, skeleton contracts for the rest) — the operator overrode that directly and required full AC/DoD everywhere, immediately, in Epic/Story/Task form. Second, once the full document existed, the adversarial review found real, concrete defects — not style nits, but things like a circular dependency between two gates and a rollback on an already-closed design invariant. All fixed and reconfirmed.

How the document got here

Draft 1

Two-tier scheme (GPT-PM's own recommendation)

Full AC/DoD for P0 and P1.G1 only; the remaining 27 gates got lightweight "Gate Contracts" (purpose, dependencies, required reviewers). The operator overrode this scope directly, requiring full Epic/Story/Task AC/DoD for every gate, immediately.

Draft 2

Full AC/DoD for all 34 gates, Epic → Story → Task

Every phase got an Epic-level AC/DoD, every gate a full Purpose/Inputs/Deliverables/Verification/Required review/Exit/Rollback story, every deliverable its own Task row with its own AC and DoD — assembled from verbatim v4.1 text plus v4.2/v4.3/v4.4 amendments, no fabricated values.

Case study: what a real finding looked like

AC-B03 — "we never built P4" is not the same claim as "no visual path exists"

The most instructive moment of the whole cycle. When P2.G5 legitimately chooses DEFER_VISUAL, phase P4 (visual search) is never built at all. My first fix said: since P4 doesn't exist, the text-lane's "visual contamination" test trivially passes. GPT-PM pointed out that the absence of new code doesn't prove the absence of ANY visual path — the app already ships a separate VisualMatch feature I hadn't considered.

Round 2 — rejected

"Under DEFER_VISUAL the test still exists, but its contamination scenario trivially passes — building P4.G2 is unnecessary."

Round 3 — accepted

CI-level proof: no visual retriever/verifier/feature (including VisualMatch) is reachable from the production text lane; the appearance of a new visual component without re-running this gate automatically routes the path to NOT_SUPPORTED, never EXACT_MODEL.

What happened to the review tooling along the way

Rounds 1–3 ran through pm-bridge, the Claude↔ChatGPT bridge with full browser automation. Per the operator's direct instruction (after a "stuck automation" incident that turned out to be the operator's own concurrent typing in the same ChatGPT window), GPT-PM's standard reply format changed mid-session: plain Markdown in the chat only, no HTML/canvas artifacts — Claude persists the exchanges to disk itself. Twice the "message sent" acceptance check false-negatived on a send that had actually gone through — each time verified directly against page content before any retry, to avoid duplicate sends.
