3. Real defects found by tests

  • firestore.rules: writing food_entries was impossible (expression limit), so the food diary would not have worked.
  • firestore.rules: withdrawing cloudConsent was refused although the design allows it.
  • nutrition_http: a bare .. path segment was collapsed into path navigation.
  • The blurred photo kept EXIF metadata on upload (fixed in 25546977).
  • Cancelling a local-only scan emitted a server delete without a server document.
  • Cyrillic serving units were not parsed, eggplant was tagged as an egg allergen, malt liquor was not tagged as alcohol.
  • Blind-written compile errors (C12, router closure): fixed.
  • Coverage-map vectors V-LOSE-M and V-LOSE-CAP were wrong; the implementation is correct.

4. Known limits and risks

  • The body-fat estimate is provisional: height, weight and age only, photos do not enter it; the ETA is hidden.
  • The cloud path is off: the face check on the blurred photo always refuses (UnavailableFaceCheck).
  • Cancelling a scan from the queue after an attempt emits no delete; an orphaned uploaded object is possible.
  • The accountExportPage quota log and the export failure log carry the uid, which differs from D-67.
  • /body-scan?scanId is ignored by the flow page; the meal thumbnail is stored but not displayed.
  • nutrition_plan imports body_scan in two non-pure files (pinned by a guard test).
  • Not run: live Vertex, OFF, USDA, TalkBack, a real device, Firestore implementations on the emulator.
