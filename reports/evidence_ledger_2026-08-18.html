The six

Each was a passing assertion attached to nothing. They are listed because a kill confirms what you already believed and a survivor tells you something you did not.

One

The fixture that scaled with the constant it bounded

A proximity window was widened from 120 to 100,000 and the suite stayed green: the test built its own gap as WINDOW * 3.

Two

The catch nothing could enter

A failure policy was mutated to swallow every quota refusal. Nothing went red — the catch sat around a live Firebase call, unreachable from any test. Fixed structurally, not by adding a test.

Three & Four

The guards that counted numerals

A provenance document must not reconcile a 29-class training log with a 37-label artefact. The guard was "29" in doc and "37" in doc — so rewriting the document to say the log was 37-class left it green, because both numerals appeared elsewhere. The repair was still too weak: flipping an inventory row also survived, because any(line says 37) was satisfied by a different line than the one falsified.

Checkout copy was extracted into a testable function, and restoring error.toString() as the card's line left everything green. Every test called the function directly; the widget had simply stopped calling it. An extracted seam that nothing requires anyone to use is not a guard.

Six

The fix with no test on the path it fixed

Re-wrapping the trial's exception — the regression fixed minutes earlier — left all 95 subscription tests green, because nothing goes through startFreeTrial at all.

Both worth recording, because a guard that cries wolf gets deleted. Checkout error semantics

The taxonomy came from what the backend exposes, not from a wish list

Old behaviour: a guest tapping Subscribe read [firebase_functions/failed-precondition] Add a Google account before subscribing… in a monospace panel with a stack trace — an English sentence written for a server log, prefixed with a vendor SDK's name, shipped to every locale, framed as a crash.

Two refusals share the gRPC status failed-precondition: you are a guest and you already subscribed. One is fixed by linking an account, the other in the billing portal. The only other thing on the wire was that English prose, and matching it would decide a product question with a substring that breaks when someone improves the wording. So the backend states the distinction as data, in the error's details payload. The messages are untouched: they are the diagnostic, not the copy. Five reasons, added only where the backend genuinely distinguishes something the user can act on differently.

Six localized lines in both locales. The diagnostic panel survives for genuinely unclassified failures and only there. Ten mutations killed.

The gate degraded its neighbour before the review caught it

The free trial shares this error card, and its service wrapped every exception into a string. Before the gate, that produced ugly untranslated text. After it, the wrapper made the trial strictly worse than it had been: an anonymous user was shown "Checkout could not be started. Please try again" — the wrong noun, and a false promise, since retrying fails identically while the thing that would actually help went unsaid.

Found independently by me and by the payments reviewer, within minutes of each other.
