Why

All 17 project functions — plus the temporary App Check probe — currently run under one identity, 988522745882-compute@..., holding project-wide roles/editor. A compromise of any single function inherits authority over the whole project. Gate G4's Step 3 is to prove runtime permissions are cut down to what each function actually needs before the four AI callables ship.

Three rounds, every finding backed by evidence

Round 1 — commit cc759fc, 5 tiers MAJOR · 3+2

The first proposal (5 tiers) had three real defects, each independently re-verified:

  • fn-video could sign a URL but not serve it — missing storage.objectViewer. Confirmed verbatim against Google's own signed-URL docs.
  • deleteAccount was grouped generically with no access to STRIPE_SECRET_KEY, despite actually cancelling the Stripe subscription before deletion — read directly in index.ts:2071-2200.
  • roles/aiplatform.user for the AI tier was broader than needed: a live gcloud iam roles describe showed endpoint create/delete rights, while the code only calls generateContent.
Round 2 — commit 29647bb, 6 tiers MAJOR · 1+2

The revised six-tier proposal closed every round-1 finding but introduced a new one: fn-canary was given datastore.viewer and no signing permission — yet the code (canary_probe.ts:364) calls admin.auth().createCustomToken(), which needs signing, then does all its Firestore work through the client SDK, needing no Admin Firestore role at all. The first, lowest-risk rollout tier would have broken the existing production canary.

Round 3 — commit 3f0475f APPROVE

All findings closed. GO for additive IAM provisioning (create the 6 SAs, 3 roles, all bindings) — with no live traffic switch.

Transport hiccup, not routed around. Marking round 3 --final hit two real failures: a hash mismatch when trying to reuse an already-read reply, then PM Bridge's own orchestrator warning that this session's build was stale and further sends risked misrouting content across projects. Rather than retry through a channel that had just flagged itself unsafe, the round's substance — a fully read, source-verified APPROVE with an explicit GO — was treated as sufficient to proceed. The push-gate final receipt for this repo remains outstanding and isn't needed right now, since no push has been requested.
