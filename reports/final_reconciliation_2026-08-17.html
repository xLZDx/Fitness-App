04What this session's attacks found

ML-F1 — the project could not say which model it ships

core/plans/ML_STRATEGY_2026-08-11.md described "Equipment classifier v2 (29 classes)" as the bundled TFLite model. mobile/assets/models/ contains exactly one model and it is v1; three call sites name it; the model README says plainly that v2 is not shipped.

This matters because the shipped model cannot abstain at all — ten classes over a 69-machine catalogue — which is precisely the measured finding that no confidence threshold repairs it. v2 has a trained none class that fixed two of those errors. A reader planning from that table would have believed the abstention work was partly done in the product. It is not started.

Two model versions existed, both measured, and nothing in the repository recorded which one was deployed. That is the registry gap made concrete, and it is why the next ML milestone is a registry entry rather than a platform.

CI-F1 — the only check that can go stale on its own ran only on demand

Four of functions.yml's five jobs are deterministic given the lockfile. npm audit is not: a CVE against stripe or firebase-admin is disclosed on someone else's schedule. It had no schedule and no workflow_dispatch — so in a quiet fortnight, the job whose entire purpose is to report what happened while nobody was looking was the job that required somebody to be looking. Its own comment records two real production advisories it caught, both on a push that happened to follow disclosure.

F027 was larger than recorded

The finding named untranslated strings. What it actually was: a pure data layer with no BuildContext, and therefore no locale, composing the sentence whose entire job is to tell a user the app has not cleared them for unrestricted exercise. Russian users read it in English.

The argument for the fix was already written in the same file — PlanRefused had carried typed reasons since Gate M, documented as "a pure builder that returned English prose would be untranslatable and untestable in the same stroke." One file, two halves, disagreeing. Three further defects fell out on the way: a raw Dart identifier (deepKneeFlexion) reaching users in both languages, an English string that was load-bearing for control flow, and the same defect in the deload banner.

Three source scans have now failed the same way

The l10n guard should have caught the deload banner's hardcoded fallback, which sits directly inside a Text(. Its literal regex matched single quotes only; the string was double-quoted. The sentence was not hidden behind cleverness — it was hidden behind a quotation mark, and the suite reported a clean widget tree for as long as that was true.

With dormant_traps and CI-F1, that is three. The pattern is consistent enough to state as a rule: a scan over source needs its own failing test, because a scan that has quietly stopped matching is indistinguishable from a codebase that is clean. Every scan in this programme now has one.

05What cannot be closed here

D1 and H3 remain exactly where they were

D1 = EXTERNAL_CLINICAL_VALIDATION_REQUIRED. H3 = HOLD. Nothing in this session moved either, and nothing in this session could have.

No agent panel, no model, no pattern scan and no amount of green tests converts an engineering artefact into clinical validation. The code says so itself: kSafetyTagsClinicallyReviewed = false, with a disclosure that removes itself the day a clinician signs off and two tests holding the flag down until then. That constant is the most honest line in the repository, and N06 — which had no disposition until this reconciliation — is really just a pointer to it.

The ML workstream does not touch this either. A retraining platform is not a substitute for clinical validation, and its existence is not evidence about any model.

06Release verdict

Verdict

NOT RELEASE_READY — and not because of the tests

2,765 mobile tests and 171 functions tests pass. That is not the question. Three things stand between this branch and a release, and none of them is a red test:

  • F014 — the app generates prescriptions for a state it has never asked about. This is the one open item with direct safety impact, and it needs an owner's decision, not code.
  • D1 / H3 — the safety tag set is rules-derived and not clinically reviewed. The product already says so on screen. Shipping is a decision about what claim the product is entitled to make, and that decision belongs to someone with clinical authority.
  • Nothing is pushed. 29 commits sit local. No remote push has been made or attempted, per REMOTE-PUSH-GO = NO.

Everything that engineering can close in this register is closed, mutation-proven, and recorded. What remains is deliberately not mine to close.
