01Why the prior report was inaccurate

"Backlog exhausted" was true as a statement about a task list. It is not the same as "the product works" — but that is how it read. The mechanism repeats: almost every gate closed on code review, Windows-rendered golden tests, or a GPT-PM APPROVE — none of which can see a system crash dialog or tell a correct pixel from one baked into the golden reference as wrong. Every time someone actually looked at a live phone, a real defect turned up on the first try (Aug 31 — trainer crash, Sep 16 — wrong Home card text style).

🟡 Trainer (Form Coach) — crash dialog removed on S8 and S23; trainer overall unproven

History (baseline before 2026-09-18). On an S8 (Android 8, Mali GPU), the first trainer launch from clean state started a separate process, mlkit_acceleration_mini_benchmark, which died with Fatal signal 6 (SIGABRT) (NoSuchFieldError in mlkit_vision_mediapipe.zzib); Android showed "fitness_app has stopped". The main app process stayed alive — the defect was the system dialog. The same crash reproduced on an S23 with the old build.

Mitigation 2026-09-18. The MlKitRemoteWorkerService was removed from the manifest (tools:node="remove"). Verified on S8 and S23, clean guest + first camera grant: 2 minutes with no dialog, no SIGABRT/NoSuchFieldError, the benchmark process never starts, pose models load. Side effect: at pose start, PoseMiniBenchmarkWorker logs four terminal FAILUREs ("service not found") within about 1.3 s, with no further retries during the 2-minute observation; downstream functional impact is unverified. Gate G17 only verified demo-video visual fidelity — a different path from the one that crashed.

Unproven. Not verified: that pose landmarks are produced with a person in frame; that equipment recognition and OCR still work without the service; a release build; rep-count accuracy (never measured). Root cause: a native ML Kit/MediaPipe failure (com.google.mlkit:mediapipe-internal 17.0.0-beta10, bundled in the app, during pose acceleration); the exact responsible artifact and version are unresolved, and whether a dependency version change would help was not tested. The squat's demo video is separately, deliberately disabled (bad source footage).

🟡 Design — no current on-device confirmation

Design-system tokens (colors, blur formula, radii) match the core/design/reference/fitness_hud_v1/ reference literally, verified directly in code. But the one real on-device check (2026-09-16) immediately found a confirmed bug — Home's stat cards rendered with the wrong text style, and golden tests never caught it because the golden reference screenshot itself baked in the bug (all M1–M9 gates closed with no device verification at all).

Re-verifying the fix was interrupted: reinstalling the APK hit INSTALL_FAILED_INSUFFICIENT_STORAGE, then the device dropped off adb; the session didn't force a reconnect. No re-check has happened since — literally "no preview of the installed design" as of today. On top of that, 142 legacy GlassCard occurrences across 46 files still coexist with the new HUD system on the same screens.
