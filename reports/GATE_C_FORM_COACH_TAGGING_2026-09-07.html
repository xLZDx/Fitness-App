01The root: a joint is not a silhouette

The catalogue maps an exercise onto one of seven hand-drawn animations by matching words in its title. hinge's matchTitle contained hip thrust|glute bridge. That was not a typo — a hip thrust really is a hinge at the hip joint, and somebody put it there deliberately. But the tagger's own header defines the tag differently:

poseTargetId: "squat" means: this row's silhouette, seen from the side, is the squat pattern.

A hip thrust is performed supine; the hinge animation is a standing deadlift. The rule had substituted what the joint does for what the shape looks like. The same substitution produced five more families.

The shared excludeWhen list is byte-identical, and that was GPT-PM's BLOCKER against the plan's first revision. It is shared on purpose: "what makes a movement unjudgeable by one side-on camera is the same in each case". Putting plank in it would have stripped 73 legitimate pushup tags. Every exclusion here is pattern-local, through the notTitle mechanism squat already uses in the same file.

squat, overhead_press and calf_raise are untouched, which deliberately leaves ten borderline rows tagged: six jump and pulse squats and four push presses. Their silhouette IS the tagged pattern; what differs is tempo or an added leg dip. Removing them would have been a different argument than the one this gate made, so they stay and are named rather than quietly swept along. Verified after the write: all ten kept their tags.

Two deviations from the plan, both declared here rather than found later. First, the seal commit carries a third file the plan did not name: .gitattributes. This repository has core.autocrlf=true, and without pinning eol=lf a fresh Windows checkout would hand back CRLF — the seal's digest would fail to verify for anyone but me, which is to say it would stop being a seal. 06Three things the gate got wrong before it got them right

The first count was 69 and it was wrong. It came from regexes over exercise ids rather than from running the tagger's own classify() over titles: the situp family is 11 rows, not 8. The real classifier says 72. A claim broader than the check behind it — the recurring defect of this session, and the reason the seal is now computed rather than typed.

A heredoc silently destroyed the first comparator run. \\b collapsed to \b, Python read it as a backspace, \blunge and \bswing\b stopped matching anything, and the run reported 146 phantom transitions and five reversals. This hazard was already in memory, and I walked into it anyway. Every script in this gate is written with a file-writing tool, none with a heredoc.

"pushup reaches no user, so the false tag is harmless" was wrong in kind, not only in conclusion. GPT-PM refused it correctly: the tag asserts what the silhouette is, and stays valid for the day the pattern becomes coachable — support is a separate decision, which the module header states outright. I had weighed today's reachability against a contract that excludes it. The seven already-wrong Side Plank rows are cleaned here as a result, rather than preserved.

07What now prevents this recurring

The asset had drifted from the rules and nothing noticed. Seven rows carried tags the rules had long stopped producing — six on Weight bench, one on Bench (flat / adjustable), all rejected by excludeWhen.equipmentLabel. Nothing in the repository compared the asset against the rules.

test_the_shipped_catalog_matches_the_rules now asserts equality across all 1887 rows, nulls on both sides included. That test, not the 86 removals, is the durable fix. A test over a list of families would never have found those seven rows; only equality does.

The tagger gained --transitions (which rows changed, not how many) and --expect PATH (compare full triples against a sealed file, exit non-zero naming MISSING and SURPLUS separately). Neither writes; --write combined with either is refused. The comparator was shown failing before it was trusted: against a wrong file carrying the same 86 rows — so a count-based check would have passed it — and it named both classes.
