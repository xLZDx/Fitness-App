03What GPT‑PM's review found — against the code

Every finding was checked independently before being accepted: a direct search against Google Cloud's own documentation, a direct read of the SDK's own type definitions in node_modules, an exact test count via grep — none taken on the reply's word alone.

Blocker · fixed

The Vertex AI location did not support the chosen model

The gateway defaulted to europe-west1, but gemini-3-flash-preview is a global-endpoint-only model on Vertex AI, and separately deprecated (Google recommends migrating to gemini-3.5-flash).

Verified: via a direct web search against Google Cloud's own documentation before accepting — confirmed on both counts.

Fixed: the default location changed to "global" (still env-overridable). The model was deliberately kept as-is — swapping it is a separate behavior/cost/latency decision, not part of a pure transport migration; a loud TODO tracks it.

Major · fixed (partially, deliberately)

The equipment/exercise name was a real prompt-injection surface

The client-controlled subjectName field was interpolated into the prompt with only a length check. The module's own header claimed a closed "structured input only" boundary, which was not fully accurate for this one field.

Fixed: quotes and control characters rejected, an explicit instruction added telling the model to ignore commands inside the name, 3 adversarial tests added. Honestly documented as defense-in-depth, not a full close — a full close needs a server-side equipment catalogue (subjectId → canonical name) that does not exist in Functions yet; tracked as its own future gate.

Major · fixed

No explicit concurrency ceiling — an accidental 1,200 simultaneous paid calls

The AI_METERED profile left concurrency at the platform default (80). At a maxInstances ceiling of 15, that implied 1,200 simultaneous paid Gemini calls — the same ceiling used for cheap Firestore work, applied to something that now bills per call.

Fixed: explicit concurrency: 10 → a 150-call fleet-wide ceiling, pinned by a test.

Major · fixed

No cap on response length

The prompt's own "under 180 words" line is a request, not a guarantee. A subject name crafted to defeat the injection defense without a forbidden character could still trigger an arbitrarily long, arbitrarily billed response.

Verified: by directly inspecting node_modules/@google/genai/dist/genai.d.ts to confirm maxOutputTokens genuinely exists on the right config interface.

Fixed: the field is now REQUIRED on the gateway's options (cannot be forgotten), set to 512 tokens for the coach.

Minor · fixed

The gateway had no test coverage of its own

ai_gateway.ts was fully mocked out in the callable's own test suite — exactly why the location bug was invisible to any test.

Fixed: a new test file mocks the @google/genai SDK directly and pins model, location, safety, request shape, and error mapping.

04What the review found — against the decision-log record itself

After round 3 approved the code, an exact-commit re-read (--commit, not the working tree) found the DECISION_LOG.md entry had gone stale before the commit — and the first attempt to fix it introduced two errors of its own. Neither finding touched G1's code.

Minor · fixed

The decision-log entry contradicted its own commit

The text had been staged before round 3's response arrived and was never refreshed once it returned APPROVE — the commit claimed "round 3's response not yet available" while being that very response.

Fixed: in a separate, purely documentary commit (not an amend — this repo's rules reserve that call to the operator, not GPT‑PM).

Minor · fixed

The first correction itself got the chronology and the final field wrong

Round 5 (not confidently correlated to its own request, but independently verified before acting) caught: (1) the draft said the commit predated round 3's response — wrong, the commit was created AFTER; (2) the draft quoted the mechanical final: true transport field as approval, when GPT‑PM's own prose in that round explicitly said final approval was withheld.

Fixed: chronology checked directly against git log, the final-field wording rewritten to distinguish the mechanical transport field from the reviewer's actual stated judgment.

06What's still open — stated plainly, not hidden

  • A live smoke test against real Vertex AI with real ADC credentials has not been run from this sandboxed session — an explicit, named gap before deployment, not claimed as done.
  • The subjectName prompt-injection defense is defense-in-depth (character rejection + a model-level instruction), not a full close. A full close needs a server-side equipment catalogue that does not exist yet.
  • The model, gemini-3-flash-preview, is deprecated on Vertex AI. Kept deliberately for the duration of this transport migration; moving off it is its own, separately reviewed change.
  • Three of the four AI surfaces (equipment recognition, machine description, exercise generation) are not yet migrated — same pattern, in separate follow-up commits.
  • Rounds 5–6 of the decision-log review both came back flagged correlated: false — a known, documented limitation of PM Bridge's shared-browser transport. Both rounds' findings were independently verified and turned out correct; the thread was closed at round 6 without a round 7, on the same reasoning the master-plan thread in this same log used earlier.
