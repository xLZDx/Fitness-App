Six Story AC hard cases, each independently proven

  • Two machines in frame. Primary cluster's 9NPL is kept; neighbour cluster's EFX885 never reaches modelCodeCandidates. A second test (added in remediation) proves the neighbour's brand (Precor) and type (treadmill) don't leak in either.
  • Neighbour placard suppression, no primary code. The neighbour's code is still suppressed even when the primary has none of its own — the exact edge case GPT-PM's ruling called out by name. A second test (added in remediation) proves the neighbour's brand is suppressed too, not only its code.
  • Two model codes, same placard. Both kept, a conflict recorded; a control test proves an OCR digit/letter confusion pair (9NP1/9NPI) does NOT falsely conflict.
  • OCR noise. Garbled, non-lexicon, non-code-shaped text yields all-empty candidates with no crash; a control test proves noise around a real brand does not suppress the real match.
  • Brand-only text. brandCandidates populated, modelCodeCandidates empty, isEmpty false.
  • OP-01 — zero readable text. Empty and whitespace-only fullText both produce an all-empty ParsedIdentityText(); a direct comparison test proves the zero-text result and the brand-only result share an identical no-model subshape (now including productLineCandidates, per remediation), differing only in brandCandidates — GPT-PM's approved reconciliation, not a whole-object byte-identity claim.

Two cases beyond the six: near-tied ambiguous clusters (both codes preserved, conflict text names "ambiguous placard ownership" explicitly), and (added in remediation) a near-tied OCR-confusion-variant pair producing zero conflicts, plus a determinism control proving two lexicons built with reversed Set insertion order produce an identical result.

OP-01 failure-path gap — DEFERRED, stated plainly rather than claimed resolved

Round 1's finding was not "unproven," it was FALSE as originally claimed: no failureCode/UNAVAILABLE_* concept exists anywhere in this client today. Both the photo path (visual_equipment_providers.dart:200-203) and the live path catch an actual OCR exception with debugPrint + return null — IDENTICAL observable behaviour to "OCR found nothing." This gate proves only that a zero-readable-text result and a brand-only-with-no-model result share the same no-model subshape (the "ordinary successful empty result" half of OP-01). Distinguishing that from an actual OCR/plugin failure is a real, currently-unfilled gap, left for whichever future gate introduces that failure-classification runtime — not silently claimed as satisfied here.

What changed for existing behaviour

Nothing observable anywhere else. parsed_identity_text.dart and identity_text_parser.dart are a wholly new, self-contained module with zero call sites wired into it yet. machine_text_anchor.dart's existing generic denoising/matching was inspected for reuse and deliberately NOT reused — its normaliseText strips all digits and its phrase matching works on single lowercase-word fragments, both the wrong shape for brand-phrase and model-code preservation.
