03Round 1 — what GPT‑PM's review found

Every finding was independently verified before fixing: a Node.js repro for the prototype-chain bypass, a direct code re-read for the timeout gap, a git show diff against the parent for the check-order regression.

Major · fixed

languageCode in LANGUAGE_NAMES was bypassable via the prototype chain

The in operator against a plain object literal walks the ENTIRE prototype chain, not just own keys: "constructor", "toString", "__proto__" all satisfied the check and resolved to real (non-string) members of Object.prototype, which would then have been interpolated into the prompt as function Object() { [native code] }.

Fixed: direct string equality (=== "ru" / === "en") — equality has no prototype chain to walk. 5 regression tests, one per discovered bypass value.

Major · fixed

The timeout hierarchy was not structurally enforced

.timeout() wrapped only the network call, not the photo resize — so a slow resize plus a legitimate network round trip could together exceed the controller's outer budget even though the network leg's own sub-timer had not fired.

Fixed (round 1): resize and network combined into one composite future under a single .timeout(). Turned out incomplete — see round 2.

Minor · fixed

image_validation.ts's extraction wasn't fully behavior-preserving

A compound-invalid case ({mimeType:"image/gif"} with no image field) got a different error message after the extraction than before it.

Fixed: validateImageInput owns both raw type checks in the original order. The boundary was refined twice more — rounds 3–4.

Minor · fixed

Decision log staleness; miscounted adjacent test files

Minor factual inaccuracies in the log entry.

Fixed: text corrected.

04Round 2 — the zombie network call

Major · fixed

Future.timeout() does not cancel the source future

Round 1's composite future (resize+network under one .timeout()) could still let the network call start — spending real quota/provider cost — after describe() had already given up and returned null, because Dart's Future.timeout() does not cancel the source computation; it only stops waiting on it, and the computation keeps running in the background.

Fixed: resize is timed on its own first; the network call is simply never started if resize left no budget — instead of "start it, then abandon it."

Same round, 1 MINOR: JS/TS object-literal property evaluation order — properties evaluate in the order WRITTEN in source, not declaration order, so the expensive image check ran before the cheap language check. Fixed by switching to sequential const statements instead of an object literal with function calls as values.

05Rounds 3–4 — pinning the cheap/expensive boundary

Three rounds in a row, GPT‑PM checked the check-order against the EXACT order of the original commit 6e52bd6 — each round narrowed the boundary a little more precisely, until round 4 reproduced it exactly.

  • Round 3, MINOR: DateTime.now() is not monotonic (NTP sync, DST, a user changing the device clock) — replaced with Stopwatch.
  • Round 3, MINOR: round 2's "language first" fix overshot — it checked language before even the cheap image-field type checks. Split into checkImageFieldTypes / decodeAndValidateImageBytes.
  • Round 4, MINOR: round 3's boundary was still in the wrong place — the MIME allowlist check and the empty-base64 check belong AFTER language, not before. Re-split into checkImageFieldsAreStrings (only the two raw typeof checks) and decodeAndValidateImageBytes (everything else).

A regression self-caught before sending to round 4

The same finer split, applied naively, would have broken aiEquipmentRecognition.validateImageInput's own, coarser check ordering (type and allowlist checks combined into one condition per field). Caught by running the existing image_validation.test.ts suite before sending the round-4 fix for review — one test failed. Fixed structurally: the shared byte-level work was extracted into a private validateImageBytes core, with each callable given its own independently-correct sequence of checks on top of it.
