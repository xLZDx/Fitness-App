Every attempt logged the same line before degrading:

cloud recognition unavailable, falling back on-device: Firebase AI Logic has been deactivated in this project. To resume using Firebase AI Logic, you must enforce Firebase App Check.

Cloud recognition (Gemini via Firebase AI Logic) is dead project-wide — a console setting, not app code. On-device fallback is the only live path, and its ceiling this session was 30% confidence, always surfaced honestly as “ambiguous” or “unknown,” never fabricated as a confident match.

A separate, code-confirmed gap: the recognition-fallback catch block is a bare debugPrint — no Crashlytics record, no analytics event (gemini_equipment_service.dart:288). If this backend state regresses again post-launch, the team gets zero signal.

03 The discovery that stopped the gate

Spawned to answer one question — is any of this a proven MVP blocker — a nine-reviewer dream-team panel instead surfaced a problem with the evidence itself.

The safety module doesn't exist on this branch

The Clinical/Safety reviewer couldn't find the PAR-Q-style health-screening gate (“Has your doctor ever said you have a heart condition…”, “This needs medical attention, not a workout”) anywhere in mobile/lib — despite it being witnessed live on the tested device, in both languages, throughout this session.

Checked directly against git, not taken on either side's word:

  • mobile/lib/features/safety/ exists on origin/master. It is completely absent from marketing/site-prototype-2026-08-19's tree.
  • The feature's origin commits (9c16699, 8bf16d2, 917dc01 and others) are confirmed not ancestors of this branch's HEAD.
  • This branch's fork point from master (78b24dc) predates all of them — not a revert, a feature this branch was never in a position to receive.

Conclusion: the debug APK on the shared emulator was built from master (or a branch carrying its safety-module commits), not from this one. A second real device (Samsung SM-G950F) was also found attached mid-session — this test environment was shared, not exclusive.

What that does and doesn't invalidate

Stands: every direct source-code citation the reviewers made against this branch's actual working tree — app_router.dart, login_page.dart, auth_providers.dart, firestore.rules, gemini_equipment_service.dart. Those files were read from this session's real checkout, not from the running app.

Doesn't stand as evidence for this branch: every live behavioral claim above — the scan outcomes, the language-switch screenshots, the isolation proof, the injury-gate pass/fail behavior. Real observations of a real build doing real things, and the underlying defects are very likely still present on this branch too, since the touched code is common ancestry — but “very likely” isn't this project's own evidentiary bar for closing a release gate.

The most urgent open question this raises: it isn't yet known whether this branch ships any injury/safety gate at all. The plan doc's “Existing state” section asserts one is “genuinely enforced and fail closed” — that claim may itself be resting on the wrong branch's code.
