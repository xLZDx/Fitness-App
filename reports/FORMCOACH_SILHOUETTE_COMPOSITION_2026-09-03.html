Fitness_App / Form Coach — live defect found by the operator on-device after G16

The silhouette no longer crams itself into a corner

While G9–G16 closed out the golden-test infrastructure, the operator was live-testing the app on a Mi 9T Pro and an S23 and saw a bent, cropped squat figure — not what the original mockup described. The cause was found from live on-device screenshots, not from reading code: the target outline was drawn as if it already sat inside a real camera frame, when its authored coordinates only occupy the bottom-left corner of that space.

What the operator reported

"I already see huge discrepancies you didn't do — instead of what I asked, just a white silhouette on a black background" — followed by: "also in the trainer itself there's a white static silhouette that doesn't look like what I asked."

The second message arrived while a release build for an unrelated request was still building and distributing in the background — the investigation started immediately, without waiting for the build to finish.

Diagnosis — from live on-device screenshots, not from reading code

Connected to both of the operator's test phones over adb and pulled the live screen while the app was open. Both the Mi 9T Pro and the S23 — including versionCode 2976, pushed and distributed that same evening and already carrying today's G14 fix — showed the identical broken shape: a bent outline crammed into the panel's bottom-left corner with a large empty area above it.

Root cause: squatBottomTarget's raw coordinates (pose_target.dart:240-252, re-measured on a real person 2026-09-01) occupy only Y 0.58-0.93 and X 0.17-0.52 of the isotropic frame space — the bottom 35% of the height, pushed left. Correct for the anatomy it was measured from; nowhere near composed to sit well in a panel when drawn straight through projectLandmark — the transform that places a coordinate as if it already sat inside a real camera frame.

The demonstration panel on the exercise-selection screen does animate correctly (confirmed with two screenshots one second apart — the figure genuinely transitions from standing to squatting), but the "bottom" frame of that same animation produced the identical cropped shape — the same bug, not a second one.

First attempt — rejected by the app's own tests before it shipped

reverted Hide the outline entirely whenever there is no live body to align it to. Implemented, then tests run — demo_silhouette_test.dart failed 3 of its cases: that file pins a 2026-09-02 GPT-PM decision that the target must be visible from the very first frame, before a body is even tracked. Reverted before commit; nothing broken shipped.

The actual fix

The file already had an unused-since-2026-09-01 function, fitSilhouette ("one scale for both axes, centred, with a margin") — it fits a figure into a panel instead of projecting authored coordinates as if they were a real camera frame. Reintroduced, but only for the no-live-body case: the aligned, tracked-body path (alignment != null) is untouched, byte for byte.

For the demo loop: fixed bounds, computed once from the UNION of both endpoint poses (standing + squat bottom) rather than recomputed every animation frame — otherwise the scale would visibly "breathe" as the figure morphs between poses. For the live "cannot place" case: the figure's own bounds, already stable frame to frame since there is no second endpoint.

The joint coordinates of squatTopTarget/squatBottomTarget — what poseMatchScore and rep counting read — are untouched entirely. This is a rendering-only fix; the data that actually scores technique stayed exactly as measured.

Goldens — regenerated and eyeballed

form_coach_selection.png, form_coach_live.png, form_coach_faulted.png were regenerated inside ghcr.io/cirruslabs/flutter:3.27.1 — the same container G15/G16 validated against real CI. Before the fix, the figure was cropped into the panel's bottom-left corner with empty space above; after, it fills the panel, with the glowing skeleton visible on both the standing pose and the squat. Inspected by eye, not just diffed byte for byte.
