The mechanism, and what review did to it

Thirteen rows became seventeen. Six source-provable became eight. Almost none of the rest survived contact with four independent reviewers.

scripts/review/state_ledger.py holds the project's boundary items. For a row whose authority is SOURCE, the recorded state is not an input at all: a predicate recomputes it from the tree and the word is only ever the thing being compared. That single rule catches a stale OPEN and a false CLOSED without needing a mechanism for either. core/CURRENT_STATE.md is generated, and the suite regenerates and byte-compares it, so the human-readable table cannot be edited into a lie.

That was the design. Here is what four reviewers found wrong with it.

The closure check ran in one direction only. It was gated on the state already being terminal — so closure() was consulted only on rows that already claimed to be closed. Trace the consequence and it is this module's own founding defect, reproduced in the rows it guards most carefully: when the clinician finally returns the review, D1 goes on saying EXTERNAL_AUTHORITY_REQUIRED forever and nothing objects. D1 in fact executed zero assertions — no predicate, no invariant, and a closure check that could not fire. Closure now runs on every row that has one, and an authority that has spoken while the row still says work remains raises AUTHORITY_SPOKE.

Four more, each real

  • The state was an unvalidated free string. Terminality was membership of a two-element tuple, so RESOLVED, SETTLED or DONE read as finished to a human and as open to the check. N-07 was a live instance: it asserted a product decision had been taken, carried a closure callable, and that callable was never once invoked. The vocabulary is now closed and split three ways.
  • The generated page promised what it cannot deliver. It told readers an external row "cannot be closed from this repository at all". Both closure artefacts are ordinary files in this worktree. The page now says the goal is legibility of forgery in a diff, not prevention — because no artefact inside a tree engineering can write will ever prove that somebody outside it acted.
  • f2 proved the wrong thing. It matched the l10n key name and never opened the ARB, so renaming the key while its value stayed "The clip link is unavailable" would have reported the exact defect F2 names as fixed.
  • The human-label guard watched the wrong directory — the batches sent out, while human_eval.py --out defaults to where returned labels land. A guard aimed at the wrong surface is worse than an untested one: it reports zero forever.

Two authorities had also been merged: CT-1's labels are content review, and pointing both CT-1 and D1 at one clinical closure callable would have merged them inside the mechanism built to keep authorities apart. And CI ran every sibling Python suite by explicit path and not this one, which made the whole "it cannot drift" claim aspirational. It is now the first step in the job.

A sign-in that succeeded and cost the person everything

A reviewer was asked to falsify "no executable work remains", and was given no hint of the wanted answer.

signInWithGoogle returned a bare AuthUser. Linking an anonymous session keeps its uid, so every document written under it stays reachable. On credential-already-in-use the code fell back to signInWithCredential, which signs the person into their real account and leaves this device's profile, injuries, workout log and schedule under a uid that has no credential anyone can ever sign into again. Both paths returned a user with a name and an email, and the screen showed the same thing either way.

Nothing was deleted. It became unreachable, silently, at the moment the person did exactly what the app asked them to do. N05_DISPOSITION.md had recorded it precisely — "the copy in this branch names the exception; the flow still does not handle it" — and it stayed recorded, unfixed, through an entire guest-upgrade gate. The copy layer got the mitigation and the flow did not.

It now returns a SignInResult carrying GuestUpgrade: linked, orphaned, notAGuest. Deliberately not defaulted — a default lets an implementation return a value without deciding what happened, which is how the original read: not a wrong answer, an unasked question. The screen renders a persistent notice, not a SnackBar, because someone who has just lost sight of their training history should not have the only explanation vanish on a timer. The copy says the workouts stayed behind and are not shown here, and a test forbids "deleted", "erased", "lost" and "removed", because none is true and each is false in the direction that stops people looking.

Why the sweep missed it, twice. This residual, and two more found later, live in document prose — not in any status table. The reconciliation sweep that built the ledger read tables. That is a property of the method rather than an oversight, and it is worth stating because it bounds what the ledger currently covers: a mechanism built by reading tables inherits the coverage of the tables it read.

The three test defects are the interesting output, and all three were predicted by the review adversary before they were run:

  • Parametrising over the tuple under test. Removing NOT_A_DEFECT from the terminal states survived, because shrinking the tuple shrank the test set with it — the vacuity trap this programme keeps finding, this time inside the fix for it. The words are now written out, where deleting one fails.
  • A constant that agreed with the measurement. Replacing a predicate's body with a hard-coded string carrying today's true counts passed a test that compared numbers. The test now watches that the locator is actually called.
  • The class that actually ships was unproven. Restoring the original auth defect in FirebaseAuthRepository left all twelve new tests green, because every one ran through the mock.

A fact about what already shipped. attach_metadata.py does not fail for want of a stub — it installs one, and that stub returns the literal string "1.0.0" for the minimum metadata parser version. metadata.json records min_parser_version: 1.0.0. Recorded, deliberately not "fixed": widening the stub would invent a second parser version and stamp that into a shipped artefact too.

What was refused

Closing two metric claims by editing the registry

Proposed by
The falsification reviewer, with sound reasoning and a correct observation: MODEL_REGISTRY.json is a tracked file in this worktree, so "not this module's to rewrite" is a true statement about the locator's authority and a false one about the repository's.
Refused because
The six claims are recorded DORMANT by explicit instruction, and editing what the registry asserts so that a claim becomes locatable is chasing the number rather than closing a defect. MEASUREMENT TRUE and SOURCE CLAIM LOCATABLE stay separate.
Honestly stated
This is a refusal, not an absence. The work is available and was declined.

Also declined, with evidence rather than by omission: the claim that N05_DISPOSITION.md's F-prefetch row still reads as stale. It is past-tense and marked FIXED, and says the result type "now has two". And the hypothesis that the App Check attested share is a local script — noteAppCheck writes to Cloud Logging, so there is no local read path and cannot be one until deployed traffic exists.
