The shape

One defect family accounted for six of the nine findings, and it is worth naming precisely because it will recur: a guard that proves a symbol is declared, and never that anything uses it.

f_prefetch read the two files that declare ClipBatch and PrefetchState.partialQuota and asserted both exist. The one line that carries a quota refusal from the batch into the outcome lives in a third file the predicate never opened. Replace it with false and every quota refusal renders as partialFailed — a deliberate self-resolving refusal shown to the user as a fault, which is F-prefetch's literal defect — while the row goes on reading CLOSED. No Dart test covered the mapping either.

f2 is the same error with a sharper edge. It checked that the enum member exists, that the card maps it, and that the two strings a person reads differ — and never that any code path produces the reason. Delete one line in video_failure.dart and a quota refusal reads "The clip link is unavailable", which is exactly F2, while the row reports CLOSED and prints the correct refusal string as its own evidence.

no_gym_membership_model was the same shape one level up. It scanned mobile/lib — 321 Dart files, zero server files — while reportEquipment writes through the Admin SDK and bypasses firestore.rules entirely, making the server the only layer where a membership could bind. A complete joinGym callable plus a memberships/ collection left it reporting that no model exists. That is not a stale state; it is a stale question — the operator would have gone on being asked something whose premise had died.

And f025_tripwire_intact was "F025" in body over raw text, comments included. A suite reduced to // F025: tripwire deleted. plus an empty main() passed — and flutter test passes on an empty main, so nothing anywhere would have noticed. This is the guard-cannot-tell-code-from-commentary failure that was fixed for n07_still_dormant earlier in this programme and then written again verbatim.

Two defects that were not in a guard

Deciding N-04 turned up two things that had nothing to do with N-04's question.

gyms/unknown was a catch-all relay waiting for one console write

gymId defaults to the literal "unknown"; the only caller in lib/ passes none, so every report filed today carries the sentinel; and nothing excluded that value from the gyms/{gymId} lookup. A document created at gyms/unknown with a maintenanceWebhookUrl would have relayed every report from every user to that single endpoint. No deploy, no code change, no pull request — and an onboarding tool that seeds a placeholder gym under the obvious placeholder id does it by accident. The sentinel now has a name and the dispatch returns before the lookup.

The webhook pushed an identity the app promises to share only on request

app_en.arb:141 and app_ru.arb:124 both tell the user their identity reaches the gym "only if they ask to follow up". The payload interpolated Reporter: ${auth.uid} unconditionally — and unlike the Firestore copy, which deleteAccount rewrites to DELETED_UID, a uid already POSTed to somebody's Slack cannot be recalled. It now carries Report: <reportId>, which is the pull model the copy already describes. Making the code match the published promise was the conservative direction; changing the promise would be product's call, and is recorded as one.

A third, from the privacy lens: noteAppCheck wrote a uid to Cloud Logging — outside users/{uid}, therefore outside deleteAccount's reach — twelve lines below a comment explaining that quota is stored under the user document on purpose for exactly that reason. The share it measures needs fn and attested and nothing else.
