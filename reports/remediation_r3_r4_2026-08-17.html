The regression I introduced, and the reviewer who found the thread

R-03 added a safety gate to addExerciseToActiveProgramme so a terminal training mutation would not depend on caller discipline. A reviewer reported something smaller: my doc comment claimed the caller renders the stated refusal, and it does not — it interpolates the exception into a snackbar.

Following that to its cause found what the reviewer had not reached. The gate evaluated against safetyContextProvider, which carries equipment. The page that offers the button resolves the exercise without equipment, deliberately, with its own reason recorded: tapping a leg press you do not own is a statement about what you want to look at, and refusing it would turn a browse into a prescription.

So the two disagreed, and the disagreement was reachable in the most ordinary case there is — a home user taps a barbell exercise, the page shows it, and “add to programme” refuses, with ProgrammeNotViable([ProgrammeFinding(blockedBySafety)]) in the snackbar. Measured before fixing.

Where a measurement changed the finding

Reviewing the plan builder, I predicted that a non-finite recovery factor would propagate through clamp into .round() and crash plan generation. A throwaway Dart program said otherwise.

double.nan.clamp(0.5, 1.10)  ->  1.1        isNaN = false
(-3.0).clamp(0.5, 1.10)      ->  0.5
double.infinity.clamp(...)   ->  1.1

Dart does not propagate NaN through clamp; it returns the upper limit. There is no crash — and the real shape is worse and points the other way. An unusable factor came out of the clamp as the planner's maximum intensity, so “we could not work out a recovery factor” would have read as “train ten per cent harder than baseline”, in the one step of that file whose job is to fail closed.

Not reachable today, and said plainly: both call sites source the verdict from detectDeload, which returns 0.5 or 1.0 and nothing else. Fixed anyway, for the reason R-03 existed — “one producer, correct today” is a fact about today.

An assert on the type was written first and removed. It is stripped in release, so it would not close the case it exists for, and it would make the reader's guard impossible to construct a failing case for — a guard nothing has ever proven, which is the thing this programme keeps finding.

CT-1 — the batch, and what it does not close

The batch is blind, and everything else about it follows from that. A reviewer who can see which rule fired is producing an agreement rate, not a label — and an agreement rate trained on is exactly the feedback loop the label contract refuses at the training step. Refusing it there and then handing reviewers the machine's output would be refusing it in the one place it cannot happen.

holdout rows          386
flagged available      56    every flagged holdout row is in the batch
unflagged available   330 -> 124 selected
batch                 180    flagged_exhausted=true  backfilled=true  short=false
double review          44    ~20%, assigned by hashing the item id

A random draw would be ~86% unflagged and would say nothing about what the rules miss. An all-flagged draw could not discover a missed row even in principle. The manifest states in the file that any rate computed on this batch describes this batch.

Two defects surfaced while the tests were being written rather than during review. The sampler returned a silently short batch when one stratum was exhausted while the other had a surplus. The test corpus gave every row identical steps, so the unflagged stratum was empty and the fixture guaranteed its own outcome.

None of the five questions asks whether an exercise is safe. That is clinical authority, unreachable from this repository by construction, and a question that invites the answer is how a content label gets read as a clinical one. A test asserts no question name contains safe, risk, injur, contraindicat or clinic.

What no file format can establish is that a reviewer is a person. reviewer_kind records a claim; the blocklist catches the cheap mistake of putting a tool's name in the field. A determined mislabel would pass. The protection that holds is procedural.
