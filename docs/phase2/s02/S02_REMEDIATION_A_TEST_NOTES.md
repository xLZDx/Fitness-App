# S02 remediation batch A: test notes

Input for the test agents. One line per item: the behaviour a test must assert. Existing tests that pin the old behaviour are named so they can be updated.

- A1: `writeActivityAccountFence` on a new document writes `touchedAt` equal to `fenceAt`; on an existing document it keeps `fenceAt` and `lateSweepAt` and refreshes only `touchedAt` (every call). Late sweep, Auth user exists, no `accountDeletionRetries` doc, `touchedAt` (or `fenceAt` when absent) older than 24 h: fence document deleted, `clearedLive` = 1, no storage delete, no `users/{uid}` write. Same with `touchedAt` younger than 24 h: nothing deleted. Same with an `accountDeletionRetries` doc present: not deleted, `stuck` = 1, `oldestStuckAgeMs` > 24 h. A `touchedAt` refreshed between the job read and the transaction (retry race): compare-and-delete does nothing. Auth lookup failing: nothing deleted (fail closed). Update the existing skipped-live tests of epic 6b (`sweeps_jobs.test.ts`) for the new `clearedLive` field.
- A5: late sweep final recursive delete also removes `users/{uid}/usage/*`; `ACTIVITY_USER_COLLECTIONS` now has five entries (update any test pinning four).
- A10: `deleteActivity` with an unset bucket and an existing stream row (state `stored` or `pending`) fails `delete_failed`, keeps the row and the summary (the tombstone stays); with no stream row it succeeds as before. Late sweep with an unset bucket and a row under `activity_streams`: `lastErrorCode` `bucket_unset`, job not done, rows and fence kept, error-level log; with no rows the job completes as before.
- A2: reconciler continuation pass gets `deadlineMs`; with the deadline already passed no user is advanced, `budgetExhausted` is true and `run-complete` is still logged; a page budget never exceeds the remaining run time. Extra passes called with two arguments still work.
- A3: with more than 20 pending jobs, users are advanced in order of oldest `streamDeleteAttemptAt` (missing first); a permanently failing job is stamped (`streamDeleteAttempts` +1, `streamDeleteAttemptAt` set) and the next run advances a different job first; fenced users are stamped too; a job start sets `streamDeleteStartedAt` and clears attempt fields; `done` clears all three; `oldestBulkDeleteAgeMs` equals now minus the oldest `streamDeleteStartedAt`.
- A4: `reconcilePendingRow` abort path returns `kept` and deletes nothing when the row's current upload id or `intendedStoredSha256` changed after the first read (simulate by mutating the row between the read and the abort); unchanged row still aborts as before.
- A14: a row with a non-activity id under `activity_streams` is deleted directly by the bulk delete, no object path is built, the job reaches `done`, and the warn log carries `unrecognised`.
- A15: `previous-object-delete-failed` (silentSkips +1, repair still returned `repaired`); stored row with missing or outside-prefix `objectPath` increments `silentSkips`; object with unparseable `timeCreated` increments `silentSkips`; `streamsCycleStartedAt` / `quarantineCycleStartedAt` set while the cursor walks on, kept across runs, deleted when the cycle ends, and `oldestScanCycleAgeMs` is reported.
