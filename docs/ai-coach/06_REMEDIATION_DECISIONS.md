## A. Decisions to apply (design level, reversible, inside the documentation program)

### A1. Safety (SF-1, SF-7, UX-3, UX-4, UX-5, AR-13 row safety_stop, AR-14)
1. `safety_stop` takes effect in memory and on screen first. A journal failure never undoes it; it only adds a "could not save" notice. Add `safety_stop` to every persistence-failure test.
2. After a safety stop: state PAUSED with a safety lock; voice alone can never clear it (UI rule wins; remove the "distinct confirmed phrase" option from the design); rest countdown is frozen and rest cues are suppressed; `finish_workout` and `abandon_workout` are user-only actions.
3. Recording a performed fact is never gated by the safety check: `record_set`, `correct_set`, `pause_workout`, `skip_rest`, `finish_workout` always succeed when the state allows them. One shared allowed-action table is the single source for design, banner copy and tests.
4. Scope of a symptom stop: a chest, dizziness, fainting or breathing code stops the whole workout; a joint or muscle pain code stops the current exercise and offers replace, skip or finish; free-text "something else" is classified on the device only against a closed list and defaults to pause when unclassified. Who signs the symptom list is OPEN (section C).
5. The emergency number is chosen per locale from a table the operator signs; no hard-coded number. A call action on the locked-screen notification is OPEN.

### A2. Single writer, ownership and time (AR-1..5, RL-4, RL-17, UX-11)
1. A live session has one owner: `ownerDeviceId` plus an `ownerEpoch` counter, both in the replica session document and in the rules fence (owner fields immutable except through a takeover that increments the epoch). A second device opens the session read-only; takeover is an explicit user action; the previous owner's unsynced journal is parked, never merged, never deleted, and shown as "kept on this phone".
2. One owner isolate holds the Runtime, the journal and the rest state. When the foreground service engine is active it is the owner and the UI engine is a thin client over a channel; otherwise the UI isolate is the owner. Never two Runtimes.
3. The Runtime owns `restEndsAt` (absolute time). `RestTimerController` is not changed in sprint 01; the live screen renders from the Runtime. An OS-scheduled notification at `restEndsAt` is the end-of-rest backstop when the process is killed (permission analysis is OPEN).
4. Time-driven transitions (rest elapsed, PREPARING end) are journaled internal commands with their own `seq`. Model and voice commands are fenced on session id, `ownerEpoch` and command id, not on the exact revision, so a rest expiry does not make a spoken set stale. `expected_revision` stays for manual optimistic edits and for the replica fence.
5. Refusals are returned to the caller and emitted as events but are not stored in the idempotency ledger, so a transient refusal can be retried. Only accepted commands are ledgered. A same-id, different-payload command returns the original result and emits `command_id_payload_mismatch`.
6. Closed command set additions: `correct_set(set_id, reps, weight_kg, effort)` (appends a correction record, never rewrites), `void_set(set_id)`, `add_rest_time(seconds)`. NEXT_EXERCISE is a derived view of ACTIVE_EXERCISE, not a persisted state. `safety_stop` and `finish_workout` are rejected from NOT_STARTED.
7. Tool-call ids from the model are `(voiceSessionId, utteranceId, toolCallIndex)`; `liveCoachTurn` is idempotent per utterance; a per-turn client deadline moves PROCESSING to LISTENING with a local "unavailable" message; state-changing tool calls are never auto-retried; a failed turn is not charged.
8. A manual tap mints its `command_id` when the entry sheet opens; the control is disabled until the acknowledgement; the duplicate-suspect check covers taps and voice.

### A3. Journal, projection and sync (SF-2, SF-3, SF-10, SF-12, SF-13, RL-5..7, RL-10, RL-13, RL-16, RL-18, RL-19, AR-8, AR-15, AR-18)
1. No time-based journal deletion. A journal is removed only after (a) the local projection exists, (b) the projection is server-confirmed through a metadata-observing path, (c) the streak step is confirmed, and (d) for an abandoned session after the user chose to delete or export. Unfinished journals are never auto-deleted.
2. The projector does not go through `LogSessionAction` or the 4 s `save()`. It writes through a new observed path and records a durable `projected` marker; the streak update is a tracked retried step keyed by `sessionId`.
3. The sync driver uses exponential backoff with jitter, a maximum attempts per record and a maximum backlog age; a permanently rejected record is quarantined with a visible "sync blocked" state and an event; copy never blames connectivity for a rejection.
4. The dispatch result is authoritative for the UI. Before showing "Not confirmed" the UI reconciles against the journal head; a late acknowledgement upgrades the card to Saved. The 4 s timeout is not a UI constant.
5. Journal files are AES-GCM encrypted with the existing activity cipher pattern, excluded from Android backup in both XML files and the shared constant, bounded in size and count, preflighted for free disk at start, and in a visible manual-only mode when storage fails. Replay time is bounded; an in-memory command-id set is kept per loaded session. The exact-set backup rules test is edited on purpose and the edit is declared.
6. Real-device kill-and-restart evidence is an exit criterion of AI-COACH-01 (claim limited to the test device); SQLite is the named fallback if the file journal fails it.
7. Replica `commands` and `sets` have a retention policy and a bounded `seq` range; the batch size is derived from a rules-emulator call-budget measurement, not fixed at 8.

### A4. Rules, flags, deletion (SE-5, SE-7, SE-9, SE-10, SE-15..17, AR-2, AR-6, AR-7, RL-3, RL-20)
1. The live collections copy the full activities pattern including the account-deletion fence and tombstone check; every `liveCoach*` callable calls the account fence check. A refused replay purges that journal's replica queue (the local file is kept, parked).
2. The replica carries only an allowlisted set of non-health action and result codes; `safety_stop`, `SAFETY_*` and screening codes never leave the device.
3. Feature flags gate only the start of new sessions. An unfinished session continues on an expired or unreachable flag cache. The global server kill switch stops new turns and still allows `liveCoachEndSession`. Per-feature emergency kill uses the Secret Manager switch, not a Firestore document.
4. New collections and the voice-session, reservation and consent records live under `users/{uid}/...`, are added to the data-lifecycle policy file and the account export list, and the local journal wipe is wrapped like `ActivityAwareLocalDataWipe`.
5. App Check options for every new callable are specified and pinned in the scaling test.

### A5. Voice, model output, cost (SF-5, SF-6, SE-6, SE-8, SE-12, RL-1, RL-2, RL-12, RL-15, RL-23, AR-10, UX-6)
1. The port exposes `captureStarted`, `captureStopped`, `captureLost` and a liveness watchdog; the mic indicator renders only from them, with an explicit "mic state unknown" display. A failing `stop()` never shows "off".
2. For turns with state-changing intents only device-generated text is spoken after the result; model reply text that claims completion is suppressed; a dropped or refused tool call is reported to the device.
3. Default MVP listening mode is tap-to-talk (or headset-only hands-free) until the gym trial; always-on is OPEN. NO_MATCH and low-confidence states and an acknowledgement cue are added.
4. Reconnect is bounded (backoff with jitter, cap, credential renewal, defined give-up state).
5. Cost: per-turn budget for Mode B (`QUOTAS.liveCoachTurn`, per-session turn cap, per-user in-flight limit, required `maxOutputTokens`, added to the gateway operation list); server-side reservation lease with `expiresAt` and refund, renewal heartbeats, idempotent start and end. Numeric caps are OPEN (OQ-05).
6. Mode A credential gate: locked to server-set prompt, tools and model; single use; revocable; budget re-checked on renewal.
7. Voice utterance ids: fallback id is a hash of final text plus audio window when the recogniser gives no stable id.
8. The tool-call production mechanism (JSON response schema or an extended gateway) is stated; ids are sent instead of titles; injection tests are reworded to what the gateway can do.

### A6. Privacy and consent (SE-1..4, SE-11, SE-13, SE-14, SE-18)
1. The utterance is declared a health-bearing channel in consent and in the privacy deliverable. A privacy policy update (voice, recogniser, model provider, retention) and the Play data-safety form are a hard prerequisite for any build that calls `liveCoach*`, as an AI-COACH-02 acceptance item (the wording itself stays an operator and legal decision).
2. `InjuryFilterReason` and `ScreeningCeilingReason` codes are removed from model-bound context; free-text symptoms are classified on the device only; provider retention and no-training criteria apply to Mode B too.
3. Coach memory values use a closed vocabulary enforced by rules. Consent is recorded per uid with version and timestamp (allowlisted, in export and delete); capture is refused without current-version consent; withdrawal applies locally first with a persistent flag and blocks capture until persisted. "Not now" gets a re-prompt cadence and a separate firm-decline action; age gating comes before the microphone screen.
4. Recogniser preference for on-device recognition is decided in the provider ADR; "no raw audio persisted" is tested for app storage only and the platform recogniser is disclosed.
5. `finish_workout` and `abandon` ask for a screen or headset-button confirmation when available.

### A7. UI wording and behaviour (UX-1, 2, 7..10, 12..17, SF-4, SF-17, SF-18)
Undo on the Saved card and a defined correction path after the 10 s window; confirm-first for implausible values; primary dock action opens the set-entry sheet; pocket claim is conditional on the actual capability; screen-reader policy (no duplicate announcements while the coach speaks, no focus jump, chip actions as custom actions, headset or tap-to-talk when a screen reader is active); Back shows a persistent microphone cue or a confirm sheet; T-7 extended with a screen reader; pain control pinned outside the scrolling bar; rest controls 56 dp; in-app reduce-animation row; neutral wording for a corrupt journal; abandoned-session copy says where data is; "Not confirmed" can later resolve to Saved.

## D. Round 2 decisions (verification review of commit 0965349a; findings in 07_REVIEW_ROUND2.md, 23 new MAJOR, 0 BLOCKER)

These decisions are binding for the second remediation batch. Open operator items stay in section C.

1. Safety stop restart and scope (R2-AR-1, R2-UX-3, R2-AR-6). `safety_stop` carries a scope: `whole` (chest, dizziness, fainting, breathing, unclassified free text) or `exercise` (joint or muscle pain). A new user-only on-screen command `restart_after_safety` clears the lock: from a `whole` stop it lands in PAUSED without lock and then the normal `resume_workout`, with rest state recomputed fresh; from an `exercise` stop it returns to the same workout with the current exercise offered for replace, skip or finish. Under an exercise stop `replace_exercise`, `skip exercise`, `record_set`, `correct_set`, `void_set` and `finish_workout` are allowed; rest is frozen. The action table gets an "exercise-level pain stop" column. A symptom reported on a non-owner device stops that device's view locally and shows "Stop the other phone" with a takeover-and-stop action; takeover lands PAUSED and needs an explicit on-screen restart. Safety codes are still never replicated.
2. Performed facts while PAUSED (R2-SF-1). `record_set`, `correct_set` and `void_set` from manual source are allowed in PAUSED including safety-locked. The test oracle is an independent hard-coded list of performed-fact commands, not the transition table.
3. Internal timer commands (R2-SF-2). `rest_elapsed` and `preparing_done` are applied in memory even if the append fails, with a visible notice and a persist retry; rows run every internal command under each fault mode.
4. Unpersisted safety stop (R2-SF-3). A tiny separate durable safety marker is written before the journal append. After any session that ran in manual-only or journal-failure mode, the resume prompt requires an explicit "I am well to continue" step. The residual risk (kill before the marker is written) is documented and needs operator acceptance (open item).
5. Takeover and parked journals (R2-UX-4, R2-AR-3, R2-SF-4, R2-SE-2, R2-SE-7). The owner listens to the session document and parks itself on an epoch change. A parked journal is never offered "finish", never projects to `workout_sessions/<sessionId>`, and is excluded from the journal count bound. The user can Review it: re-add its sets to the live session through `record_set` with new command ids after confirming each set, or export it. The takeover dialog warns with the other device's unsynced count when known and requires on-screen confirmation on the taking device; the displaced device gets a notice. "Lost confirmed sets = 0" is restated: a parked journal is not lost (it stays on the device and is shown), but it is also not in History until the user acts; the metric and the exit evidence say so. A fence refusal caused by account deletion wipes that uid's local journals (offering an export first); the local journal key is in secure storage per uid and is deleted by that wipe.
6. Owner fence (R2-SE-1). `ownerEpoch` is written in every replica set and command document and is part of the set id (`<session>:<epoch>:<seq>`); rules compare it to the session document's epoch if the measured call budget allows, otherwise the design states the fence as cooperative only. `ownerDeviceId` is documented as a client-asserted install id.
7. Sync quarantine (R2-SF-5). Quarantine only after the server was reached and denied permanently. The backlog age bound produces a "stale, will retry on reconnect" state with a manual retry and export. A replica-incomplete flag warns before takeover.
8. Build gate and flag (R2-SF-6). Recovery, the finish projector and "finish my last workout" live outside the `LIVE_COACH` build gate; a build with the define off still recovers and projects (test). `FLAG_OFF` applies only to `start_workout`.
9. Leases and cost (R2-SF-7, R2-SE-4, R2-SE-6). `liveCoachStartSession` takes a client `requestId` (idempotent); renewal goes through a named `liveCoachHeartbeat` callable with App Check, account fence and quota, or through `liveCoachTurn`; open reservations per user are capped. A turn is charged when the provider is invoked; a refund happens only when the server observed that the provider call never started; an invocation-rate cap counts failures too. In Mode A with direct credentials the reservation is consumed in full at issue and refunded only on provider-side evidence or via a relay.
10. Consent on the server (R2-SE-3). `liveCoachStartSession` and `liveCoachTurn` refuse unless the stored consent version is at least the server-set minimum; rules force the consent timestamp to `request.time`; a minimum `appVersion` is enforced.
11. Model-bound plan context (R2-SE-5). Plan rationale sent to the model is a projection in which `safety_status` is opaque or dropped; the AICR-107 serialization test covers plan tool results.
12. Late model replies (R2-AR-5). A reply arriving after its turn deadline or after PROCESSING has left is discarded.
13. Hands-free and locked screen (R2-UX-1, R2-UX-2). The pocket copy shows only for hands-free with a headset or always-on. Under tap-to-talk the locked-screen way to talk is a headset-button press or a Talk action on the foreground notification (open: needs the Android spike S-A1); "hands-free" is redefined in the requirements accordingly. With a screen reader active no announcement or focus-driven speech occurs while the microphone is open; announcements queue until capture closes; Listening is shown by haptic and visible cue.
14. Document corrections (R2-AR-2, R2-AR-4, R2-UX-5). AICR-045 gets `owner_epoch`; AICR-047 is limited to manual edits; AICR-051 says PAUSED with safety lock only (never ABANDONED); design section 23 is rewritten to say the requirements are amended; design line "rest timer is a Runtime/RestTimerController concern" is replaced by Runtime-owned rest (continues through voice-state changes, freezes in workout PAUSED with lock); UI section 9.4 wording; the pain control is pinned.
15. Remaining partials. Add a service-death section and `ForegroundServiceStartNotAllowedException` handling (RL-8); clamp remaining rest to the original duration and add a backward clock jump row (RL-21); copy for a lease-expired state distinct from the daily limit (SF-15); observability sink real delivery check and emulator tags for FT-1063, 1064, 1074 (SF-20, SF-21); a per-callable App Check options table (SE-15); bound the number of session documents and name the retention mechanism, a scheduled sweep function (SE-17); a test that a spoken health statement is never logged server-side (SE-2); offline-recogniser preference test (SE-14); tool-call production mechanism stated or marked OPEN with an owner (SE-8); journal key lifecycle (SE-4).

## E. GPT-PM gate round 1 decisions (findings F-01..F-14, M-01..M-06 in 08_GPTPM_GATE_ROUND1.md)

Binding for the third remediation batch. Numeric values marked PROPOSED are defaults for the operator to confirm, not decided limits.

1. Set id (F-01). The single authoritative format is `<session_id>:<owner_epoch>:<seq>`, defined once in design 5.1; FT-1021, E2E-01, FT-1174 and X-19 assert it; two epochs with equal `seq` give different ids.
2. Rest ownership tests (F-02). FT-1042 and ACS-023 AC-3 are rewritten: the Runtime's `restEndsAt` is authoritative; the existing `RestTimerController` is unchanged; a fake clock gives identical values in the Runtime, the HUD and the shell strip.
3. Trusted origin of finish and abandon (F-03). While a `whole` safety stop is active, `finish_workout` and `abandon_workout` are accepted only from a trusted on-screen user event on the unlocked device (command source `ui_confirmed`, a two-step tap). Voice (including spoken confirmation), model tool calls, notification actions, headset buttons and replica events can never finish or abandon. When the screen is locked the user must unlock the phone first. Outside a safety lock, voice finish/abandon stays allowed with the screen-or-headset-button confirmation of AICR-111. The same rule is written in design 4.1a/9.3, the UI action table, the backlog and the tests.
4. Deletion-fence state machine (F-04). States: `DETECTED` (fence refusal seen; replica queue purged at once), `EXPORT_OFFERED` (shown at the next foreground, at most 3 offers or 7 days from detection, PROPOSED), `EXPORT_DONE`, `WIPE_PENDING`, `WIPED`. Background or offline: nothing visible happens until the next foreground; the journals and the key stay in `DETECTED` until then. After the export is done, dismissed 3 times, failed 3 times or 7 days passed, the mandatory wipe runs (journals, key, safety marker) at the next app start regardless of UI availability. The wipe is idempotent. Tests: foreground, background, offline, restart, export dismissed, export failing; both key deletion and export disposition asserted.
5. Server-enforced epoch (F-05). Server-enforced epoch validation of replica session, set and command writes is a requirement for the AI-COACH-01 exit. If the measured rules call budget cannot support it, the fallback is to route replica writes through a callable that validates the epoch; a cooperative-only fence is NOT accepted without a recorded operator acceptance (new open question OQ-31). AICR-085 stays as written.
6. Fenced projection (F-06). The projector writes `workout_sessions/<sessionId>` in a Firestore transaction that reads the live session document and proceeds only if `ownerEpoch` equals the projecting device's epoch and the live status is not already projected by another epoch; rules enforce the same through `getAfter`. The projection stores a payload hash; a retry with the same hash is idempotent, a different payload is refused and parked. The durable `projected` marker is written only after the transaction is acknowledged; a lost acknowledgement is resolved by reading the document and comparing the hash. Test: takeover forced between validation and write.
7. Local emergency input (F-07). Step 0 (apply `safety_stop` first) applies only to the trusted local emergency input of the Runtime in the running process (on-screen Stop and Pain controls, the on-device symptom classifier, headset stop). Envelope-carrying `safety_stop` from any other source (model tool call, replica, other device) goes through session-id and owner validation but is exempt from revision, safety-check and flag refusals. Separate tests: malformed session id, stale epoch, non-owner caller, valid local input.
8. Safety marker precedence (F-08). Recovery reads the safety marker before anything else and enforces the lock before exposing any recovered state or emitting any cue; replay then proceeds with rest cues suppressed while locked; unpersisted internal commands are discarded and recomputed from the replayed state; the marker carries `sessionId` and a monotonic `stopSeq` and is cleared only by a journaled `restart_after_safety`. Test: kill at every boundary between marker write, journal append, flush, rest expiry and first recovered frame; no forbidden cue, no unsafe state exposure, no automatic resume.
9. Volatile results (F-09). When the journal cannot be written, state-changing facts (`record_set`, `correct_set`, `void_set`) are held in a typed in-memory VOLATILE queue, shown as "Not saved yet" with a count, retried automatically, never given the Saved confirmation, never spoken as saved, and lost if the process dies (the user is warned on entering this mode). Other commands return `PERSIST_FAILED` as before. This replaces the earlier "rolled back" wording for the three fact commands and the "kept in memory" wording of the UI; the three-way distinction durable / volatile / lost is asserted.
10. Quarantine (F-10, M-01). ACS-076 AC-1 and the UI Sync blocked row follow AICR-122: only a demonstrated permanent server refusal quarantines; backlog age gives the stale-sync state and keeps retrying.
11. Cost (F-11). ACS-082 AC-2 and every remaining superseded cost assertion follow AICR-125: a call invoked at the provider is charged even if the client abandons it; a request that provably never reached the provider may be refunded; independent rows for both.
12. Admission limit (F-12). Creation of a live session is admitted by a per-user counter document updated in the same batch as the session document and checked in rules (`getAfter`); the limit on unfinished plus parked sessions is 5 (PROPOSED); a rejected creation has a typed result and writes no partial documents; the scheduled sweep is a retention mechanism only. Test: concurrent creation above the limit never exceeds it.
13. Canonical matrix (F-13). Design gets section 4.1b: one transition and event matrix (state, command or internal event, resulting state, journal records and `seq`, revision effect, acknowledgement boundary). Every FT/E2E row that mentions state, set id, journal sequence or timer ownership cites matrix rows instead of delegating to a future table; FT-1019 tests the separately journaled `preparing_done`; E2E-01 fixes the command sequence now.
14. Consent state machine (F-14). States `LOCAL_ACCEPTED`, `SERVER_PENDING`, `SERVER_CONFIRMED`, `STALE_VERSION`, `WITHDRAWN`. Allowed: capture with a provably on-device recogniser needs `LOCAL_ACCEPTED` or better; any capture where the recogniser is not provably on-device, and every model turn, needs `SERVER_CONFIRMED` at the current minimum version. Offline local consent never authorises remote processing. Both the microphone adapter and the callables enforce this; tests for stale, pending, failed and withdrawn.
15. Minor items. M-02: the foreground notification has no "Resume listening" action (J9 corrected to match E2E-05). M-03: Firebase AI Logic is marked historical draft input in C-02 and D7. M-04: 04a header and inputs say revision 3. M-05: ACS-070 AC-3 references the amended performed-facts list including `void_set`. M-06: History keeps only the replacement exercise; the original is shown in the session summary and kept in the journal; the UI claim is narrowed accordingly.
16. New open question OQ-31: operator acceptance if the cooperative-only fence is ever proposed (decision 5). Also confirm the PROPOSED numbers: 3 export offers / 7 days, limit of 5 unfinished sessions.
