## What the package decides, in one paragraph

The intended product is voice control of the app's existing workout operations: one workout flow and one source of truth, with touch and voice as input methods. Any voice adapter must call the same application actions and respect their existing validation, safety and persistence results. The earlier standalone-runtime, separate-session-store and journal design is a superseded proposal, not the accepted architecture. Health answers stay on the phone. Voice capture and speech output still require product/privacy decisions and device evidence; none is implemented for workout control.

## What the package does not claim

The requested voice-to-workout control has not been built, run or measured. The existing one-shot `aiCoachAdvice` UI is not that feature. Realtime provider availability and price, Android 13 to 16 foreground-service behaviour, recogniser behaviour over a long session, persistence behavior for the required set model, and gym-noise performance are UNKNOWN until the relevant code trace and later authorized device work. Reviewer claims were applied as decisions; the editing agents re-opened only the code lines they cite themselves.
